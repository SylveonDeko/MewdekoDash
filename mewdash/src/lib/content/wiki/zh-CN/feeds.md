## 功能简介

你提供一个订阅源链接和一个频道，之后机器人会定期检查该订阅源，并发布自上次检查以来发布的所有内容。每当网站发布新内容时，成员都会在频道中看到一条新消息，包含内容标题、链接，以及订阅源提供的描述和图片（如有）。

工作人员可以为每个服务器最多订阅十个订阅源，并为每个订阅源设置自定义消息。该消息会经过嵌入解析器处理，因此订阅更新可以是纯文本、嵌入消息，或带按钮的嵌入消息，并且可以使用占位符来引用内容的标题、链接、作者等信息。

成员无需进行任何操作，只需阅读频道即可。

## 适用场景

- 将社区的博客、更新日志或版本说明自动发布到公告频道。
- 将新闻网站或 subreddit 的订阅源同步到讨论频道。
- 通过 RSS 订阅源关注 YouTube 频道或播客。
- 无需有人手动复制链接，即可持续显示状态或发布信息。

## 更新的发布方式

机器人会遍历所有已订阅的订阅源链接，逐一获取内容，并在开始下一轮之前等待约十秒。机器人启动后的第一次获取只会记录最新内容的日期，不会发布任何内容。之后，所有发布日期晚于上次记录的内容都会按从旧到新的顺序发布，记录的日期随之更新。对于 Atom 订阅源，如果内容没有发布日期，则使用其更新日期。两者都没有的内容会被忽略。

每轮发布的内容数量没有限制，因此如果订阅源一次性推送二十条带有过去日期的内容，就会产生二十条消息。

获取失败的订阅源会被静默跳过，直到下一轮。它们不会被移除，机器人也不会报告失败。

### 默认消息

如果订阅源没有自定义消息，机器人会发送一条嵌入消息，包含以下内容：

| 部分 | 内容 |
| --- | --- |
| 标题 | 内容的标题，截取至 256 个字符 |
| 描述 | 内容的描述，已去除 HTML，截取至 2048 个字符 |
| URL | 内容的链接，因此标题可以点击 |
| 图片 | 订阅源中的图片附件，或 Atom 的 `preview` 或 `thumbnail` 元素（如有） |
| 页脚 | 订阅源的链接 |

### 自定义消息和占位符

使用 `feedmessage` 或仪表板上的 **编辑消息** 按钮设置自定义消息。该文本会经过嵌入解析器处理，因此 [嵌入构建器](/wiki/embedbuilder) 支持的所有内容都可以使用：纯文本、嵌入 JSON，或两者的组合。纯文本部分中的身份组和用户提及会触发提醒。

自定义消息中会替换以下占位符，此外还会替换占位符页面中列出的通用服务器、频道和机器人占位符。

| 占位符 | 内容 |
| --- | --- |
| `%title%` | 内容的标题 |
| `%author%` | 内容的作者，如果没有则显示“Unknown” |
| `%content%` | 去除 HTML 后的内容描述 |
| `%url%` | 内容的链接 |
| `%feedurl%` | 订阅源自身的链接 |
| `%image_url%` | 如果订阅源提供了内容图片则使用该图片，否则使用订阅源的图片 |
| `%categories%` | 内容的分类，以逗号分隔 |
| `%timestamp%` | 发布日期，以 Discord 时间戳显示 |

> [!EXAMPLE]
> `feedmessage 1 New post: **%title%** by %author%
> %url%`

将消息设置为 `-` 即可恢复为默认嵌入消息。

## 设置

订阅源没有服务器范围的设置。每个订阅都有一个频道和链接（在添加时选择），以及一个可选的消息。仪表板页面名为 **RSS 订阅源**，包含三个标签页。

| 标签页 | 显示内容 |
| --- | --- |
| RSS 订阅源 | 每个订阅的频道、链接和添加日期。**编辑消息** 或 **添加自定义消息** 会打开一个文本框；消息预览会显示在其下方。**删除** 会在确认后移除该订阅源。 |
| 添加订阅源 | **频道** 选择器和 **RSS 订阅源链接** 输入框，以及 **添加 RSS 订阅源** 按钮 |
| 统计 | **订阅源总数**、**不重复订阅源**、**频道**，以及 **按频道查看订阅源** 的明细 |

已有订阅源的频道和链接无法更改。需要更改时，请移除后重新添加。

## 设置步骤

1. 在仪表板中打开 **订阅源**，然后切换到 **添加订阅源**。
2. 选择更新应发送到的 **频道**。
3. 将订阅源地址粘贴到 **RSS 订阅源链接** 中，然后点击 **添加 RSS 订阅源**。该地址必须是指向 RSS 或 Atom 文档的完整 `http` 或 `https` 地址，而不是网站首页。
4. 返回 **RSS 订阅源** 标签页，如果你想使用自己的文字，请点击 **添加自定义消息**，然后点击 **保存**。
5. 在 Discord 中运行 `feedtest 1`，发布最新内容并检查结果。该数字是订阅源在 `feedlist` 中的位置。

## 命令

请使用服务器的前缀运行这些命令（默认为 `.`，除非你已更改）。所有订阅源命令都需要“管理消息”权限。

| 命令 | 别名 | 所需权限 | 用途 |
| --- | --- | --- | --- |
| `feedadd <url> [#channel]` | `rss` | 管理消息 | 让频道订阅某个订阅源。默认为当前频道。机器人会先获取订阅源，如果无法读取则拒绝添加。 |
| `feedlist` | `feeds` | 管理消息 | 列出订阅，编号显示，每页十条 |
| `feedremove <number>` | `feedrm`, `feeddel` | 管理消息 | 按列表中的编号移除订阅 |
| `feedmessage <number> <message>` | `rssmessage` | 管理消息 | 设置订阅的自定义消息 |
| `rsstest <number>` | `feedtest` | 管理消息 | 在当前频道发布订阅源的最新内容 |

## 提示和注意事项

- 每个服务器最多十个订阅源，同一个链接不能重复添加。无法读取的链接、重复链接和超出上限的情况，`feedadd` 都只报告一个综合错误，因此如果不确定是哪种原因，请检查 `feedlist`。
- 通过仪表板添加订阅源时不会先测试链接。之后请使用 `feedtest` 确认机器人能够读取该订阅源。
- `feedremove`、`feedmessage` 和 `feedtest` 中的编号来自 `feedlist`，它按添加时间排序。
- 机器人需要目标频道中的“发送消息”和“嵌入链接”权限。没有“嵌入链接”权限时，默认嵌入消息将无法显示。
- 只有带发布日期的内容（对于 Atom 则为更新日期）才会被发布。如果订阅源的条目没有日期，则永远不会产生更新。
- 机器人重启后的第一轮不会发布任何内容。它会从当时最新的内容开始，因此机器人离线期间发布的内容不会被补发。
- 由于自定义消息使用嵌入解析器，请遵守嵌入构建器的相同规则：有效的 JSON，或纯文本。
