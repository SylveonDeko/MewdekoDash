## 功能介绍

进程日志会直接读取 pm2 为机器人保存的日志文件，显示机器人写入控制台的内容，而无需登录服务器的 shell。该页面仅对机器人所有者可见：侧边栏对其他人隐藏此入口，非所有者直接打开该 URL 会被重定向回仪表板首页，而机器人本身也会拒绝请求，除非已登录的账号是所有者。

页面会向你所选的机器人实例请求其 pm2 进程表。该主机上 pm2 管理的每个进程都会被列出，而不仅仅是机器人，并显示其状态、PID、运行时长、重启次数、CPU 和内存占用，以及两个日志文件的大小。选择一个进程后，页面会加载其标准输出日志的最后几百行；在**跟随中**开启时，每隔两秒会继续追加新的日志行。

日志行会保留 Serilog 输出的颜色，每行都会标注其级别，方便你隐藏无关信息。堆栈跟踪等续行会附着在其上一行之后，因此隐藏 info 级别的日志不会留下孤立的堆栈跟踪。

## 为什么要使用它

- 机器人重启或崩溃后，你想查看它停止前的最后一条输出，这些内容位于 stderr 一侧。
- 有成员反馈某条命令失败，你希望在他重试时实时观察日志。
- 你希望在最近数千行日志中搜索某个服务器 ID 或某条消息，而无需通过 SSH 登录。
- 你需要完整的日志文件用于提交错误报告，并希望将其下载下来。

## 控件

| 控件 | 作用 |
| --- | --- |
| 进程卡片 | 主机上每个 pm2 进程对应一张卡片。标有 **本机器人** 的卡片即为响应此请求的实例。点击卡片即可读取其日志。 |
| **stdout** / **stderr** | 在进程的输出日志（普通日志写入的位置）与错误日志（崩溃和运行时诊断信息写入的位置）之间切换。 |
| **100** 至 **2k** | 打开或重新加载日志时加载的行数。跟随模式下，页面最多保留 5,000 行，超出后会开始丢弃最旧的内容。 |
| 筛选框 | 隐藏所有文本中不包含所输入内容的行。不区分大小写。 |
| **跟随中** / **跟随** | 开启或关闭实时更新。开启时，页面每两秒轮询一次新行，并随之滚动，除非你已向上滚动。 |
| **换行** | 将长行折行显示，而不是横向滚动。 |
| **复制** | 将可见行（已去除颜色）复制到剪贴板。 |
| **重新加载** | 从文件中重新读取末尾内容。 |
| **下载** | 按照磁盘上的原样保存整个日志文件，包括颜色代码。旁边的大小为文件的当前大小。 |
| 级别标签 | **VRB**、**DBG**、**INF**、**WRN**、**ERR** 和 **FTL**，每个都带有已加载的标注行数。点击即可隐藏或显示该级别。 |

在跟随过程中向上滚动时，新行会被暂存，右下角的按钮会显示等待中的行数。点击它即可跳回底部，并继续随日志滚动。

> [!NOTE]
> 单次读取上限为 1 MB。如果你请求的行数超出此限制，页面会提示已跳过较早的行；下载文件即可查看全部内容。

## 机器人如何查找日志

机器人会在其所在主机上运行 `pm2 jlist`，并读取 pm2 为每个进程报告的日志文件路径。只有当同一用户已有 pm2 守护进程运行时，它才会执行此操作，因此不会意外启动一个守护进程。如果已安装 pm2 但无法查询，页面会回退到 pm2 日志目录中的文件，并予以说明。如果完全没有 pm2，页面会说明原因，而不是显示空列表。

在连接了多个机器人实例的仪表板上，进程列表属于当前选中的实例，因为每个实例只能看到自己所在主机的进程。

## 设置步骤

1. 在机器人所在的服务器上，使用 pm2 运行机器人，例如 `pm2 start dotnet --name mewdeko -- Mewdeko.dll`。
2. 使用机器人所有者账号登录仪表板，并从侧边栏打开**进程日志**。
3. 选择标有**本机器人**的进程，或主机上的其他任意进程。
4. 保持**跟随中**开启以实时观察日志，或将其关闭，并使用筛选框和级别标签查看已加载的内容。
5. 崩溃后切换到 **stderr**，查看运行时在退出前输出的内容。

## 注意事项与提示

- 日志是从文件中读取的，因此在 pm2 之外启动的进程在此没有日志。只有当机器人本身在 pm2 下运行时，其控制台输出才会出现在这里。
- 运行 `pm2 flush` 或使用 `pm2-logrotate` 时，pm2 会轮转或截断文件。页面会检测到文件变小，并自动重新加载末尾内容。
- 筛选和级别标签只作用于已加载的行。如需向前搜索更多内容，请加载更多行或下载文件。
- 本页面上的操作都不会改变机器人。无法在此重启进程或清除日志；请使用所有者命令 `restartinstance`，或在服务器上运行 `pm2 flush`。
