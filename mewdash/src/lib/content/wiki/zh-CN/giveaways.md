## 功能介绍

管理人员需要指定奖品、频道、获奖人数和持续时间来发起抽奖。机器人会在该频道发布一条嵌入消息，显示奖品、主办人、结束时间以及所有要求。成员可以根据抽奖的发起方式，通过使用服务器的抽奖表情进行反应、点击 **Enter** 按钮，或在仪表板中完成验证码来参与。

计时结束后，机器人会从所有参与者中随机抽取符合要求的人作为获奖者。它会编辑原始消息以显示获奖者，在频道中发布祝贺消息，并且在启用时私信每位获奖者，附上抽奖消息的链接。管理人员可以提前结束抽奖，也可以在抽奖结束后重新抽取。

要求在结束时检查，而非参与时。如果某人点击了反应，但之后失去了所需身份组，那么在抽取获奖者时将被跳过。

## 使用场景

- 无需手动挑选名字，即可将游戏激活码、Nitro 或周边赠送给活跃成员。
- 通过设置最低消息数量，奖励真正在交流的人。
- 通过要求特定身份组，将奖品限定给服务器助推者或支持者。
- 使用验证码参与，阻止小号和机器人刷参与人数。

## 参与方式

每个抽奖只能使用以下其中一种方式。交互式的 `gstart` 向导会询问选择哪一种，斜杠命令提供 `use_button` 和 `use_captcha` 选项，仪表板则提供 **参与方式** 选项。

| 方式 | 成员如何参与 | 说明 |
| --- | --- | --- |
| 反应 | 使用服务器的抽奖表情进行反应 | 默认方式。抽奖结束时，机器人会读取反应列表，最多 1000 名用户。 |
| 按钮 | 点击嵌入消息下方的 **Enter** 按钮 | 参与记录由机器人保存。重复参与、抽奖结束后参与，或不在服务器中参与，都会被拒绝。 |
| 验证码 | 点击 **Enter (Web Captcha)**，登录仪表板，并通过 Cloudflare Turnstile 检查 | 与按钮参与的存储方式相同。参与记录归属于已登录的 Discord 账号。 |

抽奖表情通过 `gemote` 按服务器设置。机器人会用该表情进行反应来验证它，因此其他服务器的自定义表情只有在机器人也加入该服务器时才有效。反应型抽奖还需要机器人拥有“添加反应”和“使用外部表情符号”权限，否则 `gstart` 会拒绝启动。

## 要求

| 要求 | 设置方式 | 抽取时的效果 |
| --- | --- | --- |
| 所需身份组 | 向导、斜杠命令 `required_roles`、仪表板的 **所需身份组** | 成员必须拥有所列的全部身份组 |
| 消息数量 | 向导、斜杠命令 `required_messages`、仪表板的 **所需消息数量** | 成员在本服务器中被计数的消息数必须不少于该数值。由于使用消息计数服务，因此只统计启用该服务之后发送的消息。 |

机器人始终会排除其他机器人，以及已离开服务器的人。抽奖嵌入消息中会以 **所需身份组** 一行和“需要 N 条消息”一行列出各项要求。

## 抽奖消息

嵌入消息的标题是奖品。描述内容为 "React with (emote) to enter!"，点名主办人，并以相对时间和绝对时间的 Discord 时间戳显示结束时间。页脚显示获奖人数、服务器名称和结束日期。若设置了提及身份组，则消息内容为该身份组的提及。

服务器范围的外观设置：

| 设置 | 命令 | 作用 |
| --- | --- | --- |
| 嵌入颜色 | `gembedcolor` | 抽奖嵌入消息的颜色，可使用颜色名称或 `#hex` |
| 横幅 | `gbanner` | 每个抽奖都会显示的图片。向导和斜杠命令可以针对单个抽奖，通过 URL 或附件覆盖该图片。 |
| 提及身份组 | 无，仅可在向导中覆盖 | 向导会询问是否提及某个身份组；如果服务器已保存提及身份组，则会询问是否覆盖它 |
| 私信获奖者 | `gdm` | 是否私信获奖者。默认开启。 |

### 结束时

如果有足够的符合条件的参与者，机器人会将嵌入消息编辑为 "Winner: @user"，并显示主办人，将页脚设置为 "Ended at (time)"，将内容改为 "**Giveaway Ended!**"，然后发布一条单独的祝贺消息，其中包含抽奖链接以及重新抽取的命令。如果无人参与，或符合条件的参与者人数少于获奖人数，嵌入消息会被替换为 "There were not enough participants!"，并将抽奖标记为已结束。如果有人参与但无人符合要求，则会改为说明这一情况。

只有一名获奖者的抽奖还会为聊天触发器触发 `GiveawayWon` 事件，因此触发器可以对中奖做出反应。

### 获奖者私信

开启 **私信获奖者** 后，每位获奖者都会收到一条私信。默认内容为一个说明其中奖的嵌入消息，并附带指向抽奖消息的链接。如果保存了自定义结束消息，则会改为发送该消息，并且除了通用的服务器、用户和频道占位符外，还可以使用以下占位符。

| 占位符 | 值 |
| --- | --- |
| `%messagelink%` | 抽奖消息的链接 |
| `%giveawayitem%` | 奖品 |
| `%giveawaywinners%` | 获奖人数 |

`gdmmessage` 不带文本时，会提供使用示例值预览已保存消息的选项；如果拒绝预览，则清除已保存的消息。带文本运行时同样会清除已保存的消息，而不会保存新内容。

## 设置

**抽奖** 仪表板页面有三个标签页：**进行中的抽奖**、**创建抽奖** 和 **已结束的抽奖**。上述服务器范围的设置（表情、颜色、横幅、私信开关）仅能通过命令修改。

**创建抽奖** 表单：

| 设置 | 默认值 | 控制内容 |
| --- | --- | --- |
| 抽奖奖品 | 空 | 奖品，显示为嵌入消息的标题 |
| 获奖人数 | 1 | 抽取的获奖人数；必须至少为 1 |
| 频道 | 无 | 嵌入消息的发布位置 |
| 持续时间 | 24 小时 | 抽奖的结束时间 |
| 所需身份组 | 无 | 成员必须拥有的身份组才能获奖 |
| 所需消息数量 | 0 | 最低计数消息数 |
| 反应表情 | 庆祝礼炮 | 反应参与所用的表情；可使用自定义表情或粘贴的表情代码 |
| 参与方式 | 反应 | 反应、按钮或验证码 |

**进行中的抽奖** 会列出每个抽奖及其结束时间。展开某一项可查看获奖者、频道、所需身份组、消息要求和参与方式，并带有一个 **结束抽奖** 按钮。重新抽取仅能通过命令进行。

## 设置示例

1. 运行 `gemote` 并指定成员用于反应的表情，例如 `gemote :tada:`。
2. 可选地设置 `gembedcolor` 和 `gbanner`，使抽奖与服务器的外观保持一致。
3. 在仪表板中打开 **抽奖**，然后点击 **创建抽奖**。
4. 填写 **抽奖奖品**、**获奖人数**、**频道** 和 **持续时间**。
5. 如果奖品应发给资深成员，请添加 **所需身份组** 或 **所需消息数量**。
6. 选择 **参与方式**，然后点击 **创建抽奖**。
7. 抽奖结束后，检查该频道。如果获奖人选错误或无人回应，请运行 `greroll <message id>`。

## 命令

请使用服务器的前缀执行以下命令（除非你修改过，默认为 `.`）。相同的命令也可以在 `/giveaways` 下作为斜杠命令使用。

| 命令 | 别名 | 所需权限 | 用途 |
| --- | --- | --- | --- |
| `gstart [#channel <time> <winners> <prize>]` | `giveawaystart` | 管理消息 | 发起抽奖。不带参数时会运行向导，还会询问主办人、消息数量要求、横幅、提及身份组、参与方式和所需身份组。时间格式如 `2d3h`。 |
| `gend <message id>` | `giveawayend` | 管理消息 | 立即结束抽奖并抽取获奖者 |
| `greroll <message id>` | `giveawayreroll`, `reroll` | 管理消息 | 从已结束抽奖的参与者中重新抽取 |
| `glist` | `giveaways`, `giveawaylist` | 管理消息 | 列出进行中的抽奖，包括消息 ID、奖品、获奖人数和链接 |
| `gstats` | `giveawaystats` | 无 | 统计进行中和已结束的抽奖总数、主办人以及各频道的数量 |
| `gemote <emote>` | `giveawayemote` | 管理消息 | 设置反应参与所用的表情 |
| `gembedcolor <colour>` | `giveawayembedcolor` | 管理消息 | 设置抽奖嵌入消息的颜色 |
| `gwinembedcolor <colour>` | `giveawaywinembedcolor` | 管理消息 | 设置与 `gembedcolor` 相同的颜色值 |
| `gbanner <url>` | `giveawaybanner` | 管理消息 | 设置默认横幅图片 |
| `gdm` | `giveawaydm` | 管理消息 | 切换是否私信获奖者 |
| `gdmmessage [text]` | `gdmmsg` | 管理消息 | 预览或清除自定义获奖私信 |

## 小贴士与注意事项

- `gend` 和 `greroll` 使用的消息 ID 是抽奖嵌入消息的 ID。可在开启开发者模式后复制，或从 `glist` 中查看。
- 重新抽取会按相同要求再次从参与者中抽取，因此上一位获奖者仍有可能再次中奖。
- 机器人重启后，会立即为未来 24 小时内结束的抽奖安排计时；更晚结束的抽奖则由每小时一次的检查接管，因此即使持续时间很长的抽奖也能准时结束。
- 如果机器人无法读取反应型抽奖的反应，它会回退为当前的服务器表情；但如果表情已被更改为无人使用的表情，则抽取时找不到任何参与者。
- 仪表板的 **进行中的抽奖** 列表也会显示已结束的抽奖，而 **已结束的抽奖** 标签页目前为空。可通过结束时间以及缺少 **结束抽奖** 按钮来区分两者。
- 验证码参与需要仪表板可以访问，并且成员需要使用 Discord 登录；参与记录与该账号绑定，而非与页面上输入的任何内容相关。
- 如果获奖者关闭了私信，获奖私信会静默失败。频道中的公告仍会正常发出。
