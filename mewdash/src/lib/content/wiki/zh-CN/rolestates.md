## 功能介绍

启用身份组状态后，机器人会监视成员离开服务器的情况。成员一离开，机器人就会记录其当时拥有的身份组列表。如果该成员之后重新加入，机器人会将所有已保存的身份组重新添加给他，因此他无需请员工重新验证或重新分配身份组。

对成员而言，离开时没有任何变化。重新加入时，他的身份组会直接恢复，通常在他读完欢迎频道之前就已经完成。

员工可以查看、编辑或删除每位成员已保存的身份组列表，也可以设置一份永远不会恢复的排除列表。此外还提供批量的“立即保存所有人”操作，因此在你开启此功能之前就已在服务器中的成员也能受到保护。

## 为什么要使用它

- 已验证的成员如果误退出，或为了清除通知而退出，重新加入后仍可保留访问权限。
- 通过身份组反应菜单选择的颜色、提醒和兴趣身份组，在重新加入后依然保留。
- 采用人工验证流程的服务器，无需重新检查已经通过审核的成员。
- 可以手动挑选永远不应恢复的身份组，例如临时禁言身份组或员工身份组。
- 迁移社区到新服务器时，可以转移身份组状态，并按名称匹配同名身份组。

## 身份组状态如何保存

成员离开时，机器人会检查：

1. 服务器已启用身份组状态。
2. **忽略机器人** 已关闭，或该成员不是机器人。
3. 该成员不在 **拒绝用户** 列表中。

如果以上条件均满足，机器人会获取该成员当前的身份组，移除 `@everyone` 身份组以及所有受管理的身份组（机器人身份组、助推者身份组、集成身份组），然后再移除 **拒绝身份组** 列表中的身份组。如果没有剩余身份组，则不保存任何内容。否则，新列表会替换该成员之前保存的内容。

封禁的处理方式不同。开启 **封禁时清除** 后，封禁成员会删除其已保存的状态，因此解封并重新加入时不会恢复任何身份组。

## 身份组状态如何恢复

成员加入时，机器人会再次检查功能是否已启用、是否忽略机器人（如果该成员是机器人），以及该用户是否在拒绝列表中。随后，它会通过一次请求添加所有已保存的身份组。如果某些身份组已不存在，或高于机器人的最高身份组，该请求就会失败，失败情况只会记录在日志中。

> [!PERMISSION]
> 机器人需要拥有管理身份组权限，并且其最高身份组必须高于它需要发还的每一个身份组。

### 跳过自动分配身份组

如果你同时在管理模块中使用了自动分配身份组，返回的成员通常会同时获得已保存的身份组和自动分配的身份组。开启 **跳过自动分配** 并使用 `togglerolestatesskipautoassign` 后，机器人会对拥有已保存身份组状态的成员跳过自动分配身份组，因此返回的成员只会获得他们之前拥有的身份组。此开关仅限命令设置，仪表板中没有。

## 手动管理已保存的状态

员工无需等待成员离开，即可直接创建或调整其身份组状态：

- `setuserrolestate` 会用你指定的身份组替换该成员已保存的列表。受管理的身份组和 `@everyone` 会被移除。
- `addrolestorolestate` 和 `removerolesfromrolestate` 用于修改已有的已保存列表。
- `deleteuserrolestate` 会彻底删除该成员的已保存状态。
- `saveallrolestates` 会一次性为所有当前成员创建快照，并应用与自动保存相同的机器人和拒绝过滤规则。

仪表板提供一项命令所没有的功能：**复制身份组状态**。它会获取某位成员已保存的身份组，并将其直接应用到另一位当前在服务器中的成员身上。

## 转移到其他服务器

`transferrolestates <serverId>` 会将当前服务器中的所有已保存状态复制到机器人所在的另一台服务器。身份组按名称匹配，不区分大小写，受管理的身份组会被跳过。如果目标服务器中没有与其已保存身份组同名的身份组，则该成员会被跳过。如果目标服务器尚未启用身份组状态，则会自动启用；若目标服务器没有自己的设置，则会继承源服务器的 **忽略机器人** 和 **封禁时清除** 值。

## 设置

身份组状态页面的 **设置** 标签页包含两个子标签：**通用** 和 **拒绝**。

| 设置 | 默认值 | 控制内容 |
| --- | --- | --- |
| 身份组状态 | 关闭 | 保存和恢复的总开关 |
| 封禁时清除 | 关闭 | 成员被封禁时删除其已保存状态 |
| 忽略机器人 | 关闭 | 不保存或恢复机器人账号的身份组 |
| 保存当前状态 | 按钮 | 立即为所有当前成员创建身份组快照 |
| 拒绝身份组 | 无 | 永不保存、因此也永不恢复的身份组 |
| 拒绝用户 | 无 | 其身份组永不保存或恢复的成员 |

**管理** 标签页包含 **管理用户身份组**（为成员的已保存状态添加或移除所选身份组）和 **复制身份组状态**。**身份组状态** 标签页会列出每一条已保存的状态，包括成员名称、ID 和身份组，并可查看详情或删除条目。

## 设置流程

1. 确保机器人的身份组高于你希望它恢复的所有身份组。
2. 打开仪表板中的 **身份组状态**，在 **设置** 下的 **通用** 中开启 **身份组状态**。
3. 除非你特别希望记住机器人身份组，否则请开启 **忽略机器人**。
4. 决定是否开启 **封禁时清除**。如果希望解封的成员重新获得身份组，请保持关闭。
5. 在 **拒绝** 中，将员工身份组、惩罚身份组以及所有临时身份组加入 **拒绝身份组**。
6. 在 **保存当前状态** 下点击 **全部保存**，让现有成员从今天起受到保护。
7. 检查 **身份组状态** 标签页，确认快照已成功填充。

## 命令

请在命令前加上服务器前缀（默认为 `.`，除非你已更改）。此模块中的每个命令都需要管理员权限。

| 命令 | 别名 | 需要权限 | 用途 |
| --- | --- | --- | --- |
| `togglerolestates` | `trs` | 管理员 | 开启或关闭身份组状态 |
| `viewrolestatessettings` | `vrss` | 管理员 | 显示当前设置和拒绝列表 |
| `viewuserrolestates` | `viewrolestates`、`vurs` | 管理员 | 翻页查看所有已保存状态 |
| `saveallrolestates` | `saveserverstates`、`backuprolestates` | 管理员 | 为所有当前成员创建快照 |
| `transferrolestates <serverId>` | `copyrolestates`、`moverolestates` | 管理员 | 将状态复制到另一台服务器，并按名称匹配身份组 |
| `togglerolestatesignorebots` | `trsib` | 管理员 | 切换是否忽略机器人账号 |
| `togglerolestatesclearonban` | `trscob` | 管理员 | 切换封禁时是否清除状态 |
| `togglerolestatesskipautoassign` | `trssaa`、`rsskipautoassign` | 管理员 | 切换是否为拥有已保存状态的成员跳过自动分配身份组 |
| `rolestatesadddenyrole @role...` | `rsadr` | 管理员 | 将身份组加入拒绝列表 |
| `rolestatesremovedenyrole @role...` | `rsrra` | 管理员 | 将身份组移出拒绝列表 |
| `rolestatesadddenyuser @user...` | `rsadu` | 管理员 | 将成员加入拒绝列表 |
| `rolestatesremovedenyuser @user...` | `rolestatesremoveadduser`、`rsrau` | 管理员 | 将成员移出拒绝列表 |
| `setuserrolestate @user @role...` | `surs` | 管理员 | 替换成员已保存的身份组 |
| `addrolestorolestate @user @role...` | `arsrs` | 管理员 | 为成员已保存的状态添加身份组 |
| `removerolesfromrolestate @user @role...` | `rrfrs` | 管理员 | 从成员已保存的状态中移除身份组 |
| `deleteuserrolestate @user` | `dur` | 管理员 | 删除成员已保存的状态 |

斜杠命令位于 `/rolestates` 下。

## 小贴士与注意事项

- 对于在你启用此功能时已在服务器中的成员，在他们离开或你执行 **全部保存** 之前，不会保存任何内容。设置完成后请立即运行一次。
- 只有离开才会触发保存。被踢出算作离开。封禁也算作离开，如果开启了 **封禁时清除**，状态随后会被再次删除。
- 恢复操作只使用一次添加身份组的请求。只要有一个身份组缺失或位置过高，整个恢复都会静默失败，因此在删除或调整身份组顺序时，请及时更新拒绝列表。
- 受管理的身份组（机器人集成身份组、助推者身份组）永远不会被保存，这些身份组由 Discord 自行分配。
- `viewuserrolestates` 每页显示三名成员。
- `setuserrolestate` 和 `deleteuserrolestate` 都可以用于已经离开的用户，因此你可以在某人重新加入前修正其状态。
- 拒绝用户仅影响自动保存和恢复。手动命令和 **复制身份组状态** 对这些成员仍然有效。
