## 功能简介

数据分析是机器人运行者查看历史数据的页面。它只对机器人拥有者可见：侧边栏对其他人隐藏，非拥有者直接打开网址时会被重定向回仪表板首页。这里没有需要服务器工作人员配置的内容。

[性能](/wiki/performance) 页面显示实时进程状态，重启后即清空；数据分析则读取机器人写入自身数据库的记录。每个正在运行的实例都会记录命令、网关事件、分片延迟、REST 调用、数据库耗时、进程指标、异常、功能使用、AI 与音乐活动，以及仪表板页面浏览量。数据在内存中按分钟汇总，每分钟刷新一次，并合并为 5 分钟和每小时的数据桶，之后按固定计划清理。因此你可以查看上周的情况，与前一周对比，并按实例、分片或服务器进行筛选。

可以将每周摘要发送到 Discord Webhook。对任何已存储指标设置的提醒规则，在越过阈值时也会通知 Webhook。

## 适用场景

- 你想知道错误激增是在部署之前还是之后开始的，而不仅仅是知道当前哪里出了问题。
- 某个服务器反映机器人变慢，你需要查看该服务器在指定日期范围内的命令延迟、活动和安全事件。
- 你想了解服务器实际配置并使用了哪些功能，以及这些情况在几个月里如何变化。
- 分片延迟、错误率或 REST 429 超过限制时，你希望收到 Discord 提醒，而不必一直盯着页面。
- 你希望每周一在某个频道收到增长、命令、错误和热门功能的汇总。

当最近一次刷新距今不超过 60 秒、最近一次汇总距今不超过 10 分钟且没有刷新错误时，数据管道状态为 `healthy`。否则显示 `flush stale` 或 `rollup stale`；刷新失败时显示 `error`；在机器人配置中关闭数据分析时显示 `disabled`。如果某个实例的最近服务器数已超过 3 分钟未更新，将以黄色标记；超过 10 分钟则以红色标记。

> [!NOTE]
> 所有时间均为 UTC。快照、普查记录和每日汇总每晚只写入一次，因此只有机器人在 UTC 00:05 之后至少运行过一次，**服务器** 和 **功能** 选项卡才会有数据。

### 筛选栏

页面顶部的筛选栏适用于所有选项卡，并保存在网址中。因此切换选项卡、刷新页面或分享链接时，都会保持相同的视图。

| 控件 | 作用 |
| --- | --- |
| 范围 | `15m`、`1h`、`6h`、`24h`、`7d`、`30d`，或最长 31 天的自定义 UTC 开始和结束时间 |
| 对比 | 在支持的图表和数据卡片上叠加前一个同等长度周期的数据 |
| 机器人 | 选择一个实例（来自数据管道已知的实例），或选择全部 |
| 分片 | 选择一个分片 ID，或选择全部 |
| 服务器 ID | 将原始数据表和服务器视图限制在某个服务器；按 Enter 应用 |
| 刷新 | 页面可见时，所有数据每 30 秒自动重新加载；点击按钮可立即刷新 |
| 复制链接 | 复制包含所有筛选条件的当前网址 |

点击数据卡片会打开钻取视图，显示该指标的细分数据。图表可以将较小的序列合并为 **其他**，切换累计总数，使用范围滑块缩放，也可以在图例条目上右键点击，单独显示某一序列。

## 设置

页面本身没有设置项。需要配置的只有提醒规则和三个机器人配置项。

### 提醒规则

每条规则监控一个指标。编辑器中的字段如下：

| 字段 | 含义 |
| --- | --- |
| 名称、描述、严重程度、启用 | 标签；`info`、`warning` 或 `critical`，用于设置 Webhook 的颜色和标题 |
| 指标、筛选条件、分组依据 | 任意已存储指标、可选的标签筛选条件，以及可选的分组标签（例如按 `shard` 分别评估每个值） |
| 聚合、窗口 | `sum`、`avg`、`min`、`max`、`last`、`rate`、`count`、`p50`、`p95` 或 `p99`，窗口范围为 1 分钟至 1 天 |
| 比较符、阈值、上限 | `gt`、`gte`、`lt`、`lte`、`outside`（低于阈值或高于上限）、`pct_change`（相对于前一个基线同窗口的百分比变化）、`deviates`（相对于最近 N 天平均值的 z 分数）、`nodata`（窗口内没有任何数据上报） |
| 基线、方向 | 用于 `pct_change` 和 `deviates`：昨天或上周；方向为 `up`、`down` 或 `both` |
| 持续时间 | 越界状态需要持续多久才会触发；`immediately` 会跳过待定状态 |
| 冷却时间 | 两次触发通知之间的最短间隔 |
| 重复通知 | 持续触发时重复通知，或只通知一次 |
| 最少样本数 | 窗口内样本数少于该值时跳过评估 |
| Webhook 链接、提及身份组 ID、子区 ID | Discord Webhook；可选的触发时提及的身份组；可选的发送目标子区 |
| 免打扰开始、免打扰结束 | UTC 时间段（可跨越午夜），在此期间不发送任何通知 |
| 恢复时通知 | 分组恢复正常时也发送通知 |

右侧的预览图表会用虚线区间标出绝对比较符的草稿阈值。

规则每分钟评估一次。每个分组的状态会依次从 `ok` 变为 `pending`（仅在设置了持续时间时）再到 `firing`，然后回到 `ok`；事件日志会将 `firing` 到 `ok` 的状态变化记录为 `resolved`。在表格中静音可让规则静音 1 小时；API 最长允许 30 天。被静音的规则和免打扰时段内的规则仍会更新状态，只是不发送通知。**发送测试** 会向该规则的 Webhook 发送一条测试消息。

### 机器人配置项

在 `bot.yml` 中设置，或使用拥有者的 `config` 命令。所有项目默认值分别为开启、30 和空。

| 配置项 | 含义 |
| --- | --- |
| `analyticsEnabled` | 设为 `false` 时收集器不做任何操作；数据管道选项卡显示 `disabled` |
| `analyticsRetentionDays` | 原始命令记录、页面浏览量和服务器安全事件日志的保留天数 |
| `analyticsDigestWebhook` | 每周摘要发送到的 Discord Webhook；留空则禁用摘要 |

### 数据保留时长

| 数据 | 保留时长 |
| --- | --- |
| 1 分钟数据桶 | 48 小时 |
| 5 分钟数据桶 | 14 天 |
| 1 小时数据桶 | 400 天 |
| 命令调用、页面浏览量、服务器安全事件 | `analyticsRetentionDays` |
| 错误样本、每服务器每小时的功能和事件活动 | 90 天 |
| 提醒事件 | 180 天 |
| 每日快照、普查数据、每日汇总 | 不清理 |

原始记录每 15 秒刷新一次，1 分钟数据桶每分钟刷新一次；1 分钟数据桶每 5 分钟合并为 5 分钟数据桶，5 分钟数据桶再合并为每小时数据桶；清理任务每 6 小时运行一次。

### 不会存储的内容

- 消息内容。命令记录包含命令名称、模块、种类、结果、耗时；命令失败时，还包含异常类别及其消息的前 200 个字符。
- 用户 ID。数据分析中的任何内容都不会按执行命令的人进行关联。
- 客户端 IP。页面浏览量保存的是 IP 和用户代理的访客哈希，并使用每日轮换的盐值，因此无法跨天追踪同一访客。发送到 `/api/`、`/cdn/`、静态资源以及数据分析页面本身的请求不会被记录。

选择退出统计的服务器和用户会被尊重：其命令仍会计入汇总，但原始记录中不包含服务器 ID 和服务器规模。

## 设置流程

1. 使用机器人拥有者账号登录仪表板，并从侧边栏打开 **数据分析**。只有拥有者可以看到该入口。
2. 先打开 **数据管道**。状态标签应显示为 `healthy`，每个实例都应有近期的心跳；如果刷新数据已过期，说明机器人没有在写入数据。
3. 在筛选栏中选择范围；如果你运行了多个实例，还可以选择机器人。勾选 **对比** 即可查看上一周期。
4. 前往 **提醒**，点击 **新建规则**，选择指标（例如 `shard.latency`），使用 `max` 聚合、5 分钟窗口，选择 `gt` 比较符并设置阈值，按 `shard` 分组，粘贴 Webhook 链接，保存后在该行点击 **发送测试**。
5. 在机器人配置中设置 `analyticsDigestWebhook`，然后点击 **立即发送摘要**，预览周一摘要的效果。
6. 过一晚后再回来查看 **服务器**、**功能** 和普查数据序列。

## 命令

数据分析页面仅在仪表板中提供；没有对应的机器人模块。拥有者的 `config` 命令可以修改上述三个配置项，另有少量拥有者命令可以在聊天中处理相关事务。请使用你服务器的前缀运行这些命令（如果你没有修改，默认为 `.`）。

| 命令 | 别名 | 所需权限 | 用途 |
| --- | --- | --- | --- |
| `config bot analyticsEnabled false` | `conf` | 机器人拥有者 | 停止记录数据分析；设为 `true` 可重新开始 |
| `config bot analyticsRetentionDays 14` | `conf` | 机器人拥有者 | 修改原始记录的保留天数 |
| `config bot analyticsDigestWebhook <url>` | `conf` | 机器人拥有者 | 设置周一摘要的发送地址 |
| `stats` | | 无需权限 | 机器人版本、每 5 秒执行的命令数、内存、缓存数量、分片和运行时长 |
| `commandstats` | `cstats` | 机器人拥有者 | 最常用的命令、模块、服务器和用户 |
| `shardstats` | | 机器人拥有者 | 每个分片的状态 |

## 技巧与注意事项

- 页面通过机器人检查拥有者身份，因此在一个机器人实例中是拥有者、而在另一个实例中不是拥有者的账号，在第二个实例中会被重定向。
- 摘要会在周一 UTC 09:00 或之后发送，内容为最近 7 天与之前 7 天的对比：服务器数、命令、错误、事件、新增和流失的服务器、页面浏览量、AI Token、音乐曲目，以及前 5 个热门命令、错误和功能。
- 较长范围的序列来自每小时数据桶，因此百分位数会被平滑；如需查看分钟级细节，请缩小范围，但分钟级数据仅保留最近 48 小时。
- 如果收集器的内存缓冲区在刷新前已满，该间隔内多出的原始命令记录会被丢弃，但汇总数据仍会继续统计；此时数据管道中 **待写入行数** 持续增长即为信号。
- 提醒规则需要 Discord Webhook 链接，其他内容在保存时会被拒绝。
- 预估 AI 费用只计算具有已知标价的模型，因此总额只是下限。
