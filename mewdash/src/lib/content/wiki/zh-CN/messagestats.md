## 功能介绍

开启消息计数后，每当真人成员发送一条达到最短长度要求的消息，机器人就会为该成员在该频道记录一次计数。机器人不会存储消息内容，只记录谁在何处、何时发送了消息。计数会先进入队列，再分批写入数据库，因此繁忙的服务器不会因此变慢。

成员可以使用 `usermessages` 查看自己的总数，使用 `channelmessages` 查看最活跃的频道，或使用 `servermessages` 查看整个服务器的情况。`topusers` 会显示前十名排行榜，并列出每位成员占全部消息的比例。`activitygraph` 会渲染一张柱状图，展示一周中最活跃的日期或一天中最活跃的时段。

仪表板会以图表展示同样的数据，员工还可以开启或关闭计数、重置计数，并将数据导出为 CSV 或 JSON 格式。

## 为什么要使用它

- 找出最活跃的成员，用于发放奖励、分配身份组或招募版主。
- 在重新规划服务器之前，了解哪些频道冷清，哪些频道活跃。
- 根据你自己时区的最活跃时段图表选择活动时间。
- 通过比较消息数量与消息质量，识别机器人和垃圾广告账号。

## 统计规则

| 规则 | 行为 |
| --- | --- |
| 启用计数 | 在运行 `togglemsgcount` 或开启仪表板开关之前，不会记录任何内容 |
| 机器人 | 永不计数 |
| 私信 | 永不计数；仅统计服务器频道 |
| 最短长度 | 字符数少于 **最短消息长度** 的消息会被跳过；默认值为 0，因此所有消息都会计数 |
| 时间戳 | 消息时间保留 90 天，用于生成时段和日期图表；总数则会永久保留 |

最短长度最多可设为 4098。直接运行 `minmsglength` 而不带数字，可查看当前值。

## 活跃度图表

`activitygraph days` 需要一周七天都有数据，并会查看过去四周的情况。`activitygraph hours` 需要过去七天内 24 小时都有数据。对于逐小时图表，机器人会先要求你选择时区，提供常见时区列表，也接受任何 IANA 时区名称；如果你不作答，则会取消操作。图表以 PNG 格式发送。

## 设置

消息统计页面有两个顶级标签页：**统计** 和 **管理**。**统计** 包含 **概览**、**最活跃用户** 和 **最活跃频道**。**管理** 包含 **设置** 和 **导出数据**。

| 设置 | 默认值 | 控制内容 |
| --- | --- | --- |
| 启用消息计数 | 关闭 | 是否记录新消息 |
| 最短消息长度 | 0 | 滑块范围为 0 至 4098；达到此长度的消息才会计数 |
| 重置消息计数 | | **重置所有服务器计数** 会在确认后删除该服务器所有已存储的计数 |
| 导出格式 | CSV | 已加载统计数据的 CSV 或 JSON 下载格式 |
| 包含用户统计 | 开启 | 在导出中添加最活跃用户数据行 |
| 包含频道统计 | 开启 | 在导出中添加最活跃频道数据行 |
| 包含每小时明细 | 关闭 | 在导出中添加最活跃时段和最活跃日期数据行 |

**概览** 标签页会显示 **每日消息**、**消息总数**、**最后更新** 和 **状态** 卡片，以及 **最不活跃用户** 和 **最不活跃频道**、**24 小时活跃度** 图表和 **每周趋势** 图表。**最活跃用户** 标签页会列出 **发送消息最多的用户**，**最活跃频道** 标签页则会列出 **最活跃频道**。

> [!NOTE]
> 导出文件由浏览器根据页面上已加载的统计数据生成。你输入的开始和结束日期会写入文件头部，但不会筛选数据行。

## 设置流程

1. 打开仪表板中的 **消息统计**，进入 **管理**，然后选择 **设置**。
2. 开启 **启用消息计数**。
3. 可选：将 **最短消息长度** 设为 5，或在 Discord 中运行 `minmsglength 5`，让只有一个字符的回复不计入统计。
4. 让服务器聊天一天，然后在 **统计** 中查看初步数据。
5. 一周后，运行 `activitygraph hours` 并选择你的时区，即可了解服务器在何时最为活跃。

## 命令

请在命令前加上服务器前缀（默认为 `.`，除非你已更改）。

| 命令 | 别名 | 需要权限 | 用途 |
| --- | --- | --- | --- |
| `usermessages [@user]` | `usermsg`、`umsg` | 无 | 你或其他成员的消息总数、最活跃频道和最不活跃频道 |
| `channelmessages [#channel]` | `channelmsg`、`cmsg` | 无 | 某频道的消息总数、最活跃成员和最不活跃成员 |
| `servermessages` | `servermsg`、`smsg`、`guildmessages`、`guildmsg` | 无 | 服务器消息总数，以及最活跃和最不活跃的成员与频道 |
| `topusers` | `topu` | 无 | 按消息数排名的前十名成员及其百分比 |
| `activitygraph [days or hours]` | `actgraph` | 无 | 最活跃日期或时段的柱状图；默认按日期 |
| `minmsglength [number]` | `mmlength`、`minmlength` | 管理服务器 | 查看或设置消息计入统计的最短长度 |
| `togglemsgcount` | `togglemessagecount` | 管理员 | 开启或关闭计数 |
| `resetmessagecounts [@user] [#channel]` | `rmc`、`resetmsgcounts`、`resetmessages`、`resetcounts` | 管理消息 | 确认后，重置整个服务器、某位成员、某个频道，或某位成员在某个频道中的计数 |

## 小贴士与注意事项

- 计数只会从启用的那一刻开始。之前发送的消息不会被补充统计。
- 在启用计数之前，所有统计命令和仪表板都会显示“已禁用”，即使已有旧数据。
- 计数按每批最多 100 个事件写入，因此总数可能比实时聊天略有延迟。
- 删除频道不会删除其计数。如果希望在删除频道前清除其数据，请先运行 `resetmessagecounts #channel`。
- 逐小时图表的准确性取决于你选择的时区。建议使用管理模块中的时区命令保存服务器时区，以便所有员工保持一致。
- XP 系统有自己的活跃度追踪，不使用这些计数。
