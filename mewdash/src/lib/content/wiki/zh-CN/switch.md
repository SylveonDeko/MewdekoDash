## 功能介绍

Switch 模块是一套面向 Nintendo Switch 自制软件和模拟器相关服务器的支持工具包。当有人发布类似 `2168-0002` 的错误时，帮助者可以运行 `err 2168-0002`，机器人会回复该错误所属的模块、已知的相关信息，以及（如果存在）Nintendo 支持页面的链接。

两个小型转换工具可以将 `NNNN-NNNN` 形式转换为代码和调试中使用的原始十六进制值，也可以反向转换。`switchbrew` 会搜索 switchbrew.org 维基，方便大家无需离开 Discord 即可找到 SVC、结果代码或硬件相关页面。

最重要的功能是 Ryujinx 日志分析器。用户附上 `Ryujinx.log`，有人对其运行 `analyselog`（或将其作为回复目标），机器人就会生成一个嵌入，其中包含游戏、模拟器版本、硬件、所有相关设置、最后一个错误、已安装的模组和作弊码，以及一份指出常见配置错误的注意事项列表。

无需进行任何配置，也不会存储任何数据。所有命令对所有人开放。

## 为什么要使用它

- 支持频道每天都会收到"2811-5001 是什么意思"之类的问题。
- Ryujinx 故障排除从阅读日志开始，而大多数人并不知道该看什么。
- 开发者需要错误的十六进制形式，以便在源代码中搜索。
- 任何人都可以在 Discord 中调出 switchbrew.org 的页面。

## 错误代码查询

`err <code>` 接受以下两种形式之一：

- `NNNN-NNNN`，其中第一组以 2 开头（例如 `2168-0002`）。模块编号为第一组减去 2000，描述编号为第二组。
- 带有 `0x` 前缀的十六进制值，例如 `0x2A2`。低九位为模块，其余部分为描述。

回复会以两种形式显示该代码，以及模块名称和编号、描述编号和解释。解释按以下顺序查找：该确切代码的已知描述、该确切代码的 Nintendo 支持页面、该代码所在模块范围的描述，否则显示"unknown"。已知代码以正常颜色显示，未知代码以错误颜色显示。

少数代码不符合此格式，例如 `2-AAB6A-3400`。这些代码会与一份简短列表进行精确匹配，并报告它们所属的游戏。

`err2hex <NNNN-NNNN>` 输出十六进制值。`hex2err <hex>` 输出带横线的形式；`0x` 前缀可以省略。

## Switchbrew 搜索

`switchbrew <query>` 会查询维基的搜索 API，返回前五个匹配结果，每个结果包含链接和最多 200 个字符的摘要。`svc` 是其别名，因此 `svc SetThreadPriority` 读起来很自然。

## Ryujinx 日志分析

`analyselog` 会查找你的消息中附加的 `.log` 或 `.txt` 文件。如果没有，并且你的消息是回复，它会使用你所回复的消息中的附件，并在页脚中注明该消息的作者。嵌入的标题为游戏名称，包含以下内容：

| 字段 | 内容 |
| --- | --- |
| General Info（常规信息） | Ryujinx 版本、固件、CPU、GPU、内存、操作系统 |
| System Settings（系统设置） | 音频后端、底座或掌机模式、PPTC、着色器缓存、VSync、虚拟化（仅 macOS） |
| Graphics Settings（图形设置） | 图形后端、分辨率缩放、各向异性过滤、宽高比、纹理重新压缩 |
| Errors（错误） | 日志中最后一个错误块，或"no errors"（无错误） |
| Mods（模组） | 每个模组及其为 ExeFS 或 RomFS；数量较多时会截断并显示计数 |
| Cheats（作弊码） | 每个作弊码，截断方式相同 |
| Notes（注意事项） | 检测到的问题和建议 |

注意事项涵盖以下内容：着色器缓存冲突或损坏、转储文件哈希错误、密钥过旧、缺少固件、文件权限错误、缺少存档、缺少服务、Vulkan 内存不足、默认用户配置文件、未配置手柄、应使用 Vulkan 的 Intel 或 AMD GPU、Apple 芯片上的 Rosetta、虚拟音频后端、PPTC 或着色器缓存已禁用、扩展内存、软件内存管理器、忽略缺失服务、VSync 已关闭、文件系统完整性检查已关闭、后端线程已关闭，以及自定义构建。每条注意事项都带有从信息到严重的严重程度标记。

如果文件无法下载，或不是 Ryujinx 日志，机器人会提示日志无效。

## 设置

此模块没有设置，也没有仪表板页面。

## 设置步骤

1. 确保机器人可以在支持频道中读取消息历史并附加文件。
2. 请用户将 `Ryujinx.log` 直接附加到消息中。
3. 帮助者回复该消息并运行 `analyselog`。
4. 对于错误代码，运行 `err <code>`，如果显示了支持链接，请分享该链接。
5. 可选：添加一个聊天触发器或置顶消息，提醒大家这两个命令的用法。

## 命令

使用服务器的前缀运行这些命令（如果你未更改，则为 `.`）。

| 命令 | 别名 | 所需权限 | 用途 |
| --- | --- | --- | --- |
| `err <code>` | `nxerr`, `serr` | 无 | 以带横线或十六进制形式解释 Switch 错误代码 |
| `err2hex <NNNN-NNNN>` | `e2h` | 无 | 将带横线的代码转换为十六进制 |
| `hex2err <hex>` | `h2e` | 无 | 将十六进制转换为带横线的形式 |
| `switchbrew <query>` | `sb`, `svc` | 无 | 搜索 switchbrew.org |
| `analyselog` | `analyzelog`, `analyselogs`, `analyzelogs`, `analyze`, `analyse` | 无 | 分析附加的 Ryujinx 日志 |

## 技巧与注意事项

- 带横线的形式必须恰好是四位数字、一个横线、四位数字，并以 2 开头。包含字母的代码只能通过特殊情况列表处理。
- 日志必须以 `.log` 或 `.txt` 格式附加；粘贴在代码块中的日志不会被读取。
- 分析器会读取整个文件，因此请向用户索取问题发生时所在会话的日志，而不是重新启动后的新日志。
- switchbrew.org 搜索是实时请求；如果网站响应缓慢，该命令也会变慢。
- 成员可以使用 `setswitchfc` 将其 Switch 好友代码存储在个人资料中，这属于用户个人资料模块的一部分。
