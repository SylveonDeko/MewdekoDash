## Що це робить

Персонал реєструє один або кілька серверів Minecraft за назвою та адресою. Будь-який учасник може потім виконати `mcstatus`, щоб побачити, чи працює сервер, його MOTD, версію, затримку та список тих, хто онлайн. За сервером також можна стежити: бот публікує embed статусу в каналі й оновлює його за таймером або записує кількість гравців у тему каналу, а також повідомляє, коли сервер впав або знову працює.

Якщо на сервері увімкнено RCON, персонал може надсилати консольні команди та керувати білим списком з Discord або з консолі панелі керування, не заходячи в гру.

Необов'язковий супутній плагін перетворює це з'єднання на двосторонній міст. Чат гравців, входи, виходи, смерті та досягнення публікуються в обраних тобою каналах Discord, а повідомлення, написані в каналі моста, транслюються гравцям у грі.

## Навіщо це потрібно

- Показувати живий embed "хто онлайн", щоб учасники знали, коли варто зайти.
- Миттєво сповіщати спільноту, коли сервер падає або повертається після обслуговування.
- Додавати нових учасників до білого списку з Discord, не відкриваючи консоль сервера.
- Тримати учасників, які є лише в Discord, в курсі через внутрішньоігровий чат, смерті та досягнення.
- Шукати UUID гравця або рендер скіну під час розгляду заявки чи скарги.

## Типи серверів

| Тип | Порт за замовчуванням | Як виконується запит |
| --- | --- | --- |
| Java Edition | 25565 | Server list ping; протокол запитів також використовується, коли встановлено **Query Port** і `enable-query=true` |
| Bedrock Edition | 19132 | Bedrock ping |
| Geyser (Java + Bedrock) | 25565 | Java ping, позначений як Geyser |

Кожен сервер має назву, яка зберігається в нижньому регістрі, і перший доданий сервер стає типовим, його використовує `mcstatus` без аргументів. Приватні, зарезервовані та loopback-адреси відхиляються, якщо хост бота не дозволив їх.

## Моніторинг сервера

Встанови **Канал моніторингу**, і бот опитуватиме сервер кожні **Watch Interval** хвилин (за замовчуванням 5, мінімум 1). Що бот робить з результатом, залежить від **Режим моніторингу**.

| Режим | Поведінка |
| --- | --- |
| Embed (edit in place) | Публікує один embed статусу і редагує його щотіку; публікує знову, якщо повідомлення видалено |
| Channel Topic | Записує короткий рядок статусу в тему каналу не частіше ніж раз на п'ять хвилин |
| Both | Виконує обидві дії вище |

Кожен тік також записує знімок стану онлайн, кількості гравців, затримки та версії. Вкладка **Історія** на панелі керування будує графіки цих даних у часі.

Коли стан онлайн змінюється, бот публікує сповіщення в каналі моніторингу: зелений embed "came online" або червоний "went offline" за замовчуванням, або твої шаблони **Сповіщення про онлайн сервера** і **Сповіщення про офлайн сервера**.

### Плейсхолдери статусу

**Власний embed моніторингу** і обидва шаблони сповіщень проходять через парсер embed і підтримують наведені нижче плейсхолдери.

| Плейсхолдер | Значення |
| --- | --- |
| `%mc.server.name%` | Зареєстрована назва |
| `%mc.server.address%` | Ім'я хоста або IP |
| `%mc.server.port%` | Порт |
| `%mc.online%` | `Online` або `Offline` |
| `%mc.players.online%` | Поточна кількість гравців |
| `%mc.players.max%` | Кількість слотів для гравців |
| `%mc.player.list%` | Імена гравців онлайн |
| `%mc.motd%` | MOTD без кодів форматування |
| `%mc.version%` | Версія, яку повідомив сервер |
| `%mc.latency%` | Пінг, наприклад `42ms` |
| `%mc.favicon%` | URL іконки сервера |
| `%mc.map%` | Назва світу, лише протокол запитів |
| `%mc.gamemode%` | Ігровий режим, лише протокол запитів |
| `%mc.software%` | Програмне забезпечення сервера, лише протокол запитів |
| `%mc.plugins%` | Список плагінів, лише протокол запитів |
| `%mc.query%` | `Yes`, якщо розширений запит отримав відповідь |
| `%mc.geyser%` | `Yes`, якщо виявлено Geyser |

## RCON і білий список

Увімкни **Налаштування RCON** для сервера і введи **Порт RCON** та **Пароль RCON** з `server.properties`. Після цього `mcrcon` надсилає будь-яку консольну команду і повертає її вивід. `mcwhitelist` обгортає команди білого списку з діями `add`, `remove`, `list`, `on`, `off` і `reload`. На панелі керування білий список відображається як список з кнопками додавання та видалення, а вкладка **Консоль** дає рядок команд для серверів з увімкненим RCON.

> [!WARNING]
> RCON дає повний доступ до консолі. Обмеж `mcrcon` для адміністраторів і стався до пароля як до будь-яких інших облікових даних сервера.

## Супутній плагін і міст

Для моста потрібен плагін MewdekoMC на ігровому сервері: плагін для Paper 1.21+ або мод NeoForge для 21.1.x, обидва на Java 21. На панелі керування відкрий розділ **Супутній плагін** сервера і згенеруй ключ. Скопіюй **API URL** і **API-ключ** у `config.yml` плагіна (Paper) або `config/mewdeko-server.toml` (NeoForge), а потім перезапусти сервер або виконай `/mewdeko reconnect`. Ключ показується лише один раз; щоб замінити його, згенеруй новий.

Після підключення плагін передає події через WebSocket, а бот спрямовує їх у канали.

| Подія | Куди надсилається | Вигляд за замовчуванням |
| --- | --- | --- |
| Вхід гравця | Канал **Вхід/вихід** | Зелений embed з іменем і аватаром гравця |
| Вихід гравця | Канал **Вхід/вихід** | Червоний embed з іменем і аватаром гравця |
| Чат | Канал **Міст чату** | `**player**: message` |
| Смерть | Канал **Смерті** | Сірий embed з повідомленням про смерть |
| Досягнення | Канал **Досягнення** | Зелений embed з назвою досягнення |
| Статус сервера | Нікуди; зберігається як знімок в історії з TPS і пам'яттю | |

Будь-який порожній канал події переходить до **Канал моніторингу**. Повідомлення від не-ботів у каналі Chat Bridge (або в каналі моніторингу, якщо канал чату не встановлено) пересилаються в гру у форматі `[Discord] user: message` за замовчуванням. Власний конфіг плагіна може вимкнути кожну категорію подій; передача консолі вимкнена за замовчуванням і ботом не відображається.

### Шаблони подій моста

Кожна подія, що надсилається в Discord, може мати власний шаблон у розділі **Шаблони подій моста**. Шаблони приймають вивід конструктора embed, згадки нейтралізуються, а наведені плейсхолдери замінюються.

| Шаблон | Плейсхолдери |
| --- | --- |
| Player Join (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| Player Leave (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| Chat Message (Discord) | `%mc.player%`, `%mc.message%`, `%mc.avatar%` |
| Death Message (Discord) | `%mc.player%`, `%mc.death.message%`, `%mc.avatar%` |
| Advancement (Discord) | `%mc.player%`, `%mc.advancement%`, `%mc.avatar%` |
| Chat from Discord (In-game format) | `%user%`, `%message%`, `%channel%`; використовуй коди кольорів Minecraft із символом секції |

## Налаштування

Сторінка Minecraft має вкладку **Сервери**, вкладку **Додати сервер**, **Історія**, **Консоль** і вкладку з назвою вибраного сервера для його редагування.

| Налаштування | За замовчуванням | Що контролює |
| --- | --- | --- |
| Name | | Короткий ідентифікатор для команд, наприклад `survival` |
| Address | | Ім'я хоста або IP |
| Port | 25565 | Ігровий порт; 19132 для Bedrock |
| Type | Java Edition | Java, Bedrock або Geyser |
| Query Port (0 = game port) | 0 | Порт для розширеного протоколу запитів |
| Watch Channel | немає | Канал, що отримує embed статусу і сповіщення |
| Watch Interval (minutes) | 5 | Як часто опитується сервер |
| Watch Mode | Embed | Embed, Channel Topic або Both |
| Custom Watch Embed | стандартний embed | Твій власний embed статусу з плейсхолдерами вище |
| Server Online Alert | стандартний embed | Надсилається, коли сервер знову працює |
| Server Offline Alert | стандартний embed | Надсилається, коли сервер вимикається |
| Event Channels | канал моніторингу | Chat Bridge, Join/Leave, Deaths, Advancements |
| Bridge Event Templates | стандартні | Шаблони для кожної події, перелічені вище |
| RCON Settings | вимкнено | Перемикач увімкнення, RCON Port, RCON Password |
| Companion Plugin | немає ключа | Згенерувати або відкликати API-ключ плагіна і скопіювати API URL |

## Покрокове налаштування

1. Відкрий **Minecraft** на панелі керування і перейди до **Додати сервер**.
2. Введи **Назва**, **Адреса** і **Порт**, вибери **Тип**, а також **Канал моніторингу** і **Режим моніторингу**. Збережи.
3. Перевір вкладку **Сервери**: картка статусу має показати сервер онлайн протягом кількох секунд.
4. Відредагуй сервер, щоб увімкнути **Налаштування RCON**, якщо потрібен доступ до консолі та білого списку, і спробуй вкладку **Консоль**.
5. Для мосту чату встанови **Event Channels**, згенеруй ключ у **Супутній плагін**, встанови плагін на ігровому сервері і встав URL та ключ у його конфіг.
6. Зайди в гру і напиши щось: це має з'явитися в каналі Chat Bridge, а відповідь там має з'явитися в грі.

## Команди

Виконуй їх з префіксом твого сервера (`.`, якщо ти його не змінював). Слеш-версії розміщено в `/minecraft`.

| Команда | Псевдоніми | Потрібно | Призначення |
| --- | --- | --- | --- |
| `mcstatus [name or address]` | `mcs` | Нікому | Статус сервера за замовчуванням, зареєстрованого сервера або будь-якої адреси `host:port`, яку ти введеш |
| `mcadd <name> <address[:port]>` | | Керування сервером | Зареєструвати сервер; додай `bedrock:` перед адресою для Bedrock |
| `mcremove <name>` | `mcrm` | Керування сервером | Видалити зареєстрований сервер |
| `mclist` | `mcl` | Нікому | Список зареєстрованих серверів з типом, позначкою типового і каналом моніторингу |
| `mcdefault <name>` | `mcdef` | Керування сервером | Вибрати сервер, який `mcstatus` використовує за замовчуванням |
| `mcwatch <name> [#channel]` | `mcw` | Керування сервером | Почати публікувати статус у канал або зупинити без каналу |
| `mcwatchmode <name> <embed, channeltopic or both>` | `mcwm` | Керування сервером | Вибрати, як моніторинг показує статус |
| `mcembed <name> [template]` | `mce` | Керування сервером | Встановити власний embed статусу або `-` для скидання |
| `mcplayer <username>` | `mcp` | Нікому | Показати UUID, аватар і скін гравця |
| `mcskin <username>` | | Нікому | Показати рендер скіну гравця |
| `mcrcon <name> <command>` | | Адміністратор | Виконати консольну команду через RCON |
| `mcwhitelist <name> <action> [player]` | `mcwl` | Керування сервером | `add`, `remove`, `list`, `on`, `off` або `reload` |

## Поради та підводні камені

- `mcstatus` обмежено десятьма запитами на хвилину для кожного сервера Discord, спільними для всіх учасників.
- Пряме опитування адреси командою `mcstatus play.example.com:25565` працює без реєстрації, але приватні та локальні адреси блокуються.
- Боту потрібне право **Керування каналами** в каналі моніторингу для режиму Channel Topic, а Discord сам обмежує редагування теми, тож режим теми ніколи не оновлюється частіше ніж раз на п'ять хвилин.
- Розширені дані, як-от карта, ігровий режим і плагіни, з'являються лише коли в `server.properties` встановлено `enable-query=true` і **Query Port** збігається.
- Якщо embed моніторингу видалено, наступний тік публікує новий, а не видає помилку.
- Повідомлення моста нейтралізують `@everyone`, `@here` і згадки користувачів, тож гравці не можуть пінгувати Discord із гри.
