## Що це робить

Персонал додає один або кілька текстів для відстеження, наприклад `discord.gg/yourserver` або `playing minecraft`. Бот стежить за оновленнями присутності. Коли власний статус учасника починає містити цей текст, бот видаляє ролі, перелічені в **Ролі для видалення**, додає ролі з **Ролі для додавання** і, якщо встановлено канал та повідомлення, публікує сповіщення туди.

Коли текст зникає зі статусу, два перемикачі визначають, що станеться. **Remove Added** забирає ролі, які були видані. **Readd Removed** повертає ролі, які були забрані. Обидва вимкнені за замовчуванням, тож без змін учасник просто зберігає ті ролі, які отримав у результаті.

Перевіряється лише власний статус, тобто текст, який учасник вказав у "Set a custom status" в Discord. Активності на кшталт гри, Spotify і стрімінгу ігноруються. Учасники, які офлайн або невидимі, пропускаються, а перевірка збігу — це простий пошук підрядка, тож `mewdeko` знаходить `I love mewdeko`, але регістр має значення.

Кожен сервер може мати будь-яку кількість записів статусних ролей, кожен зі своїми ролями, каналом і повідомленням. Команди посилаються на запис за його індексом, тобто номером, який показує `liststatusroles`.

## Навіщо це потрібно

- Нагороджувати учасників, які ставлять твоє персональне запрошення у статус, роллю підтримувача та її перевагами.
- Видавати роль "стрімлю" або "шукаю гру", поки хтось рекламує це у статусі, і знімати її, коли він перестає.
- Оголошувати в каналі, коли учасник починає представляти сервер, щоб персонал міг йому подякувати.
- Міняти одну роль на іншу, поки активний певний статус, наприклад вивести учасника з ролі "без пінгів", поки він показує певний статус.

## Збіг і зміни ролей

| Ситуація | Що робить бот |
| --- | --- |
| Статус отримує відстежуваний текст | Видаляє **Ролі для видалення**, додає **Ролі для додавання**, надсилає сповіщення, якщо його налаштовано |
| Статус і далі містить відстежуваний текст | Нічого, зміна обробляється лише один раз |
| Статус втрачає відстежуваний текст, увімкнено **Remove Added** | Знімає ті з **Ролей для додавання**, які учасник ще має |
| Статус втрачає відстежуваний текст, увімкнено **Readd Removed** | Повертає ті з **Ролей для видалення**, яких учаснику більше немає |
| Учасник переходить в офлайн або стає невидимим | Нічого, ролі залишаються як є |

Бот порівнює кожне оновлення присутності з останнім статусом, який він закешував для цього користувача, тож учасник, який змінює непов'язану частину свого статусу, не обробляється повторно. Відстежуваний текст має бути унікальним для кожного сервера; команди обмежують його 128 символами, панель керування — ні.

## Повідомлення сповіщення

Якщо в записі задано і **Канал сповіщень**, і **Повідомлення сповіщення**, бот публікує повідомлення туди щоразу, коли статус учасника починає збігатися. Текст проходить через парсер вбудованих повідомлень, тож працює все, що створює конструктор вбудованих повідомлень: звичайний текст, до десяти вбудованих повідомлень і компоненти. Коли статус перестає збігатися, нічого не публікується.

### Плейсхолдери

Повідомлення проходить через стандартний набір заміни для учасника, каналу сповіщень і сервера. Найкорисніші наведено нижче; повний список є на сторінці плейсхолдерів у розділах user, server, channel, bot і time.

| Плейсхолдер | Значення |
| --- | --- |
| `%user.mention%` | Згадка учасника |
| `%user.name%` | Ім'я користувача учасника |
| `%user.fullname%` | Ім'я користувача з дискримінатором |
| `%user.avatar%` | URL аватара учасника |
| `%user.id%` | ID користувача учасника |
| `%server.name%` | Назва сервера |
| `%server.icon%` | URL іконки сервера |
| `%channel.mention%` | Згадка каналу сповіщень |
| `%server.time%` | Поточний час у налаштованому часовому поясі сервера |

> [!NOTE]
> У редакторі на панелі керування є плейсхолдер `%status%`, але бот його не замінює. Впиши текст статусу в повідомлення самостійно.

> [!EXAMPLE]
> `%user.mention% is now repping the server in their status, thank you!`

## Налаштування

Усе розташоване на сторінці Статусні ролі, яка має три вкладки: **Статусні ролі**, **Додати нову** і **Статистика**. Кожен запис у списку розгортається, щоб показати свої налаштування.

| Налаштування | Типово | Що керує |
| --- | --- | --- |
| Текст статусу для відстеження | немає | Текст, який має містити власний статус; на панелі керування без ліміту довжини, через команди 128 символів |
| Ролі для додавання | немає | ID ролей через пробіл, які видаються, коли статус збігається; Save замінює весь список |
| Ролі для видалення | немає | ID ролей через пробіл, які забираються, коли статус збігається; Save замінює весь список |
| Канал сповіщень | немає | Канал, у який надсилається повідомлення сповіщення |
| Повідомлення сповіщення | немає | Текст або вбудоване повідомлення, що надсилається в канал, з плейсхолдерами |
| Remove Added | вимкнено | Забирати додані ролі, коли статус перестає збігатися |
| Readd Removed | вимкнено | Повертати видалені ролі, коли статус перестає збігатися |

Вкладка **Статистика** показує загальну кількість записів, скільки з них змінюють ролі і скільки мають канал сповіщень.

## Покрокове налаштування

1. Відкрий **Статусні ролі** на панелі керування і перейди до вкладки **Додати нову**.
2. Введи текст для відстеження і натисни **Додати статусну роль**.
3. Перейди до вкладки **Статусні ролі** і розгорни новий запис.
4. Натисни **Редагувати налаштування**, встав ID ролей у **Ролі для додавання** та **Ролі для видалення**, обери **Канал сповіщень** і напиши **Повідомлення сповіщення**, якщо потрібно, а потім **Зберегти**.
5. Використай два перемикачі на записі, щоб увімкнути **Remove Added** і, за потреби, **Readd Removed**.
6. Перевір: постав свій власний статус із цим текстом і переконайся, що роль з'явилася, потім очисти статус і переконайся, що роль зникла.

## Команди

Виконуй їх із префіксом свого сервера (`.`, якщо ти його не змінював). Кожна команда потребує права Керування сервером. `<index>` — це номер, який показує `liststatusroles`, починаючи з 1. Слеш-версії розташовані під `/statusroles`.

| Команда | Псевдоніми | Потрібно | Призначення |
| --- | --- | --- | --- |
| `addstatusrole <text>` | `asr` | Керування сервером | Додати текст статусу для відстеження |
| `removestatusrole <index>` | `rsr` | Керування сервером | Видалити запис |
| `liststatusroles` | `lsr` | Керування сервером | Переглянути всі записи з їхніми індексами та налаштуваннями |
| `setaddroles <index> <@role...>` | `sar` | Керування сервером | Додати ролі до списку, який видається, коли статус збігається |
| `setremoveroles <index> <@role...>` | `srr` | Керування сервером | Додати ролі до списку, який забирається, коли статус збігається |
| `removeaddroles <index> <@role...>` | `remar` | Керування сервером | Прибрати ролі зі списку "ролі для додавання" |
| `removeremoveroles <index> <@role...>` | `rmremoveroles` | Керування сервером | Прибрати ролі зі списку "ролі для видалення" |
| `setstatusrolechannel <index> <#channel>` | `statusrolechannel`, `ssrc` | Керування сервером | Встановити канал сповіщень |
| `setstatusroleembed <index> [text]` | `statusroleembed`, `asre` | Керування сервером | Встановити повідомлення сповіщення або, без тексту, показати поточне |
| `toggleremoveadded <index>` | `togglerma` | Керування сервером | Перемкнути **Remove Added** |
| `togglereaddremoved <index>` | `togglermrm` | Керування сервером | Перемкнути **Readd Removed** |

`setaddroles` і `setremoveroles` додають ролі до наявного списку, а не замінюють його. Щоб прибрати ролі, використовуй команди `remove...`. Редактор на панелі керування працює навпаки: що є в полі на момент Save, стає повним списком, але порожнє поле ігнорується, тож повністю очистити список можна лише командами `remove...`.

## Поради та підводні камені

- Боту потрібне право Керування ролями, і його найвища роль має бути вищою за всі ролі, які він додає або видаляє. Помилки лише записуються в журнал, учасник нічого не бачить.
- Бот має мати інтент присутності, щоб взагалі бачити власні статуси. Якщо нічого не відбувається, коли ти змінюєш статус, це перше, що варто перевірити.
- Збіг чутливий до регістру і шукає текст у будь-якому місці статусу. Тримай текст для відстеження коротким і впізнаваним.
- Бот дивиться лише на першу активність у присутності учасника. Discord зазвичай ставить власний статус першим, але якщо попереду стоїть інша активність, статус не буде помічено.
- Ролі змінюються лише під час зміни статусу. Учасник, який уже має цей текст у статусі на момент створення запису, не обробляється, доки його статус не зміниться.
- Сповіщення надсилається щоразу, коли статус починає збігатися, тож учасник, який постійно перемикає статус, спричинить повторні повідомлення.
- Панель керування приймає ID ролей, а не назви. Увімкни Режим розробника в Discord і клацни правою кнопкою миші на роль, щоб скопіювати її ID.
