## Що це робить

За замовчуванням відкрити сервер на панелі керування можуть лише власник сервера та учасники з дозволом Адміністратор. Доступ до панелі дозволяє розширити це коло. Ти обираєш учасника або роль, вибираєш, які розділи панелі вони отримають, і чи буде кожен з них **Перегляд** чи **Керування**. Відтепер цей сервер з'являється у списку серверів на їхній панелі, а розділи, які ти надав, працюють для них; усе інше відхиляється.

Перевірка відбувається на API бота, а не лише на веб-сторінці. Кожен запит, що стосується сервера, містить ідентичність авторизованого користувача. Якщо це власник або адміністратор, запит проходить. Інакше бот знаходить розділ, до якого належить запит, вважає читання **Перегляд**, а будь-яку зміну **Керування**, і порівнює це з найвищим рівнем, який користувач має безпосередньо або через будь-яку зі своїх ролей.

Власник сервера також вирішує, хто може редагувати сам список доступу. За замовчуванням це лише власник. Власник може призначити конкретних менеджерів доступу або ввімкнути один перемикач, щоб дозволити це кожному, хто має Адміністратор або Керування сервером.

## Навіщо це потрібно

- Команда спільноти веде giveaway, пропозиції та тікети з панелі, не маючи Адміністратора в Discord.
- Роль модератора отримує **Керування** для Moderation і Logging та **Перегляд** для всього іншого, тож вона може дивитися, але не змінювати налаштування, які їй не належать.
- Помічник бота має право редагувати XP і Валюту, але нічого, пов'язаного з безпекою.
- Власник делегує супровід списку доступу ролі співвласника, не віддаючи керування, доступне лише власнику.

## Рівні доступу

| Рівень | Дозволяє |
| --- | --- |
| Немає | Нічого для цього розділу; розділ не надано |
| Перегляд | Лише запити на читання, як-от відкриття сторінки та завантаження її даних |
| Керування | Усе, що дозволяє Перегляд, плюс створення, редагування та видалення |

Коли учасник відповідає кільком наданим доступам, наприклад персональному і через роль, для кожного розділу перемагає найвищий рівень. Учасник, якому надано принаймні один розділ, бачить сервер у своєму перемикачі серверів на панелі; учасник без жодного доступу — ні.

Власники та адміністратори повністю оминають надані доступи й завжди мають повний доступ.

## Розділи

Розділи відповідають бічній панелі на панелі керування. Кожна функція у виборі відповідає одній або кільком областям API бота, тож надання "Administration" охоплює ендпоїнти Administration і Protection, а "Moderation" також охоплює Protection. Вибір групує розділи за категоріями бічної панелі, а функції, що є глобальною інфраструктурою бота, а не даними конкретного сервера, наприклад Performance, не можна надавати.

Коли доступ охоплює функцію, що відповідає кільком областям, вибір показує найнижчий рівень, спільний для них усіх; встановлення групи одразу встановлює всі її області.

## Хто може керувати списком доступу

| Хто | Що може робити |
| --- | --- |
| Власник сервера | Усе: перемикач делегування, список менеджерів і всі доступи |
| Призначені менеджери доступу | Додавати, редагувати та видаляти доступи |
| Учасники з Адміністратор або Керування сервером | Додавати, редагувати та видаляти доступи, лише коли перемикач делегування увімкнено |
| Усі інші | Бачать "You can't manage dashboard access here" |

Менеджером доступу може бути учасник або роль. Лише власник може бачити або змінювати список менеджерів і перемикач делегування; API відхиляє ці виклики від усіх інших.

> [!WARNING]
> Надати **Керування** для Dashboard Access неможливо, бо контролер доступу звільнений від перевірок розділів. Щоб передати комусь керування списком, використовуй список менеджерів або перемикач делегування.

## Налаштування

Усе розташоване на єдиній сторінці Доступ до панелі.

| Налаштування | Типово | Що керує |
| --- | --- | --- |
| Дозволити адміністраторам і учасникам із Керуванням сервером керувати доступом до панелі | Вимкнено | У **Налаштуваннях делегування**. Коли увімкнено, учасники з Адміністратор і Керування сервером можуть редагувати доступи. Лише власник. |
| Менеджери доступу | немає | Учасники або ролі, призначені для редагування доступів. Лише власник. |
| Доступи | немає | Один запис на учасника або роль, із рівнем для кожного розділу. Менеджери та власник. |

Форма **Надання обмеженого доступу** приймає тип об'єкта (користувач або роль), сам об'єкт і рівень для кожної групи функцій. Збереження другого доступу для того самого об'єкта замінює перший. Редагування наявного доступу відкриває ту саму форму як **Редагування доступу**.

## Покрокове налаштування

1. Відкрий **Доступ до панелі** на панелі керування як власник сервера.
2. Вирішиш, хто підтримує список. Або увімкни перемикач делегування в **Налаштуваннях делегування**, або додай учасника чи роль у **Менеджери доступу**.
3. У **Надання обмеженого доступу** обери **Роль** і вибери роль свого персоналу.
4. Постав **Керування** для функцій, якими вони керують щодня, і **Перегляд** для тих, які вони мають лише переглядати. Решту залиш на **Немає**.
5. Натисни **Надати доступ**. Доступ з'явиться в **Доступи**.
6. Попроси учасника з цією роллю увійти на панель. Сервер має з'явитися в їхньому списку, а працювати лише надані сторінки.

## Команди

Доступ до панелі налаштовується лише з панелі керування; команд бота для нього немає.

## Поради та підводні камені

- Доступи перевіряються за кешованим списком учасників бота, тож учасник має бути на сервері й видимим для бота, щоб його доступ працював.
- Доступи через роль відстежують поточні ролі учасника. Видалення ролі одразу забирає доступ.
- Доступ, у якому кожен розділ має **Немає**, вважається відсутнім і відкидається, а учасник втрачає сервер у своєму перемикачі.
- Адміністратори зберігають повний доступ незалежно від доступів. Щоб обмежити когось, спершу забери в нього Адміністратор у Discord, а потім надай потрібне тут.
- Проксі панелі додає спільний ключ API до кожного запиту, але сам лише цей ключ ніколи не дає доступу до сервера; завжди потрібна ідентичність авторизованого користувача.
- Ендпоїнти, не прив'язані до сервера, як-от глобальний список команд, не підлягають перевіркам розділів і продовжують працювати для обмежених користувачів.
