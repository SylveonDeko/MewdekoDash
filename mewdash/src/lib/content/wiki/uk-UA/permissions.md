## Що це робить

За замовчуванням кожна команда доступна всім, кому дозволяють дозволи Discord. Дозволи команд додають поверх цього власний список правил сервера. Кожне правило визначає, чи дозволено або заборонено команду, модуль чи всі модулі для всього сервера, ролі, каналу, категорії або одного учасника. Коли хтось запускає команду, бот проходить список, застосовує перше правило, що підходить, і або пропускає команду, або зупиняє її.

Заблоковані команди непомітно ігноруються, якщо не увімкнено **докладний режим**. Тоді бот відповідає номером і текстом правила, яке її заблокувало. Слеш-команди завжди отримують ефемерне пояснення.

Правилами можуть керувати адміністратори або будь-хто з **роллю дозволів**, яку ти обереш. Той самий список є на панелі керування в розділі **Адміністрування**, у секції **Автоматизація та налаштування**, як картка **Дозволи команд**.

Поруч є два пов'язані інструменти. Кулдауни команд обмежують, як часто учасник може використовувати команду на сервері. Перевизначення дозволів Discord у модулі Адміністрування замінюють дозвіл Discord, який команда зазвичай вимагає, наприклад дозволяють використовувати команду, що зазвичай потребує Адміністратора, тим, хто має дозвіл «Керувати повідомленнями».

## Навіщо це потрібно

- Тримай розважальні та NSFW-команди подалі від серйозних каналів.
- Вимкни модуль Music скрізь, крім каналу для команд бота.
- Дай ролі помічників використовувати `warn`, не видаючи їм «Керувати повідомленнями» чи Адміністратора.
- Повністю заблокуй користування ботом для одного проблемного учасника.
- Обмеж частоту шумної команди на кшталт `roll` до одного разу на десять секунд для кожного учасника.

## Як записується правило

Кожне правило має три частини.

| Частина | Варіанти |
| --- | --- |
| Що | Одна команда, один модуль або всі модулі |
| Для кого | Весь сервер, роль, канал, категорія або конкретний користувач |
| Дія | Дозволити або заборонити |

Назви команд у таблиці нижче кодують перші дві частини. Перші літери визначають ціль (`s` сервер, `r` роль, `c` канал, `ca` категорія, `u` користувач), останні визначають обсяг (`cmd` команда, `mdl` модуль), а форми `all...mdls` охоплюють усі модулі.

| Команда | Створюване правило |
| --- | --- |
| `srvrcmd <command> <enable|disable>` | Команда для всього сервера |
| `srvrmdl <module> <enable|disable>` | Модуль для всього сервера |
| `allsrvrmdls <enable|disable>` | Усі модулі для всього сервера |
| `rolecmd <command> <enable|disable> <role>` | Команда для ролі |
| `rolemdl <module> <enable|disable> <role>` | Модуль для ролі |
| `allrolemdls <enable|disable> <role>` | Усі модулі для ролі |
| `chnlcmd <command> <enable|disable> <#channel>` | Команда в каналі |
| `chnlmdl <module> <enable|disable> <#channel>` | Модуль у каналі |
| `allchnlmdls <enable|disable> <#channel>` | Усі модулі в каналі |
| `catcmd <command> <enable|disable> <category>` | Команда в кожному каналі категорії |
| `catmdl <module> <enable|disable> <category>` | Модуль у категорії |
| `allcatmdls <enable|disable> <category>` | Усі модулі в категорії |
| `usrcmd <command> <enable|disable> @user` | Команда для одного учасника |
| `usrmdl <module> <enable|disable> @user` | Модуль для одного учасника |
| `allusrmdls <enable|disable> @user` | Усі модулі для одного учасника |

Чат-тригери вважаються командами: вказуй номер або текст тригера там, де очікується назва команди.

> [!EXAMPLE]
> `srvrmdl nsfw disable`, а потім `chnlmdl nsfw enable #adult` блокує модуль NSFW всюди, крім одного каналу.

## Порядок правил

`listperms` показує список з нумерацією від 1. Правило 1 завжди означає «дозволити всі модулі для всього сервера»; його не можна змінити чи видалити, і воно застосовується, коли більше нічого не підходить.

Нові правила додаються в кінець списку. Коли запускається команда, бот перевіряє правила, починаючи з найбільшого номера і рухаючись до правила 1, і перше правило, у якого збігаються ціль і обсяг, вирішує результат. Отже, найновіше правило, що підходить, перемагає. Саме тому приклад вище працює: дозвіл для каналу додано після заборони для сервера.

`moveperm <from> <to>` змінює позицію правила і перенумеровує все, тож можна підняти виняток вище або нижче ширшого правила без повторного створення. `removeperm <number>` видаляє одне правило. `resetperms` повертає список до правила 1 і потребує Адміністратора.

На панелі керування ті самі правила показані зі стрілками «вгору» і «вниз» та кнопкою видалення для кожного правила.

## Докладний режим

`verbose` перемикає, чи отримує заблокована текстова команда повідомлення про помилку з назвою правила, наприклад «дозвіл 4 (`.chnlmdl nsfw disable #general`) не дозволяє цього». За замовчуванням він вимкнений. Коли він вимкнений, заблоковані команди ігноруються без повідомлень, що правильно для більшості серверів і не дає учасникам досліджувати, чого вони не можуть запускати. Слеш-команди завжди відповідають із причиною, ефемерно, незалежно від цього налаштування.

## Хто може змінювати правила

Кожна команда цього модуля проходить додатковий контроль. Адміністратори можуть використовувати їх завжди. Усі інші потребують **ролі дозволів**, встановленої командою `permrole <role>`. Якщо її немає, не-адміністраторам повідомляють, що їм потрібні права адміністратора (лише коли докладний режим увімкнено), і команда зупиняється. `permrole` без аргументу показує поточну роль; `permrole reset` її очищує. Роль `@everyone` використовувати не можна.

Самі `resetperms` і `permrole` завжди потребують Адміністратора понад це.

## Кулдауни

`cmdcooldown <command> [time]` встановлює кулдаун для команди для кожного учасника на цьому сервері: від 1 секунди до 90000 секунд (25 годин). Без часу або з `0s` кулдаун очищується. `allcmdcooldowns` показує поточні кулдауни. Вони додаються до будь-якого вбудованого кулдауну, який уже має команда.

## Перевизначення дозволів Discord

Модуль Адміністрування може замінити дозвіл Discord, який потрібен команді. `dpo <command> <permissions...>` змушує команду вимагати перелічені дозволи замість вбудованого, наприклад `dpo purge ManageMessages`. Запусти `dpo <command>` без дозволів, щоб прибрати перевизначення, `dpol`, щоб його переглянути, і `dpor`, щоб очистити всі після підтвердження. Усі три потребують Адміністратора.

Перевизначення замінює лише вимогу Discord. Правила дозволів команд вище все одно діють, а сторінка команди з `help <command>` показує початкову вимогу закресленою, а поруч — перевизначення.

## Швидке меню в help

`help <command>` показує адміністраторам кнопку дозволів. Вона відкриває швидке меню для цієї однієї команди, де видно правила, що її стосуються, попереджає про зайві правила (два правила з однаковою ціллю та обсягом), пропонує їх усунути і дозволяє додавати правила дозволу та заборони для команди або скидати її дозволи, не залишаючи сторінку help.

## Керування для власника бота

Три групи команд доступні лише власникам бота і діють на всі сервери: глобальні дозволи (`globalmodule`, `globalcommand`, `globalpermlist`, `resetglobalperms`) вимикають модуль або команду всюди, а чорний список (`userblacklist`, `channelblacklist`, `serverblacklist`, `manualblacklistcheck`) зупиняє реакції бота на користувача, канал або сервер повністю. Глобально вимкнений модуль позначається в меню help глобусом із хрестиком.

## Налаштування

На панелі керування відкрий **Адміністрування**, потім секцію **Автоматизація та налаштування**, потім картку **Дозволи команд**.

| Налаштування | За замовчуванням | Що контролює |
| --- | --- | --- |
| Докладні дозволи | вимкнено | Повідомляти користувачам, коли правило блокує команду |
| Роль дозволів | немає | Учасники з цією роллю можуть змінювати правила командами |
| Правила | лише правило 1 | Упорядкований список; додавай через **Дія**, **Що** і **Для кого**, а потім модуль, команду, роль, канал, категорію або ID користувача |

Картка також показує кількість власних правил і чи увімкнено докладний режим. Картка **Перевизначення дозволів** у тій самій секції керує перевизначеннями дозволів Discord: вибери команду бота і **Необхідний дозвіл Discord**, який вона має вимагати замість вбудованого.

## Покрокове налаштування

1. Визнач форму: зазвичай «все дозволено, дещо заборонено» або «все заборонено, а потім дозволено в каналах для бота».
2. Для другої форми виконай `allsrvrmdls disable`, а потім `allchnlmdls enable #bot-commands`.
3. Збережи модерацію для персоналу: `rolemdl moderation enable @Mods` і `rolemdl administration enable @Mods`.
4. Виконай `listperms` і читай його знизу вгору, адже саме в такому порядку працює бот. Використай `moveperm`, якщо виняток стоїть нижче правила, яке він має перевизначати.
5. Дай довіреному персоналу `permrole @Mods`, щоб вони могли змінювати правила без Адміністратора.
6. Під час тестування увімкни `verbose`, щоб бачити, яке правило спрацьовує, а потім знову вимкни.

## Поради та підводні камені

- `resetperms` звільнений від перевірки правил, тож ти завжди можеш відновитися після правила, яке заблокувало все, якщо ти адміністратор.
- Правила зіставляються за канонічною назвою команди, тож `srvrcmd clear disable` і `srvrcmd purge disable` є одним і тим самим правилом. Використовуй першу назву з `help <command>`.
- Правило для «всіх модулів» також охоплює модуль Permissions. Якщо ти заборониш усе для ролі, учасники лише з цією роллю теж не зможуть запустити `listperms`.
- Правила для категорій використовують батьківську категорію каналу на момент запуску команди; гілки успадковують від свого батьківського каналу.
- Перевизначення дозволів Discord змінюють те, який дозвіл Discord потрібен, а не те, кому дозволяють правила. Використовуй їх разом: перевизначення, щоб знизити planку, і правило, щоб обмежити місце.
- Правила дозволів ніколи не діють у особистих повідомленнях.
- Панель керування називає варіанти цілі «Весь сервер», «Роль», «Канал», «Категорія» і «Конкретний користувач»; варіант користувача приймає вставлений ID користувача.
