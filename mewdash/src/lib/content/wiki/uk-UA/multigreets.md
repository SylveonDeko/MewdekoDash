## Що це робить

Коли учасник приєднується, бот публікує привітання в кожному каналі, який ти налаштував як привітання. Кожне привітання має власне повідомлення, власний таймер видалення, власну ідентичність вебхука і власний перемикач для ботів. Можна запустити їх усі одразу або обирати одне випадкове на кожне приєднання.

Повідомлення проходять через парсер embed, тож привітання може бути простим текстом, повним embed з кнопками або повідомленням через webhook з власним іменем і аватаром. Заповнювачі підставляють ім'я учасника, назву сервера, кількість учасників і, якщо відстеження запрошень увімкнено, того, хто запросив.

Стара система з одним повідомленням також існує поруч. Вона відповідає за повідомлення про вихід, коли хтось іде, оголошення про буст, коли хтось робить буст, і приватне привітання в ПП. Вони живуть у модулі Administration і описані нижче.

## Навіщо це потрібно

- Публічне привітання в `#general` і короткий лог-рядок у `#staff-joins` з одного приєднання.
- Різні стилі привітань для кожного каналу, наприклад embed в одному і webhook-«персонаж» в іншому.
- Набір привітань, де кожен новий учасник отримує одне обране випадково.
- Коротке привітання, яке видаляє себе через хвилину, щоб канал не забивався.
- Повідомлення про вихід або буст без налаштування чогось іншого.

## Типи привітань

**Тип привітання** діє для всього сервера і визначає, що відбувається під час приєднання.

| Тип | Підпис на панелі керування | Що відбувається |
| --- | --- | --- |
| MultiGreet | **Усі привітання** | Спрацьовують усі увімкнені привітання в порядку додавання. За замовчуванням. |
| RandomGreet | **Випадкове привітання** | Зі списку випадково обирається одне привітання і спрацьовує. Вимкнені привітання можуть бути обрані, і тоді їх пропускають. |
| Off | **Вимкнено** | Жодне привітання не спрацьовує. |

## Що містить одне привітання

Кожне привітання прив'язане до одного каналу. Один канал може мати до п'яти привітань, а на сервері їх може бути тридцять. Привітання нумеруються за позицією в списку, і саме цей номер використовують команди.

| Поле | За замовчуванням | Значення |
| --- | --- | --- |
| Канал | канал, який ти додав | Куди публікується це привітання |
| Повідомлення | порожньо | Шаблон тексту або embed. Порожнє привітання нічого не надсилає. |
| **Видалити через** | 0 (ніколи) | Скільки секунд до самовидалення привітання |
| **Привітати ботів** | вимкнено | Чи спрацьовує привітання, коли приєднується акаунт бота |
| **Вебхук** | немає | Публікувати через webhook з власним іменем і аватаром, а не від імені бота |
| **Увімкнено** | увімкнено | Вимкнені привітання пропускаються, але не видаляються |

Якщо канал видалено, привітання прибирається під час наступної спроби спрацювати. Якщо вебхук видалено або бот втрачає право публікувати, привітання вимикається, а не видає помилку під час кожного приєднання.

## Заповнювачі

Привітання будуються з наборів заповнювачів для користувача, сервера і бота. Заповнювачі запрошень працюють лише тоді, коли відстеження запрошень увімкнено на сторінці Invites.

| Заповнювач | Значення |
| --- | --- |
| `%user%`, `%user.mention%` | Згадка нового учасника |
| `%user.name%`, `%username%` | Ім'я користувача |
| `%user.fullname%`, `%userfull%` | Повний тег |
| `%user.id%`, `%id%` | ID користувача |
| `%user.avatar%`, `%useravatar%` | URL аватара |
| `%user.banner%` | URL банера |
| `%user.created_date%`, `%user.created_time%` | Коли створено акаунт |
| `%user.joined_date%`, `%user.joined_time%` | Коли учасник приєднався до цього сервера |
| `%server%`, `%server.name%` | Назва сервера |
| `%server.id%`, `%sid%` | ID сервера |
| `%server.icon%`, `%server.banner%` | URL іконки і банера |
| `%server.members%`, `%members%` | Кількість учасників |
| `%server.boostlevel%`, `%server.boostcount%` | Рівень бустів і кількість бустів |
| `%server.time%`, `%server.timestamp.longdatetime%` | Поточний час, звичайний або як мітка часу Discord |
| `%bot.name%`, `%bot.id%`, `%bot.avatar%` | Дані про самого бота |
| `%inviter.username%`, `%inviter.mention%`, `%inviter.id%`, `%inviter.avatar%` | Той, чиє запрошення використали, або `Unknown` |
| `%inviter.count%`, `%inviter.regular%`, `%inviter.left%`, `%inviter.fake%`, `%inviter.bonus%` | Лічильник запрошень того, хто запросив |
| `%invite.code%`, `%invite.url%`, `%invite.uses%`, `%invite.label%`, `%invite.type%` | Використане запрошення, його мітка і те, чи це запрошення, персоналізоване посилання чи застосунок |
| `%user.joincount%`, `%user.leavecount%` | Скільки разів цей учасник приєднувався і виходив |
| `%server.members.ordinal%` | Кількість учасників як 1-й, 2-й, 1 204-й |
| `%user.joined.R%`, `%user.created.F%` (і стилі t, T, d, D, f) | Час приєднання і створення акаунта як мітки часу Discord |

> [!EXAMPLE]
> `Welcome %user.mention% to %server%! You are member #%server.members%.`

Повний список заповнювачів сервера, каналу і бота є на сторінці placeholders. Заповнювачі каналу для привітань не заповнюються.

## Класичні команди привітання, прощання і буста

Ці команди з'явилися раніше за multi greets і живуть у модулі Administration. Кожна з них — це одне повідомлення, яке зберігається в конфігурації сервера і перемикається з каналу, у якому ти виконуєш команду.

| Повідомлення | Спрацьовує, коли | Заповнювачі |
| --- | --- | --- |
| Bye | Учасник виходить | Набори для користувача, сервера і бота, а також заповнювачі каналу. `%user%` згадує учасника, який вийшов. |
| Boost | Учасник починає бустити або бустить знову | Набори для користувача, каналу, сервера, бота і gif |
| Greet DM | Учасник приєднується; надсилається в приватні повідомлення | Набори для користувача, каналу, сервера, бота і gif |

Команди `bye` або `boost` перемикають відповідне повідомлення і встановлюють канал, який ти вказав. `byedel` і `boostdel` задають таймер самовидалення в секундах; `boostdel` обмежено 600. Команди повідомлень без тексту показують поточне повідомлення. `leavehook` огортає повідомлення про вихід у webhook з власним іменем і аватаром, а `leavehook disable` його прибирає.

Привітальні ПП потребують уважності. Бот просить підтвердження перед їх увімкненням, якщо він не верифікований, бо масові ПП від неверифікованих ботів можуть призвести до позначення бота. Будь-який учасник може відмовитися від цих ПП для себе командою `greetdmoptout` або перемикачем **Привітальні ПП** на своїй сторінці профілю на панелі керування.

Команди класичного привітання в каналі немає. Для привітань у каналах використовуй multi greet.

## Налаштування

Усе це на сторінці Привітання на панелі керування.

| Налаштування | За замовчуванням | Що керує |
| --- | --- | --- |
| **Тип привітання** | Усі привітання | Усі привітання, Випадкове привітання або Вимкнено |
| **Додати нове привітання** | | Обери канал, потім натисни **Додати привітання** |
| **Повідомлення привітання** | порожньо | Конструктор embed для одного привітання. Підтримує текст, до десяти embed і компоненти. |
| **Видалити через** | Ніколи | Введи час на кшталт `1m30s` або `45s` |
| **Вебхук** | Не налаштовано | Назва вебхука і необов'язковий URL аватара |
| **Привітати ботів** | вимкнено | Спрацьовувати також для акаунтів ботів |
| **Увімкнено** | увімкнено | Вимкнути одне привітання без його видалення |

Повідомлення про вихід, буст і привітальні ПП на цій сторінці немає. Налаштовуй їх командами вище.

## Покрокове налаштування

1. Відкрий **Привітання** на панелі керування і залиш **Тип привітання** на **Усі привітання**.
2. У розділі **Додати нове привітання** обери канал для вітань і натисни **Додати привітання**.
3. На новій картці відкрий **Повідомлення привітання**, створи своє повідомлення з наведеними вище заповнювачами і збережи.
4. За бажанням задай **Видалити через**, додай назву **Вебхука** та аватар, а також увімкни **Привітати ботів**, якщо хочеш оголошувати приєднання ботів.
5. Повтори для інших каналів. Перейди на **Випадкове привітання**, якщо додав кілька привітань в один канал і хочеш різноманіття.
6. Для повідомлення про вихід виконай `byemsg Goodbye %user%, we will miss you` у потрібному каналі, а потім `bye`, щоб його увімкнути.
7. Для повідомлення про буст виконай `boostmsg Thanks for boosting, %user%!`, а потім `boost`.
8. Перевір командами `byetest` і `boosttest`. У multi greets є попередній перегляд: виконай `multigreetmessage 1` і натисни **Попередній перегляд**.

## Команди

Виконуй ці команди з префіксом твого сервера (`.`, якщо ти його не змінював). Команди multi greet також доступні як `/multigreets add`, `/multigreets remove` і так далі.

| Команда | Псевдоніми | Потрібно | Призначення |
| --- | --- | --- | --- |
| `multigreetadd [#channel]` | `mgadd`, `mga` | Адміністратор | Додати привітання для каналу; за замовчуванням — поточний канал |
| `multigreetremove <number or #channel>` | `mgrem`, `mgrm`, `mgr` | Адміністратор | Видалити одне привітання за номером або всі привітання каналу після підтвердження |
| `multigreetmessage <number> [message]` | `mgmsg`, `mgm` | Адміністратор | Задати текст або embed привітання; без повідомлення пропонує попередній перегляд або сирий шаблон |
| `multigreetdelete <number> <time or seconds>` | `mgdel`, `mgd` | Адміністратор | Таймер самовидалення, наприклад `1m` або `60`; `0` вимикає |
| `multigreetdisable <number> <true or false>` | `mgdisable`, `mgdis` | Адміністратор | `true` вимикає привітання, `false` вмикає |
| `multigreetgreetbots <number> <true or false>` | `multigreetbots`, `mggb` | Адміністратор | Чи спрацьовує це привітання для ботів |
| `multigreetwebhook <number> [name] [avatar url]` | `mgwebhook`, `mghook`, `mgh` | Адміністратор | Створити webhook для привітання; без назви — видалити |
| `multigreettype <multigreet, randomgreet or off>` | `mgtype`, `mgt` | Адміністратор | Змінити тип привітання для всього сервера |
| `multigreetlist` | `mglist`, `mgl` | Адміністратор | Переглянути всі привітання з їхніми налаштуваннями посторінково |
| `bye` | | Керування сервером | Перемкнути повідомлення про вихід у цьому каналі |
| `byemsg [text]` | | Керування сервером | Показати або встановити повідомлення про вихід |
| `byedel [seconds]` | | Керування сервером | Таймер самовидалення повідомлення про вихід, за замовчуванням 30 |
| `byetest [@user]` | | Керування сервером | Надіслати повідомлення про вихід як тест |
| `leavehook [#channel] [name] [image url] [text]` | `byehook` | Керування сервером | Надсилати повідомлення про вихід через webhook, або `leavehook disable` |
| `boost` | | Керування сервером | Перемкнути повідомлення про буст у цьому каналі |
| `boostmsg [text]` | `boostmessage` | Керування сервером | Показати або встановити повідомлення про буст |
| `boostdel [seconds]` | `boostdelete` | Керування сервером | Таймер самовидалення буста, від 0 до 600, за замовчуванням 30 |
| `boosttest [@user]` | `testboost` | Керування сервером | Надіслати повідомлення про буст як тест |
| `greetdm` | | Керування сервером | Перемкнути привітальні ПП |
| `greetdmmsg [text]` | | Керування сервером | Показати або встановити текст привітальних ПП |
| `greetdmtest [@user]` | | Керування сервером | Надіслати привітальні ПП як тест |
| `greetdmoptout` | `gdmoptout` | Без вимог | Перестати отримувати привітальні ПП від цього бота будь-де |

## Поради та підводні камені

- `multigreetdelete` потребує, щоб у бота було право Керування повідомленнями, а `multigreetwebhook` і `leavehook` потребують права Керування webhook.
- Номери привітань — це позиції в списку, тож видалення одного зсуває номери всіх наступних. Перед редагуванням виконай `multigreetlist`.
- Варіант `off` у `multigreettype`, `/multigreets type` і кнопка **Вимкнено** на панелі керування встановлюють той самий тип привітання, тож будь-який із них вимикає систему без видалення твоїх привітань.
- Заповнювачі запрошень чекають до п'яти секунд, поки приєднання буде віднесено до запрошення, перш ніж надіслати привітання, тож той, хто запросив, визначається правильно, навіть коли приєднується кілька людей одночасно.
- Привітальна ПП працює лише тоді, коли учасник дозволяє ПП від учасників сервера. Невдалі ПП ігноруються.
- Привітання ролей — це окрема функція, яка спрацьовує, коли роль видається, а не під час приєднання.
