## Що це робить

Журналювання стежить за подіями, які Discord надсилає боту, і публікує короткий опис кожної з них у текстовому каналі, який ти обираєш. Видалене повідомлення показує, хто його написав і що в ньому було. Приєднання учасника показує вік його акаунта. Зміна ролі показує, які ролі додано або знято. Там, де бот може читати журнал аудиту, він також називає члена персоналу, який це зробив.

Кожен тип події має власне налаштування каналу, тож редагування повідомлень можна надсилати в один канал, дії модерації в інший, а решту вимкнути. Нічого не журналюється, доки ти не призначиш канал, а тип події з порожнім каналом тихо пропускається.

Канали також можна виключати. Ігнорований канал не дає жодних записів про повідомлення, гілки чи голосові події, що зберігає кімнати персоналу та канали для спаму ботів поза журналом.

## Навіщо це потрібно

- Зберігати копію видалених і відредагованих повідомлень, щоб модератори могли побачити, що було прибрано згодом.
- Відстежувати, хто приєднався і вийшов, включно з датами створення акаунтів, щоб помічати рейди та альтернативні акаунти.
- Фіксувати бани, розбани та заглушення разом із відповідальним модератором для підзвітності.
- Стежити за змінами ролей, каналів і прав, зробленими іншими адміністраторами або скомпрометованими акаунтами.
- Відстежувати активність у голосових каналах на серверах, де голосові канали є основним місцем спілкування.

## Типи подій журналу

Кожен тип може вказувати на інший канал або бути вимкненим. Це значення, які приймає `log` і які показано на панелі керування.

| Тип | Підпис на панелі | Записується, коли |
| --- | --- | --- |
| `MessageUpdated` | Повідомлення відредаговано | Редагується вміст повідомлення (повідомлення ботів і незмінений вміст пропускаються) |
| `MessageDeleted` | Повідомлення видалено | Повідомлення видаляється |
| `MessagesBulkDeleted` | Масове видалення повідомлень | Одразу очищується кілька повідомлень, із зазначенням кількості закешованих |
| `ReactionEvents` | Події реакцій | Реакції додаються або знімаються, групуються для кожного повідомлення раз на п'ять секунд |
| `ThreadCreated` | Гілку створено | Створюється гілка |
| `ThreadDeleted` | Гілку видалено | Гілку видаляється |
| `ThreadUpdated` | Гілку оновлено | Змінюється назва гілки, її статус архівування або подібне |
| `UsernameUpdated` | Ім'я користувача оновлено | Змінюється глобальне ім'я учасника |
| `NicknameUpdated` | Нік оновлено | Змінюється нік учасника на сервері |
| `UserUpdated` | Користувача оновлено | Змінюється профіль учасника, наприклад аватар або глобальне ім'я |
| `UserJoined` | Користувач приєднався | Учасник приєднується до сервера |
| `UserLeft` | Користувач вийшов | Учасник виходить або його вигнали |
| `UserRoleAdded` | Користувачу додано роль | Учаснику додається одна або кілька ролей |
| `UserRoleRemoved` | У користувача знято роль | У учасника забирається одна або кілька ролей |
| `UserBanned` | Користувача заблоковано | Учасника блокують |
| `UserUnbanned` | Користувача розблоковано | Блокування знімається |
| `UserMuted` | Користувача вимкнено | Учасника вимикають у голосовому або текстовому каналі |
| `VoicePresence` | Присутність у голосових | Учасник приєднується, виходить, переміщується, вимикає мікрофон або звук чи транслює в голосовому каналі |
| `VoicePresenceTts` | Присутність у голосових (TTS) | Учасник, імовірно, використав синтез мовлення в голосовому каналі; виявлення працює за можливостями |
| `ServerUpdated` | Сервер оновлено | Змінюються налаштування сервера, наприклад назва, значок або власник |
| `EventCreated` | Подію створено | Створюється запланована подія сервера |
| `InviteCreated` | Запрошення створено | Створюється запрошення із зазначенням максимального терміну дії та кількості використань |
| `InviteDeleted` | Запрошення видалено | Запрошення видаляється |
| `RoleCreated` | Роль створено | Створюється роль |
| `RoleDeleted` | Роль видалено | Роль видаляється |
| `RoleUpdated` | Роль оновлено | Змінюється назва, колір або дозволи ролі |
| `ChannelCreated` | Канал створено | Створюється канал |
| `ChannelDestroyed` | Канал видалено | Канал видаляється |
| `ChannelUpdated` | Канал оновлено | Змінюється назва, тема або дозволи каналу |
| `Other` | Інше | Різні події, які не охоплені вище |

На панелі керування також є запис **Аватар оновлено**. Він зберігається разом з іншими й задається категоріями Users і All, але це не значення, яке можна передати команді `log`.

## Категорії

`logcategory` задає цілу групу типів одним кроком для одного каналу. Якщо запустити її без каналу, усі типи цієї групи очищаються.

| Категорія | Типи, які вона задає |
| --- | --- |
| `All` | Кожен тип вище |
| `Users` | NicknameUpdated, AvatarUpdated, UsernameUpdated, UserRoleAdded, UserRoleRemoved, VoicePresence, UserJoined, UserLeft, UserUpdated |
| `Threads` | ThreadCreated, ThreadDeleted, ThreadUpdated |
| `Roles` | RoleCreated, RoleDeleted, RoleUpdated |
| `Server` | ServerUpdated, EventCreated, InviteCreated, InviteDeleted |
| `Channel` | ChannelCreated, ChannelDestroyed, ChannelUpdated |
| `Messages` | MessageDeleted, MessageUpdated, MessagesBulkDeleted, ReactionEvents |
| `Moderation` | UserMuted, UserBanned, UserUnbanned, Other |
| `None` | Очищає кожен тип (використовується кнопкою **Вимкнути все** на панелі керування) |

## Ігноровані канали

Будь-який канал зі списку ігнорування пропускається для подій повідомлень, гілок, каналів і голосових подій, які відбуваються в ньому. Гілки успадковують налаштування від батьківського каналу, тож ігнорування форуму або текстового каналу також ігнорує його гілки. Ігнорування голосового каналу пригнічує записи про присутність у голосових для входів до цього каналу і виходів із нього.

Ігнорування каналу не зупиняє події учасників, ролей або сервера, бо вони не прив'язані до каналу.

## Налаштування

На сторінці Журналювання є дві вкладки: **Канали журналу** та **Ігноровані канали**.

| Налаштування | Типове значення | Що контролює |
| --- | --- | --- |
| Канали журналу | немає | Окремий вибір каналу для кожного типу події, згруповано за категоріями Популярні, Користувачі, Повідомлення, Модерація, Сервер, Канали, Ролі, Гілки, Голосові та Усі події |
| Очистити категорію | | Очищає всі вибори в групі, яку ти переглядаєш; набуває чинності після натискання **Зберегти конфігурацію** |
| Очистити все | | Показується в групі **Усі події**; очищає всі вибори, застосовується після збереження |
| Вимкнути все | | Кнопка в заголовку, яка з'являється, поки задано будь-який канал; після підтвердження відв'язує кожен тип події одразу, зберігаючи ігноровані канали |
| Ігноровані канали | немає | Канали, виключені з журналювання, переміщуються між списками **Активні канали** та **Ігноровані канали** |

> [!TIP]
> До групи **Популярні** входять Користувач приєднався, Користувач вийшов, Повідомлення видалено, Повідомлення відредаговано, Користувача заблоковано, Користувача розблоковано, Канал створено і Канал видалено. Це хороший початковий набір для більшості серверів.

## Покроковий приклад налаштування

1. Створи один або кілька приватних каналів журналу, які можуть читати лише члени персоналу.
2. Відкрий **Журналювання** на панелі керування і залишись на вкладці **Канали журналу**.
3. У групі **Популярні** обери канал журналу для кожної потрібної події і збережи.
4. Перейди до інших груп, наприклад **Модерація** або **Голосові**, і призач канали для всього іншого, що тобі потрібно.
5. Відкрий вкладку **Ігноровані канали** і перенеси кімнати персоналу та канали команд бота до списку ігнорованих.
6. Видали тестове повідомлення і переконайся, що запис з'явився в потрібному каналі.

## Команди

Виконуй їх із префіксом свого сервера (`.`, якщо ти його не змінював). Slash-версії розташовані під `/log`.

| Команда | Аліаси | Потрібно | Призначення |
| --- | --- | --- | --- |
| `log <type> [#channel]` | | Адміністратор | Надсилати один тип події в канал; без каналу використовується поточний канал |
| `log #channel [types...]` | | Адміністратор | Надсилати кілька типів в один канал або відкрити меню вибору всіх типів, якщо типи не вказано |
| `log "#channel:Type1,Type2" ...` | | Адміністратор | Задати кілька пар каналу і типів в одному повідомленні |
| `logcategory <category> [#channel]` | `logcat` | Адміністратор | Призначити цілу категорію каналу або очистити її без каналу |
| `logevents` | | Адміністратор | Перелічити кожен тип події та канал, який він зараз використовує |
| `logignore [#channel]` | `lignore` | Адміністратор | Перемкнути канал у списку ігнорування; за замовчуванням поточний канал |
| `logignorelist` | `lignorel` | Адміністратор | Показати список ігнорування |
| `commandlogchannel [#channel]` | `commandlog`, `logcommands` | Адміністратор | Журналювати використання команд бота в канал або вимкнути без каналу |

> [!EXAMPLE]
> `log "#mod-logs:UserBanned,UserUnbanned,UserMuted" "#message-logs:MessageDeleted,MessageUpdated"`

## Поради та підводні камені

- Надай боту **Перегляд журналу аудиту**. Без нього журнали все одно публікуються, але не можуть сказати, який модератор видалив повідомлення, заблокував когось або змінив роль.
- Боту потрібно бачити та надсилати повідомлення в кожному каналі журналу. Канал журналу, який бот не бачить, пропускається без помилки.
- Журнали видалених і відредагованих повідомлень залежать від кешу повідомлень бота. Повідомлення, надіслані до останнього перезапуску бота, або ті, що видалено масово, можуть показуватися як незакешовані.
- Журнали реакцій згруповані: усі зміни реакцій на одному повідомленні протягом приблизно п'яти секунд надходять одним записом, щоб не засмічувати активні сервери.
- Меню вибору, яке відкриває `log #channel`, показує до 25 типів на меню і попередньо вибирає ті, що вже надсилаються в цей канал.
- `logcategory` перезаписує кожен тип у категорії, включно з тими, які ти направив в інші канали. Використовуй `log` для окремих типів після цього.
