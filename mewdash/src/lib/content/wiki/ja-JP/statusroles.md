## 概要

スタッフは、監視するテキストを1つ以上追加します。例としては、`discord.gg/yourserver` や `playing minecraft` などがあります。ボットはプレゼンスの更新を監視します。メンバーのカスタムステータスに監視するテキストが含まれるようになると、ボットは **削除するロール** に設定されたロールを取り外し、**付与するロール** に設定されたロールを付与します。チャンネルとメッセージが設定されている場合は、そのチャンネルに通知も投稿します。

ステータスから再びテキストが消えたときの動作は、2つの切り替え設定で決まります。**追加したロールを削除** をオンにすると、付与されていたロールが取り外されます。**削除したロールを再付与** をオンにすると、取り外されていたロールが戻されます。どちらも既定ではオフなので、何も変更しなければ、メンバーは最終的に持っていたロールをそのまま保持します。

確認されるのは、Discordの「カスタムステータスを設定」で入力したカスタムステータスだけです。ゲーム、Spotify、配信のアクティビティは無視されます。オフラインや非表示のメンバーはスキップされます。一致の判定は単純な部分文字列の比較で、`mewdeko` は `I love mewdeko` に一致しますが、大文字と小文字は区別されます。

サーバーには、ステータスロールのエントリを任意の数だけ登録できます。各エントリには、それぞれ独自のロール、チャンネル、メッセージを設定できます。コマンドでは、`liststatusroles` で表示される番号（インデックス）でエントリを指定します。

## 使いどころ

- サーバーの招待リンクをステータスに入れてくれたメンバーに、サポーター用のロールと特典を与えます。
- 誰かがステータスで「配信中」や「一緒に遊ぼう」と宣伝しているあいだだけ、そのロールを付与し、やめたら削除します。
- メンバーがサーバーの宣伝をし始めたら、チャンネルでお知らせして、スタッフがお礼を伝えられるようにします。
- ステータスが有効なあいだに、あるロールを別のロールに入れ替えます。例えば、特定のステータスを表示している間は、「メンションなし」ロールを外すといった使い方ができます。

## 一致の判定とロールの変更

| 状況 | ボットの動作 |
| --- | --- |
| ステータスに監視テキストが追加された | **削除するロール** を取り外し、**付与するロール** を付与します。設定されていれば通知を送信します |
| ステータスに監視テキストが残っている | 何もしません。変更は一度だけ処理されます |
| ステータスから監視テキストが消えた（**追加したロールを削除** がオン） | 付与した **付与するロール** のうち、メンバーがまだ持っているものを取り外します |
| ステータスから監視テキストが消えた（**削除したロールを再付与** がオン） | 取り外した **削除するロール** のうち、メンバーがもう持っていないものを付与します |
| メンバーがオフラインまたは非表示になった | 何もしません。ロールはそのままです |

ボットは、各プレゼンスの更新を、そのユーザーについてキャッシュされている前回のステータスと比較します。そのため、ステータスの無関係な部分を編集しても、再度処理されることはありません。監視テキストは、サーバーごとに一意である必要があります。コマンドでは128文字の上限がありますが、ダッシュボードには上限がありません。

## 通知メッセージ

エントリに **通知チャンネル** と **通知メッセージ** の両方が設定されている場合、メンバーのステータスが一致するたびに、ボットはそのチャンネルにメッセージを投稿します。テキストは埋め込みパーサーで処理されるため、埋め込みビルダーで作成できるものはすべて使えます。プレーンテキスト、最大10個の埋め込み、コンポーネントを含みます。ステータスが一致しなくなったときは、何も投稿されません。

### プレースホルダー

メッセージは、メンバー、通知チャンネル、サーバーに対する標準の置き換えセットで処理されます。よく使われるものを以下に示します。全一覧は、ユーザー、サーバー、チャンネル、ボット、時刻のプレースホルダーのページにあります。

| プレースホルダー | 値 |
| --- | --- |
| `%user.mention%` | メンバーへのメンション |
| `%user.name%` | メンバーのユーザー名 |
| `%user.fullname%` | 識別子付きのユーザー名 |
| `%user.avatar%` | メンバーのアバターのURL |
| `%user.id%` | メンバーのユーザーID |
| `%server.name%` | サーバー名 |
| `%server.icon%` | サーバーアイコンのURL |
| `%channel.mention%` | 通知チャンネルへのメンション |
| `%server.time%` | サーバーで設定されたタイムゾーンの現在時刻 |

> [!NOTE]
> ダッシュボードのエディターには `%status%` プレースホルダーが表示されますが、ボットはこれを置き換えません。ステータスのテキストは、自分でメッセージに入力してください。

> [!EXAMPLE]
> `%user.mention% is now repping the server in their status, thank you!`

## 設定

すべての設定は、ステータスロールのページにあります。このページには **ステータスロール**、**新規追加**、**統計** の3つのタブがあります。一覧の各エントリを展開すると、その設定が表示されます。

| 設定 | 既定値 | 制御する内容 |
| --- | --- | --- |
| 監視するステータステキスト | なし | カスタムステータスに含まれている必要があるテキスト。ダッシュボードでは長さの制限はなく、コマンドでは128文字まで |
| 付与するロール | なし | ステータスが一致したときに付与される、スペースで区切られたロールID。保存すると、リスト全体が置き換えられます |
| 削除するロール | なし | ステータスが一致したときに取り外される、スペースで区切られたロールID。保存すると、リスト全体が置き換えられます |
| 通知チャンネル | なし | 通知メッセージを受け取るチャンネル |
| 通知メッセージ | なし | プレースホルダーを含む、チャンネルに送信されるテキストまたは埋め込み |
| 追加したロールを削除 | オフ | ステータスが一致しなくなったときに、付与したロールを取り外します |
| 削除したロールを再付与 | オフ | ステータスが一致しなくなったときに、取り外したロールを戻します |

**統計** タブには、エントリの総数、ロールを変更するエントリの数、通知チャンネルを設定しているエントリの数が表示されます。

## セットアップの手順

1. ダッシュボードで **ステータスロール** を開き、**新規追加** タブに移動します。
2. 監視するテキストを入力し、**ステータスロールを追加** を押します。
3. **ステータスロール** タブに戻り、新しいエントリを展開します。
4. **設定を編集** を押し、**付与するロール** と **削除するロール** にロールIDを貼り付けます。必要であれば **通知チャンネル** を選び、**通知メッセージ** を書いてから **保存** を押します。
5. エントリにある2つの切り替えボタンで、**追加したロールを削除** をオンにし、必要であれば **削除したロールを再付与** もオンにします。
6. 動作を確認します。自分のカスタムステータスを監視テキストに設定してロールが付与されることを確かめ、そのあとステータスを消してロールが削除されることを確かめます。

## コマンド

サーバーのプレフィックスを付けて実行します（変更していなければ `.`）。すべてのコマンドにはサーバーの管理の権限が必要です。`<index>` は `liststatusroles` で表示される番号で、1から始まります。スラッシュコマンド版は `/statusroles` にあります。

| コマンド | エイリアス | 必要な権限 | 用途 |
| --- | --- | --- | --- |
| `addstatusrole <text>` | `asr` | サーバーの管理 | 監視するステータステキストを追加します |
| `removestatusrole <index>` | `rsr` | サーバーの管理 | エントリを削除します |
| `liststatusroles` | `lsr` | サーバーの管理 | すべてのエントリを、番号と設定とともにページ送りで表示します |
| `setaddroles <index> <@role...>` | `sar` | サーバーの管理 | ステータスが一致したときに付与するロールのリストにロールを追加します |
| `setremoveroles <index> <@role...>` | `srr` | サーバーの管理 | ステータスが一致したときに取り外すロールのリストにロールを追加します |
| `removeaddroles <index> <@role...>` | `remar` | サーバーの管理 | 「付与するロール」のリストからロールを取り除きます |
| `removeremoveroles <index> <@role...>` | `rmremoveroles` | サーバーの管理 | 「削除するロール」のリストからロールを取り除きます |
| `setstatusrolechannel <index> <#channel>` | `statusrolechannel`, `ssrc` | サーバーの管理 | 通知チャンネルを設定します |
| `setstatusroleembed <index> [text]` | `statusroleembed`, `asre` | サーバーの管理 | 通知メッセージを設定します。テキストを省略すると、現在のメッセージを表示します |
| `toggleremoveadded <index>` | `togglerma` | サーバーの管理 | **追加したロールを削除** を切り替えます |
| `togglereaddremoved <index>` | `togglermrm` | サーバーの管理 | **削除したロールを再付与** を切り替えます |

`setaddroles` と `setremoveroles` は、既存のリストを置き換えるのではなく、末尾に追加します。ロールを取り除くには、`remove...` のコマンドを使ってください。ダッシュボードのエディターは逆の動作をします。保存時に入力欄にあるものが、リスト全体になります。ただし、空の入力欄は無視されるため、リストを完全に空にするには `remove...` のコマンドを使う必要があります。

## ヒントと注意点

- ボットには、ロールの管理の権限が必要です。また、ボットの最上位のロールが、付与または削除するすべてのロールより上にある必要があります。失敗はログに記録されるだけで、メンバーには何も表示されません。
- ボットがカスタムステータスを確認するには、プレゼンスインテントが有効になっている必要があります。ステータスを変更しても何も起こらない場合は、最初にこれを確認してください。
- 一致の判定は大文字と小文字を区別し、ステータステキストのどこにあっても一致します。監視テキストは短く、特徴的なものにしてください。
- ボットは、メンバーのプレゼンスの最初のアクティビティだけを確認します。通常、Discordではカスタムステータスが最初に表示されますが、ほかのアクティビティが先に報告されていると、そのステータスは確認されません。
- ロールは、ステータスが変わったときにだけ変更されます。エントリを作成した時点ですでにステータスに監視テキストが含まれているメンバーは、ステータスが変わるまで処理されません。
- 通知は、ステータスが一致するようになるたびに送信されます。そのため、ステータスを何度も切り替えるメンバーがいると、メッセージも何度も送信されます。
- ダッシュボードでは、ロールの名前ではなくロールIDを入力します。Discordで開発者モードを有効にし、ロールを右クリックしてIDをコピーしてください。
