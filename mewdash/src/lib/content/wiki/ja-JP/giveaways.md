## 概要

スタッフは、景品、チャンネル、当選者数、期間を指定してプレゼント企画を開始します。Botは、そのチャンネルに景品、主催者、終了時刻、条件を示す埋め込みを投稿します。メンバーは、プレゼント企画の開始方法に応じて、サーバーのプレゼント企画用の絵文字でリアクションするか、**Enter** ボタンを押すか、ダッシュボードでキャプチャを解くことで参加します。

タイマーが切れると、Botは参加者の中から、条件を満たしている人をランダムに選んで当選者を決めます。元のメッセージを編集して当選者を表示し、チャンネルにお祝いのメッセージを投稿します。有効にしている場合は、各当選者にプレゼント企画へのリンクをDMで送ります。スタッフは、プレゼント企画を終了前に締め切ることも、終了後に再抽選することもできます。

条件は参加時ではなく、終了時に確認されます。リアクションした後に必要なロールを失った人は、当選者を選ぶときにスキップされます。

## 使う理由

- 名前を手作業で選ばずに、ゲームのキー、Nitro、グッズを活発なメンバーにプレゼントする。
- 最低メッセージ数を条件にして、実際に発言している人を優遇する。
- 必要なロールを設定して、ブースターやサポーターのロールを持つ人だけに景品を限定する。
- キャプチャによる参加を使い、代替アカウントやBotによる大量の参加を防ぐ。

## 参加方法

各プレゼント企画は、これらのいずれか1つを使います。対話型の `gstart` ウィザードでどれを使うかを尋ねられ、スラッシュコマンドには `use_button` と `use_captcha` のオプションがあり、ダッシュボードには **参加方法** の選択肢があります。

| 方法 | メンバーの参加方法 | 補足 |
| --- | --- | --- |
| リアクション | サーバーのプレゼント企画用の絵文字でリアクション | 初期値です。プレゼント企画が終了すると、Botはリアクションのリストを読み取ります(最大1000ユーザー)。 |
| ボタン | 埋め込みの下にある **Enter** ボタンを押す | 参加はBotが保存します。2回参加する場合、終了後に参加する場合、またはサーバーにいない場合は拒否されます。 |
| キャプチャ | **Enter (Web Captcha)** を押し、ダッシュボードにサインインして、Cloudflare Turnstile の確認を通過する | ボタンによる参加と同じ方法で保存されます。参加は、サインインしたDiscordアカウントに記録されます。 |

プレゼント企画の絵文字は、`gemote` でサーバーごとに設定します。Botは、その絵文字でリアクションして検証するため、別のサーバーのカスタム絵文字は、Botがそのサーバーにもいる場合にのみ使えます。リアクションのプレゼント企画には、Botのリアクションの追加と外部の絵文字の使用の権限も必要で、`gstart` はこれらがないと開始を拒否します。

## 条件

| 条件 | 設定方法 | 抽選時の効果 |
| --- | --- | --- |
| 必要なロール | ウィザード、スラッシュの `required_roles`、ダッシュボードの **必要なロール** | メンバーは、指定したすべてのロールを持っている必要があります |
| メッセージ数 | ウィザード、スラッシュの `required_messages`、ダッシュボードの **必要なメッセージ数** | このサーバーでのメンバーのカウント済みメッセージ数が、この数以上である必要があります。メッセージ数の集計サービスを使うため、その機能が有効になってからのメッセージしか対象になりません。 |

Botは常に除外され、サーバーを退出した人も除外されます。条件は、プレゼント企画の埋め込みに **必要なロール** の行と、「N Messages Required」の行として表示されます。

## プレゼント企画のメッセージ

埋め込みのタイトルは景品です。説明文には「(絵文字)でリアクションして参加!」と表示され、主催者の名前と、相対時刻と絶対時刻のDiscordタイムスタンプで終了時刻が表示されます。フッターには当選者数、サーバー名、終了日が表示されます。メッセージの本文には、設定されている場合は通知するロールのメンションが入ります。

サーバー全体の見た目の設定:

| 設定 | コマンド | 効果 |
| --- | --- | --- |
| 埋め込みの色 | `gembedcolor` | プレゼント企画の埋め込みの色。色名または `#hex` で指定 |
| バナー | `gbanner` | すべてのプレゼント企画に表示される画像。ウィザードとスラッシュコマンドでは、URLまたは添付ファイルでプレゼント企画ごとに上書きできます。 |
| 通知ロール | なし。ウィザードでのみ上書き可能 | ウィザードでロールに通知するかを選べます。サーバーの通知ロールが保存されている場合は、上書きするかを尋ねられます |
| 当選者にDM | `gdm` | 当選者にDMを送るかどうか。初期値はオンです。 |

### 終了時

参加できる人が十分いる場合、Botは埋め込みを編集して「Winner: @user」と主催者を表示し、フッターを「Ended at (time)」に設定し、本文を「**Giveaway Ended!**」に変更します。さらに、プレゼント企画へのリンクと再抽選のコマンドを示す、お祝いのメッセージを別途投稿します。誰も参加しなかった場合、または参加者が当選者数より少ない場合は、埋め込みが「There were not enough participants!」に置き換えられ、プレゼント企画は終了としてマークされます。参加者はいたものの、誰も条件を満たさなかった場合は、その旨が表示されます。

当選者が1人のプレゼント企画は、チャットトリガー用の `GiveawayWon` イベントも発火させるため、トリガーで当選に反応させることもできます。

### 当選者へのDM

**DM winners** をオンにすると、各当選者にDMが送られます。初期値は、当選したことを伝える埋め込みで、プレゼント企画のメッセージへのリンクが付きます。カスタムの終了メッセージが保存されている場合は、代わりにそれが送られます。この場合、一般的なサーバー、ユーザー、チャンネルのプレースホルダーに加えて、次のプレースホルダーを使えます。

| プレースホルダー | 値 |
| --- | --- |
| `%messagelink%` | プレゼント企画のメッセージへのリンク |
| `%giveawayitem%` | 景品 |
| `%giveawaywinners%` | 当選者数 |

テキストを指定せずに `gdmmessage` を実行すると、保存されているメッセージをサンプルの値でプレビューするかを尋ねられ、プレビューを断ると消去されます。テキストを指定して実行した場合も、保存はされず、保存されているメッセージは消去されます。

## 設定

**プレゼント企画** のダッシュボードページには、**進行中のプレゼント企画**、**ギブアウェイを作成**、**終了したギブアウェイ** の3つのタブがあります。上記のサーバー全体の設定(絵文字、色、バナー、DMのトグル)はコマンドでのみ変更できます。

**ギブアウェイを作成** フォーム:

| 設定 | 初期値 | 内容 |
| --- | --- | --- |
| Giveaway Item | 空 | 景品。埋め込みのタイトルとして表示 |
| Number of Winners | 1 | 抽選する当選者数。1以上である必要があります |
| Channel | なし | 埋め込みを投稿する場所 |
| Duration | 24 hours | プレゼント企画が終了する時刻 |
| Required Roles | なし | 当選するためにメンバーが持っている必要のあるロール |
| Required Message Count | 0 | カウント対象のメッセージの最低数 |
| Reaction Emoji | クラッカー | リアクション参加用の絵文字。カスタム絵文字や貼り付けた絵文字のコードも使えます |
| Entry Method | Reaction | Reaction、Button、または Captcha |

**進行中のプレゼント企画** には、各プレゼント企画と終了時刻が表示されます。1つを展開すると、当選者、チャンネル、必要なロール、メッセージ条件、参加方法が表示され、**End Giveaway** ボタンもあります。再抽選はコマンドでのみ可能です。

## セットアップの手順

1. `gemote` を使い、メンバーがリアクションする絵文字を設定します。例: `gemote :tada:`。
2. 任意で `gembedcolor` と `gbanner` を設定し、プレゼント企画をサーバーの雰囲気に合わせます。
3. ダッシュボードで **プレゼント企画** を開き、**ギブアウェイを作成** を選びます。
4. **ギブアウェイの景品**、**当選者数**、**チャンネル**、**期間** を入力します。
5. 景品を長く在籍しているメンバーに渡したい場合は、**必要なロール** または **必要なメッセージ数** を追加します。
6. **参加方法** を選び、**ギブアウェイを作成** を押します。
7. 終了したら、チャンネルを確認します。不適切な人が当選した場合、または当選者が反応しない場合は、`greroll <message id>` を実行します。

## コマンド

これらのコマンドは、サーバーのプレフィックス(変更していなければ `.`)を付けて実行します。同じコマンドは、`/giveaways` の下にスラッシュコマンドとしてもあります。

| コマンド | エイリアス | 必要な権限 | 目的 |
| --- | --- | --- | --- |
| `gstart [#channel <time> <winners> <prize>]` | `giveawaystart` | メッセージの管理 | プレゼント企画を開始。引数なしの場合はウィザードが起動し、主催者、メッセージ条件、バナー、通知ロール、参加方法、必要なロールも尋ねます。時間は `2d3h` のように指定します。 |
| `gend <message id>` | `giveawayend` | メッセージの管理 | プレゼント企画を今すぐ終了し、当選者を抽選 |
| `greroll <message id>` | `giveawayreroll`, `reroll` | メッセージの管理 | 終了したプレゼント企画の参加者から、もう一度抽選 |
| `glist` | `giveaways`, `giveawaylist` | メッセージの管理 | 実施中のプレゼント企画を、メッセージID、景品、当選者数、リンクとともに一覧表示 |
| `gstats` | `giveawaystats` | なし | 実施中と終了したプレゼント企画の合計、主催者、チャンネルごとの数 |
| `gemote <emote>` | `giveawayemote` | メッセージの管理 | リアクション参加用の絵文字を設定 |
| `gembedcolor <colour>` | `giveawayembedcolor` | メッセージの管理 | プレゼント企画の埋め込みの色を設定 |
| `gwinembedcolor <colour>` | `giveawaywinembedcolor` | メッセージの管理 | `gembedcolor` と同じ色の値を設定 |
| `gbanner <url>` | `giveawaybanner` | メッセージの管理 | 既定のバナー画像を設定 |
| `gdm` | `giveawaydm` | メッセージの管理 | 当選者へのDMを切り替え |
| `gdmmessage [text]` | `gdmmsg` | メッセージの管理 | カスタムの当選者DMをプレビューまたは消去 |

## ヒントと注意点

- `gend` と `greroll` で使うメッセージIDは、プレゼント企画の埋め込みのIDです。開発者モードでコピーするか、`glist` から確認してください。
- 再抽選は、同じ条件で参加者から改めて選ばれるため、前回の当選者が再び当選することもあります。
- Botは再起動後、次の24時間以内に終了するプレゼント企画をすぐにスケジュールします。それ以降に終了するものは1時間ごとのチェックで拾われるため、長い期間のプレゼント企画も時間どおりに終了します。
- リアクションのプレゼント企画で、Botがリアクションを読み取れない場合は、現在のサーバーの絵文字にフォールバックします。ただし、絵文字が誰もリアクションしていないものに変更された場合、抽選では参加者が見つかりません。
- ダッシュボードの **進行中のプレゼント企画** の一覧には、終了したプレゼント企画も表示されます。現在 **終了したギブアウェイ** タブは空です。終了時刻と **End Giveaway** ボタンがないことで、両者を区別してください。
- キャプチャによる参加には、ダッシュボードにアクセスできることと、メンバーがDiscordでサインインすることが必要です。参加はそのアカウントに紐づけられ、ページに入力した内容とは関係ありません。
- 当選者がDMを受け付けていない場合、当選者へのDMは失敗しますが、エラーは表示されません。チャンネルでの発表は引き続き行われます。
