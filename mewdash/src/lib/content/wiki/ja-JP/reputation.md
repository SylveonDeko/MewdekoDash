## 概要

メンバーは `rep @user` を実行して、理由を添えることもできますが、1ポイントのレピュテーションを与えます。受け取ったユーザーの合計は増え、与えたユーザーの連続日数が記録され、履歴には誰が何をなぜ与えたかが残ります。誰でも `repcheck` で合計を確認でき、`repleaderboard` でサーバーのランキングを見られ、`rephistory` で直近10件の記録を読めます。

スタッフは、レピュテーションの流れを細かく設定できます。与える人と受け取る人のペアごとのクールダウン、1日と1週間の上限、そして与えることができるようになるための最低アカウント年数、サーバー参加期間、メッセージ数を設定できます。チャンネルはレピュテーションを無効にしたり、倍率を設定したりできます。また、リアクションからもレピュテーションを獲得できます。メッセージに設定された絵文字が付くと、その投稿者にポイントが与えられます。

設定されたしきい値に達すると、ボットはロールを付与し、そのチャンネルでマイルストーンを告知し、メンバーにDMを送ります。任意の減衰機能を有効にすると、しばらく与えも受けもしていないメンバーのポイントが少しずつ減り、リーダーボードが現在の活動を反映するようになります。

## 利用するメリット

- サポートチャンネルで役に立つメンバーを認め、目に見えるロールを与えます。
- ショーケースチャンネルでサムズアップのリアクションを付けると、作者にポイントが与えられるようにします。
- 手動でロールを付けるのではなく、レピュテーションのレベルでコマンドやチャンネルへのアクセスを制限します。
- 週末のイベントとして、あるチャンネルでのレピュテーションを2倍にします。
- 手伝わなくなった人に減衰を適用して、サポートのリーダーボードを正確に保ちます。

## レピュテーションを与える

`rep` を1回実行すると、チャンネルの倍率が設定されている場合はその倍率を掛けた1ポイントが与えられます。自分自身やボットに与えることはできません。すべての試行は、以下の順番で確認され、最初に失敗した確認の内容が与えたユーザーに通知されます。

| 確認項目 | デフォルト | 内容 |
| --- | --- | --- |
| システムの有効化 | オン | オフの間は、すべての操作が拒否されます。 |
| チャンネルの状態 | enabled | `disabled` に設定されたチャンネルでは、そこで与えたレピュテーションが拒否されます。 |
| 受け取る側の凍結 | なし | 凍結されたメンバーは、レピュテーションを受け取れません。 |
| クールダウン | 60分 | 同じユーザーが同じ相手に再度与えられるまでの時間 |
| 1日の上限 | 10 | 1回のUTC日に、ユーザーが与えられるレピュテーションの数 |
| 1週間の上限 | なし | 日曜日から数える、週ごとの任意の上限 |
| 最低アカウント年数 | 7日 | 与える側のDiscordアカウントの年数 |
| 最低サーバー参加期間 | 24時間 | 与える側がサーバーに参加している期間 |
| 最低メッセージ数 | 10 | 与える側が送信したメッセージ数（メッセージカウントによる） |

匿名のレピュテーションは、記録上は匿名として残りますが、設定で匿名の付与が有効になっている場合に限ります。マイナスのレピュテーションは別の設定です。リアクションの削除では、そのリアクションで与えたポイントが取り消されます。

### 連続記録と統計

連続する日にレピュテーションを与えると、連続記録が積み上がります。1日半を超える空白があると、連続記録はリセットされます。`repstats` は、合計、順位、与えた数、受け取った数、現在の連続記録、最長の連続記録、そして最後に与えた日時と受け取った日時を表示します。

### カスタムの種類

`reptypeadd helpful Helpful` は、名前付きの種類を作成します。その後、メンバーは `rep @user helpful thanks for the fix` のように実行できます。標準のレピュテーションは合計にのみ加算されます。カスタムの種類は、その種類ごとの個別のカウントも保持し、コマンドの要件でそのカウントを指定できます。

## リアクション

`repreaction <emoji> [amount] [type]` を実行すると、リアクションによってメッセージの作者にレピュテーションが与えられます。リアクションを付けたユーザーはボットであってはならず、リアクションを削除するとポイントは取り消されます。このコマンドのデフォルトは、標準のレピュテーション1ポイントです。各リアクションの設定には、それぞれ独自のクールダウンがあります。

## ロール報酬

`reprole @Role 100` は、メンバーのレピュテーションが100に達したときにロールを付与します。オプションとして、レピュテーションがしきい値を下回ったときにロールを削除するか（デフォルトでオン）、チャンネルでマイルストーンを告知するか、DMを送信するかを選べます。報酬は、レピュテーションが変わるたびに確認されます。報酬に設定したボーナスXPは保存されますが、まだ支払われません。

ロール報酬とは別に、メンバーが50、100、250、500、1000、2500、5000、または10000のレピュテーションを超えると、ボットは **通知チャンネル** にマイルストーンのメッセージを投稿します。また、一度に10ポイント以上受け取った場合、または10の倍数に達した場合にも、メンバーにDMが送られます。

## 減衰

有効にすると、ボットは1時間ごとに減衰の時刻かどうかを確認します。`daily` は毎日UTC 02:00に、`weekly` は毎週日曜日のUTC 02:00に、`monthly` は毎月1日に実行されます。与えも受けもしていない期間が非アクティブ期間を超えたメンバーは、減衰量を失います。減衰量は固定のポイント数か、合計に対する割合のどちらかで、0未満にはなりません。凍結されたメンバーはスキップされます。デフォルトは毎週、1ポイント、非アクティブ期間30日です。

## コマンドの要件

`repcommandreq <command> <minimum> [type] [#channels]` は、メンバーが必要な量のレピュテーションを持つまで、コマンドをブロックします。必要に応じて、特定のカスタムの種類に限定したり、特定のチャンネルでのみ適用したりできます。`repcommandbypass` は、指定したロールを免除します。`repcommandinfo` を使うと、誰でもコマンドに必要な条件を確認できます。

## 設定

レピュテーションのページには4つのタブがあります。**設定**、**ロール報酬**、**ランキング**、**統計** です。

| 設定 | デフォルト | 内容 |
| --- | --- | --- |
| Enable Reputation System | オン | メインのスイッチ |
| Cooldown (minutes) | 60 | ペアごと（与える人と受け取る人） |
| Daily Limit | 10 | 与える人ごとの1日あたりのレピュテーション |
| Weekly Limit (optional) | なし | 与える人ごとの1週間あたりのレピュテーション |
| Min Account Age (days) | 7 | 与える側の条件 |
| Min Server Time (hours) | 24 | 与える側の条件 |
| Min Message Count | 10 | 与える側の条件 |
| Notification Channel (optional) | なし | マイルストーンのメッセージを投稿する場所 |
| Allow Negative Reputation | オフ | マイナスの値を有効にします。 |
| Enable Anonymous Reputation | オフ | `repanon` で与える人を隠せるようにします。 |

減衰はダッシュボードにはありません。下記の `repdecay*` コマンドを使ってください。

**ロール報酬** には、**ロール**、**必要なレピュテーション**、**お知らせチャンネル（任意）**、**ボーナス XP（任意）**、**レピュテーションが基準値を下回ったらロールを削除する**、**DM で通知を送信** のフォームがあります。**ランキング** にはランキングが表示され、メンバーの履歴を開くことができます。**統計** には、総ユーザー数、与えられたレピュテーションの合計、取引数、平均レピュテーションが表示されます。

## セットアップの流れ

1. ダッシュボードで **評判** を開きます。**設定** で **有効** をオンにします。
2. **クールダウン**、**Daily Limit**、3つの最低条件を、サーバーの規模に合わせて設定します。
3. マイルストーン用の **Notification channel** を選んで保存します。
4. **ロール報酬** で、ロールと **必要なレピュテーション** を追加します。継続的に獲得させたい場合は、**レピュテーションが基準値を下回ったらロールを削除する** にチェックを入れます。
5. Discordで `repreaction <emoji> 1` を実行してリアクションによるレピュテーションを有効にし、`repchannel #bot-spam disabled` を実行してスパムのチャンネルを除外します。
6. 別のアカウントでテストします。`rep @you great help` を実行した後、`repcheck @you` を実行します。

> [!WARNING]
> `represet all` は、確認後にサーバー内のすべてのメンバーのレピュテーション、履歴、バッジを消去します。元に戻すことはできません。

## ヒントと注意点

- ロール報酬には、ボットのロールがすべての報酬ロールより上にあり、「ロールの管理」権限が必要です。`reprole` は、ボットより上のロールを拒否します。
- 最低メッセージ数は、メッセージカウント機能を使用します。カウントが無効な場合、メンバーの数が0と判定され、レピュテーションを与えられなくなることがあります。
- 与えることをブロックするのは `disabled` のチャンネル状態のみです。`readonly` はコマンドで受け付けられますが、現時点ではそのチャンネルでのレピュテーションを止めません。
- `repeventcreate` で作成されたイベントには、倍率と終了時刻が保存されますが、現時点ではイベント中に与えられたレピュテーションに倍率は適用されません。
- リアクションによるレピュテーションは、標準の絵文字では絵文字の名前を、カスタム絵文字ではそのIDを使います。そのため、他のサーバーのカスタム絵文字は、削除された後は一致しなくなります。
- 減衰の確認は毎時0分に実行されるため、`daily` の減衰は02:00 UTCの時間帯に1回だけ行われます。
- クールダウンはペアごとに適用されます。1人のメンバーは、1日の上限までであれば、異なる複数の人に連続してレピュテーションを与えられます。
