## 概要

スタッフは配信のURLを貼り付け、Discordのチャンネルを選びます。するとボットは、その配信者のプラットフォームを定期的に確認し、配信がオフラインからオンラインに切り替わったときに、選んだチャンネルへ配信開始のメッセージを投稿します。デフォルトでは、配信者の名前が配信へのリンクになった埋め込みが投稿されます。埋め込みには、配信のタイトル、ゲームまたはカテゴリ、視聴者数、配信者のアバター、プレビュー画像が含まれます。

デフォルトの埋め込みは、独自のメッセージに置き換えられます。フォローしているすべての配信に適用されるサーバー全体のテンプレートがあるほか、配信ごとに個別の配信開始メッセージと配信終了メッセージを設定することもできます。これらはすべて、以下の `%stream.*%` プレースホルダーに対応しており、プレーンテキストでも、ダッシュボードの埋め込みエディターで作成した完全な埋め込みでも使えます。

配信終了の通知は、デフォルトでオフになっています。オンにすると、フォローしている配信が終了したときにもボットが投稿します。その際、配信に個別の終了メッセージがあればそれを使い、なければサーバーのテンプレート、それもなければ「Offline」を表示するデフォルトの埋め込みを使います。

> [!NOTE]
> 配信通知は、他の人の配信をDiscordに告知するものです。別機能の Twitch Bot は、ボットを自分のTwitchチャットに接続し、コマンド、タイマー、イベントを扱います。それについては Twitch Bot の記事を参照してください。

## 利用するメリット

- コミュニティサーバーで、配信者が配信を開始するたびに点灯する「今すぐライブ」のチャンネルが欲しい場合。
- 配信者本人のDiscordで、タイトルとカテゴリ付きの自動通知を出し、誰も手作業で投稿しなくてもよいようにしたい場合。
- イベントやeスポーツのサーバーで、TwitchとKickにまたがる複数の大会チャンネルを1か所でフォローしたい場合。
- 配信のお知らせが古く見えないように、サーバーが「配信終了」の通知を明確に出したい場合。

## 対応プラットフォーム

ボットは、指定したURLからプラットフォームを判断します。以下のパターンに一致するURLのみフォローできます。

| プラットフォーム | URLの形式 | 備考 |
| --- | --- | --- |
| Twitch | `twitch.tv/username` | Twitch Helix APIを使用します。タイトル、ゲーム、視聴者数、アバター、プレビューがすべて入力されます。 |
| YouTube | `youtube.com/@handle` または `youtube.com/channel/ID` | チャンネルのライブページをスクレイピングして読み取るため、Twitchと比べてデータが不完全になることがあります。チャンネルIDのURLは、ハンドルに変換されます。 |
| Kick | `kick.com/slug` | Kickの公開APIを使用します。アバターのプレースホルダーには、チャンネルのバナー画像が入ります。 |
| Picarto | `picarto.tv/name` | Picarto APIを使用します。 |

Trovo と Facebook は、ダッシュボードのプラットフォーム一覧や保存されたデータには表示されますが、現在のコードにはTrovoのURLを判定する仕組みがなく、Facebookのプロバイダーもありません。そのため、これらのURLをフォローしようとすると拒否されます。

## 確認の仕組み

ボットは、プラットフォームごとに1つのトラッカーを保持し、フォローしているすべてのチャンネルの状態を、ラウンドの間に3秒の間隔を空けながらループで確認します。配信は、オフラインになった後に初めてライブとして確認された時点で、オンラインとして通知されます。

配信終了の判定はより慎重に行われます。Twitchでは、ライブ配信中に一時的にオフラインと報告されることがあるためです。配信終了の通知が送られるのは、2回連続のチェックでオフラインと確認された場合です。その間にオンラインに戻った場合は、何も投稿されません。

30分ごとに、ボットはプラットフォームの確認が12時間を超えて失敗し続けている配信を探します。例えば、削除された、または名前を変更されたチャンネルがこれにあたります。該当する配信は、それをフォローしているすべてのサーバーから削除されます。

フォローしている配信の通知チャンネルが削除された場合、その配信は次に `streamlist` が実行されたときに削除されます。

## 送信されるメッセージ

配信の状態が変わると、ボットは次の順序でメッセージを選びます。

1. 配信ごとの **オンラインメッセージ** または **オフラインメッセージ**（新しい状態に対応するもの）。
2. サーバー全体の **共通の配信メッセージ** テンプレート。
3. 組み込みの埋め込み。

配信ごとのメッセージが埋め込みのJSONとして無効な場合は、組み込みの埋め込みの上にプレーンテキストとして投稿されます。グローバルテンプレートが埋め込みのJSONでない場合は、単独のプレーンテキストとして投稿されます。ダッシュボードの埋め込みビルダーで作成されるような、有効な埋め込みのJSONのメッセージは、ボタンを含めて設計どおりに送信されます。

組み込みの埋め込みには、配信者の名前がリンク付きのタイトルとして表示され、配信のタイトルが作成者の行に表示されます。また、**ステータス** フィールドにはOnlineまたはOfflineが、**Viewers** フィールドには視聴者数が、**配信中** フィールドにはゲームまたはカテゴリが表示されます。アバターはサムネイルとして、プレビューは大きな画像として表示されます。ライブ中は緑色、オフラインのときは赤色になります。

### プレースホルダー

配信のメッセージでは、以下のプレースホルダーのみが置き換えられます。プレースホルダーのページにある一般的なサーバーやユーザーのプレースホルダーは使用できません。

| プレースホルダー | 値 |
| --- | --- |
| `%stream.name%` | 配信者の表示名。ない場合は `Unknown` |
| `%stream.username%` | 配信者のログイン名またはハンドル |
| `%stream.url%` | 配信への直接リンク。常に `https://` 付きです。 |
| `%stream.title%` | 現在の配信のタイトル。ない場合は `No title` |
| `%stream.game%` | ゲームまたはカテゴリ。ない場合は `No category` |
| `%stream.viewers%` | 桁区切り付きの視聴者数。オフラインの場合は `-` |
| `%stream.platform%` | `Twitch` や `Youtube` などのプラットフォーム名 |
| `%stream.avatar%` | 配信者のアバターのURL |
| `%stream.preview%` | 配信のプレビューまたはサムネイルのURL |
| `%stream.status%` | `Online` または `Offline`。それぞれ色付きの丸が前に付きます。 |
| `%stream.channelid%` | プラットフォームが提供する場合の、プラットフォーム固有のチャンネルID |

> [!EXAMPLE]
> シンプルなグローバルテンプレートの例：`%stream.name% is live on %stream.platform% playing %stream.game%: %stream.title% %stream.url%`

## 設定

配信通知のページには、**配信**、**配信をフォロー**、**設定**、**統計** の4つのタブがあります。

| 設定 | デフォルト | 内容 |
| --- | --- | --- |
| Notification Channel | なし | 新しい配信のお知らせを送るチャンネル。**配信をフォロー** で選択します。 |
| Stream URL | なし | フォローするリンク。**配信をフォロー** で入力します。 |
| Online Message | なし | 配信が開始したときの配信ごとのメッセージ。**配信** の配信のカードから編集します。 |
| Offline Message | なし | 配信が終了したときの配信ごとのメッセージ。同じカードから編集します。 |
| Global Stream Message | なし | 配信に独自のメッセージがない場合に使うサーバー全体のテンプレート。**設定** で設定します。 |
| Offline Notifications | オフ | フォローしている配信が終了したときに投稿するかどうか。**設定** で設定します。 |

**配信** には、フォローしているすべての配信が、プラットフォーム、チャンネル、追加日とともに一覧表示されます。各カードには削除ボタンがあり、**Clear All** ボタンもあります。**統計** には、配信の合計数、ユニークな配信者の数、通知チャンネルの数、使用中のプラットフォーム、プラットフォームごとの内訳が表示されます。

1つのサーバーがフォローできる配信は最大10件です。11件目を追加すると失敗します。

## セットアップの流れ

1. ダッシュボードで **配信通知** を開き、**配信をフォロー** タブに移動します。
2. **通知チャンネル** を選び、**配信のURL** を貼り付けて、**配信をフォロー** をクリックします。
3. **設定** で、上のプレースホルダーを使って埋め込みエディターから **共通の配信メッセージ** を作成し、**メッセージを保存** をクリックします。組み込みの埋め込みのままにしたい場合は、この手順を省略します。
4. 配信終了の投稿も必要な場合は、**オフライン通知** をオンにします。
5. **配信** に戻り、配信のカードを開いて、グローバルテンプレートと異なる内容が必要な場合は、その配信専用の **オンラインメッセージ** または **オフラインメッセージ** を設定します。
6. `streamcheck <url>` で、ボットが配信を読み取れることを確認し、次の配信開始を待ちます。

## コマンド

これらのコマンドは、サーバーのプレフィックス（変更していない場合は `.`）で実行します。

| コマンド | エイリアス | 必要な権限 | 目的 |
| --- | --- | --- | --- |
| `streamadd <url>` | `sta`, `stadd` | メッセージの管理 | 配信をフォローし、現在のチャンネルに通知を送信 |
| `streamremove <index>` | `strm` | メッセージの管理 | `streamlist` のその位置にある配信のフォローを解除 |
| `streamsclear` | `stclear` | 管理者 | サーバー内のすべての配信のフォローを解除 |
| `streamlist` | `stl`, `streamslist` | なし | フォローしている配信の、番号、プラットフォーム、チャンネルのページ分けされた一覧 |
| `streamoffline` | `sto`, `stoff` | メッセージの管理 | 配信終了の通知を切り替え |
| `streammessage <index> <message>` | `stm`, `stmsg` | メッセージの管理 | 配信の配信開始メッセージを設定。空のメッセージでリセット。 |
| `streamofflinemessage <index> <message>` | `stofmsg`, `stoffline` | メッセージの管理 | 配信の配信終了メッセージを設定。空のメッセージでリセット。 |
| `streamtemplate [template]` | `stt`, `sttemplate` | メッセージの管理 | グローバルテンプレートとプレースホルダーを表示、新しいテンプレートを設定、または `reset` でクリア |
| `streamcheck <url>` | `stc` | なし | 配信が現在ライブかどうかと、その視聴者数を報告 |

## ヒントと注意点

- `streamadd` は、実行したチャンネルを使用します。別のチャンネルを選びたい場合は、ダッシュボードを使ってください。
- 配信の番号は `streamlist` から取得でき、1から始まります。配信を削除すると番号がずれるため、番号で削除する前に一覧を確認してください。
- ボットには、通知チャンネルでのメッセージの送信と埋め込みリンクの権限が必要です。ボットが見えないチャンネルへの通知はスキップされ、ログに記録されます。
- サーバーに、同じTwitchチャンネルの配信開始チャンネルを設定したTwitch Botが接続されている場合は、その連携が優先され、配信通知はそのチャンネルについて沈黙します。そのため、同じ配信が2回投稿されることはありません。
- YouTubeのデータはAPIからではなくスクレイピングで取得されます。タイトル、カテゴリ、視聴者数が欠けたり、`Live Stream` と表示されたりすることがあります。
- 12時間にわたって確認に失敗し続けた配信は、自動的に削除されます。配信者がチャンネル名を変更した場合は、新しいURLをフォローしてください。
