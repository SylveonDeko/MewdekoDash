## 概要

モデレーションは、スタッフが個々のメンバーに対して使うツール群です。中心となるのは警告です。モデレーターが `warn @user reason` を実行すると、メンバーに理由と警告したモデレーターを伝えるDMが届き、警告が保存されます。サーバーに警告ログチャンネルが設定されていれば、警告回数と発動したペナルティを示す埋め込みがそこに投稿されます。

警告は積み重なります。有効な警告が一定数に達したときに自動的に実行されるペナルティ（ミュート、タイムアウト、キック、BAN、ロール付与など）のラダーを設定できます。スタッフがルールを覚えておく必要はなく、件数に達した瞬間にBotが適用します。警告は後から取り消すこともできますし、一定日数が経過すると自動的に失効させることもできます。

これとは別に、直接的な操作もあります。管理ミュートロールを使ったミュート、タイムアウト、キック、ソフトBAN、BAN、期間付きBAN、一括キック、メッセージの一括削除、そして特殊文字を使ってメンバーリストの上位に表示されているニックネームの整理などです。どのBAN操作にも設定可能な削除日数があり、BANと同時にDiscordがそのメンバーのメッセージを何日分削除するかを決めます。

ダッシュボードのページでは、警告、ペナルティラダー、警告ログチャンネル、BANの削除設定を扱います。ミュート、キック、BANなどの直接操作はコマンドのみです。

## 使う理由

- モデレーターが誰であっても同じように適用される、一貫した「3回で処罰」のルールを作りたい。
- チャンネル権限を手動で変更せずに、メンバーをすばやく発言禁止にしたい。
- スパム投稿者が参加したので、BANと同時に直近1日分のメッセージを削除したいが、常連メンバーの期間付きBANでは履歴を消したくない。
- モデレーターが入れ替わっても、誰がいつ何の理由で警告されたかを検索できる記録を残したい。
- 「!!! xXx」のような名前がメンバーリストの上に表示され続けるので、まとめて整理したい。

## 警告

`warn <user> [reason]` の実行には「メンバーをBAN」権限が必要です。Botはまず、サーバー名、モデレーター、理由を含む埋め込みをメンバーにDMで送信しようとします。DMの送信に失敗した場合は、チャンネルでの確認メッセージのフッターにその旨が表示されます。その後、モデレーターの名前と理由（理由が指定されなかった場合は `-`）を付けて警告が保存されます。

メンバーはロールの階層でモデレーターより下、かつBotより下である必要があります。そうでない場合、コマンドは実行されません。

`warnlog <user>` は、日付、モデレーター、理由を含むリストを1ページあたり9件で表示します。取り消された警告は、取り消したユーザー名とともに取り消し線付きで表示されます。`warnlogall` は警告のあるすべてのメンバーを `active (total - forgiven)` の形式で一覧表示します。

`warnclear <user> [index]` は警告を取り消し扱いにします。インデックスを指定しない場合、または `0` の場合は、すべての警告を取り消します。インデックスを指定すると、`warnlog` に表示される番号の警告だけを取り消します。取り消された警告はログには残りますが、ペナルティのカウントには含まれなくなります。ダッシュボードからは、警告を完全に削除することもできます。その場合は永久に消えます。

### 警告の有効期限

`warnexpire <days> <clear|delete>` は、警告が有効とみなされる期間を設定します。日数は0から366まで指定できます。0を指定すると有効期限は無効になります。アクションは、警告が期限切れになったときの処理を決めます。

| アクション | 動作 |
| --- | --- |
| Clear | 警告は取り消し扱いになり、ログに残ります |
| Delete | 警告はデータベースから削除されます |

有効期限は12時間ごとにチェックされ、設定した時点でも1回すぐにチェックされます。

### 警告ログチャンネル

`setwarnchannel #channel` で設定するか、ダッシュボードの **罰則** タブにある **警告のログチャンネル** で選択します。警告が行われるたびに、メンバーの名前とID、現在の警告回数、発動したペナルティ（発動しなかった場合は「None」）、理由、そして警告を発行したメッセージへのジャンプリンクを含む埋め込みが投稿されます。

## 警告ペナルティ

ラダーは「有効な警告がN件に達したら、Xを実行する」というルールの一覧です。警告が発行されると、Botは新しい警告を含むそのメンバーの有効な警告数を数え、その件数とちょうど一致するルールを探します。完全一致の場合にのみ発動するため、3件のルールがあるのに4件目のルールがない状態で警告が4件になった場合は、何も追加では発動しません。

ルールは `warnpunish <number> <punishment> [time]` で設定します。ロール付与の場合は `warnpunish <number> addrole <role> [time]` を使います。`warnpunish <number>` のように数字だけを指定すると、そのルールは削除されます。`warnpunishlist` でラダーを表示できます。

| ペナルティ | 期間指定 | 内容 |
| --- | --- | --- |
| Mute | 任意 | ミュートロールを付与します。期間を指定した場合は期間付きミュートになります |
| ChatMute | 任意 | ミュートロールのみ付与します。ボイスはミュートしません |
| VoiceMute | 任意 | サーバーのボイスミュートのみ行います |
| Timeout | 必須、最大28日 | Discordのタイムアウトを行います |
| Kick | なし | メンバーをキックします |
| Softban | なし | BANしてすぐに解除し、メッセージを削除します |
| Ban | 任意 | 永久BANを行います。期間を指定した場合は期間付きBANになります |
| AddRole | 任意 | 選択したロールを付与します。期間を指定した場合は、その期間後に削除されます |
| RemoveRoles | なし | メンバーのロールをすべて剥奪します |

期間は分単位で保存され、最大49日まで指定できます。Softban、Kick、RemoveRolesでは期間を指定できません。Timeoutは期間がないと保存できません。ペナルティは「Warned too many times.」という理由で実行されます。

ダッシュボードでも同じラダーを **罰則** タブで設定できます。**警告 # の回数で**、**処罰**、任意の **期間（分）**、ロール付与の場合は **追加するロール** を選択し、**段階に追加** を押します。すでにルールが設定されている件数に対して保存すると、そのルールは置き換えられます。

> [!EXAMPLE]
> `warnpunish 2 mute 1h`、`warnpunish 3 timeout 1d`、`warnpunish 5 ban`。警告が2件で1時間ミュート、3件で1日タイムアウト、5件でBANになります。

## ミニ警告

ミニ警告と呼ばれる、独立した2つ目の警告の仕組みもあります。これは、若手スタッフが対応する軽微な違反のためのものです。`mwarn` の実行には「メンバーをミュート」権限のみが必要です。ミニ警告には独自のログ（`mwarnlog`、`mwarnlogall`）、独自の取り消しコマンド、独自の有効期限、独自のペナルティラダー（`mwarnpunish`）、独自のログチャンネル（`setmwarnchannel`）があります。ミニ警告がメインのラダーにカウントされることはなく、その逆もありません。ダッシュボードにはミニ警告は表示されません。

## ミュートとミュートロール

Botは管理するミュートロールを持っています。デフォルトの名前は `Mewdeko-mute` です。`muterole @role` で変更でき、`muterole` だけを実行すると現在のロールを確認できます。最初にミュートが必要になったとき、ロールが存在しなければBotがそれを作成し、すべてのテキストチャンネルを順にたどって、メッセージの送信、リアクションの追加、ファイルの添付、スレッドでのメッセージ送信、公開スレッドの作成を拒否する上書き権限を追加します。スレッドはスキップされます。チャンネル数の多いサーバーでは時間がかかることがあります。

| コマンド | 効果 |
| --- | --- |
| `mute` | 完全ミュートです。ミュートロールを付与します |
| `chatmute` | ミュートロールのみ付与します |
| `voicemute` | そのメンバーをボイスでのみサーバーミュートします |
| `stfu` | 現在のチャンネルでのみ、そのメンバーのメッセージ送信を権限上書きで拒否します |

それぞれに期間指定の形式もあります。完全ミュートは1分から90日まで、チャットとボイスのミュートは1分から49日までの期間を指定できます。`stfu` に期間を指定すると、時間が経過したときに上書きが解除されます。ミュートされたメンバーとミュート解除されたメンバーには、それぞれDMが届きます。

`removeonmute y` を設定すると、完全ミュート時にそのメンバーの他のロールも剥奪して保存し、`unmute` で元に戻します。`removeonmute n` で無効になります。`unmuteall` は、確認のプロンプトの後（任意で理由を付けて）、ミュートロールを持つすべてのメンバーからそのロールを削除します。

## タイムアウト

`timeout <time> <user> [reason]` は、最大28日までのDiscordのネイティブなタイムアウトを使用します。実行者とBotの両方に「メンバーをタイムアウト」権限が必要です。`untimeout <user>` で解除できます。理由は監査ログに `moderator | reason` の形式で記録されます。

## BAN、キック、ソフトBAN

`ban <user> [reason]` は、先にメンバーにDMを送信してからBANします。`ban <time> <user> [reason]` は期間付きBANで、最大49日後に自動で解除されます。`ban <pruneTime> <time> <user>` では、削除期間とBANの長さを明示的に指定できます。サーバーにいないユーザーもIDを指定してBANできます。`unban <user or id>` で解除します。

`softban <user> [reason]` はBANしてすぐに解除するため、直近のメッセージも削除されるキックのような動作になります。`kick <user> [reason]` はメンバーをキックし、`masskick @a @b @c` は複数のメンバーを一度にキックして、成功した人数を報告します。`masskill` はBotのオーナーのみが使用でき、貼り付けたID一覧を一括BANします。

### BANのDM

BANされたメンバーに送られるメッセージは、`banmessage <text or embed code>` でカスタマイズできます。テキストは埋め込みパーサーを通るため、埋め込みビルダーのあらゆる機能を使えます。`-` に設定するとDMを一切送信しません。`banmsgreset` でデフォルトに戻せます。`banmsgtest [duration] [reason]` を実行すると、現在のテンプレートがあなたにDMで送信されるので、表示を確認できます。

| プレースホルダー | 値 |
| --- | --- |
| `%ban.mod%` | モデレーターのフルネーム |
| `%ban.mod.name%` | モデレーターのユーザー名 |
| `%ban.user%` | BANされたメンバーのフルネーム |
| `%ban.user.name%` | BANされたメンバーのユーザー名 |
| `%ban.reason%` または `%reason%` | 理由。理由がない場合は `-` |
| `%ban.duration%` | `d.hh:mm` 形式の期間、または `perma` |

`%server.name%` などのサーバー用プレースホルダーもここで使用できます。

## BANの削除

どのBANにも削除設定があります。これは、Discordがそのメンバーのメッセージを何日分削除するかを表す値で、0から7までの範囲で指定します。単一のグローバルな値ではなく、BANの種類ごとにデフォルト値があり、サーバー全体、カテゴリ、または単一のチャンネルごとに上書きできます。

| アクション | キー | 組み込みのデフォルト |
| --- | --- | --- |
| Ban | `ban` | 7日 |
| Ban by ID | `hackban` | 7日 |
| Temporary ban | `tempban` | なし |
| Softban | `softban` | 7日 |
| Mass ban | `massban` | 7日 |
| Ban by avatar hash | `banbyhash` | なし |
| Ban in role | `baninrole` | なし |
| Ban under age | `banunder` | なし |
| Warn punishment | `warnpunish` | なし |
| Auto-ban role | `autobanrole` | なし |
| Role monitor | `rolemonitor` | なし |
| Filter | `filter` | なし |
| Lockdown | `lockdown` | なし |
| Dashboard | `dashboard` | なし |

BANが行われると、Botは最も具体的な設定を探します。まずコマンドを実行したチャンネル、次にそのチャンネルのカテゴリ、最後にサーバーのデフォルトです。それぞれのレベルでは、「すべてのアクション」向けの設定よりも、そのアクションに対する正確な設定が優先されます。一致する設定がない場合は、組み込みのデフォルトが適用されます。

`banprune` は、現在のチャンネルからのBANで削除される内容と、設定されているすべての値を表示します。`banpruneset <action|all> <days> [#channel or category]` で設定し、`banpruneclear <action|all> [#channel or category]` で削除し、`banprunereset` ですべてを消去します。

ダッシュボードの **BAN 時のメッセージ削除** タブには、**Server Defaults** の下にすべてのアクションが並び、それぞれに日数の入力欄があります。また、フォールバックとなる **すべてのアクション** の行と、**上書き設定** セクションがあります。**上書き設定** では **対象範囲**（ChannelまたはCategory）、対象、**アクション**、**メッセージ削除（日数）** を選択できます。

## メッセージの一括削除

`purge [count] [flags]` は、現在のチャンネルの最大1000件のメッセージを削除します。件数を指定しない場合は、Bot自身の直近100件のメッセージを削除します。`purge @user [count]` は、直近2週間のうちそのメンバーのメッセージだけを削除します。フラグは組み合わせて使えます。`-s` はピン留めされたメッセージをスキップし、`-nb` はBotをスキップし、`-ob` はBotのメッセージのみを対象にし、`-he` は埋め込みを含むメッセージのみを対象にし、`-ne` は埋め込みを含まないメッセージのみを対象にし、`-c text` はテキストを含むメッセージのみを対象にし、`-b date` は日付より前、`-a date` は日付より後を対象にします。

`purgeuser <user> <count>` は、すべてのテキストチャンネルの直近 `count` 件（1から1000まで）のメッセージを検索し、各チャンネルからそのユーザーのメッセージを削除します。

## ニックネーム

`dehoist <user>` と `sanitize <user>` は、1人のメンバーのニックネームを書き換えて、先頭の特殊文字や一般的でない文字を取り除きます。`dehoistall [nicksOnly]` と `sanitizeall` は、確認の後にすべてのメンバーに対して実行され、バックグラウンドジョブとして動きます。`massnickprogress` で進行状況を確認し、`massnickstop` でキャンセルできます。1人を対象とするコマンドにはBotの「ニックネームの管理」権限が必要です。「すべて」を対象とするバリアントにはBotの「管理者」権限が必要です。どちらの場合も、Botのロールは対象のメンバーより上位にある必要があります。

## 設定

ダッシュボードのページには **概要**（警告の件数）、**警告**、**罰則**、**最近のアクティビティ**、**BAN 時のメッセージ削除** の5つのタブがあります。

| 設定 | デフォルト | 制御する内容 |
| --- | --- | --- |
| Warning Log Channel | なし | すべての警告の埋め込みを受け取るチャンネル |
| Punishment ladder | 空 | 警告の各件数で発動する内容 |
| Warning expiry | オフ | 警告が取り消されるまたは削除されるまでの日数。コマンドのみ |
| Mute role | `Mewdeko-mute` | ミュートコマンドが付与するロール。コマンドのみ |
| Remove roles on mute | オフ | 完全ミュートの前後でロールを剥奪・復元します。コマンドのみ |
| Ban DM template | デフォルトの埋め込み | BANされたメンバーが受け取るDM。コマンドのみ |
| Ban purge defaults | 操作ごと | 各種BANで削除されるメッセージの日数 |
| Ban purge overrides | なし | チャンネルごとまたはカテゴリごとの削除設定 |

**警告** タブでは、スタッフはユーザーIDを指定して、必須の理由を付けてメンバーに警告したり、ID、理由、モデレーターで検索したり、取り消された警告を非表示にしたり、1件の警告を取り消したり、メンバーのすべての警告を取り消したり、1件の警告を完全に削除したりできます。

> [!WARNING]
> ダッシュボードから警告を削除すると、完全に消去され、カウントされなくなります。取り消しの場合は記録が残り、同じくカウントされなくなります。履歴を消す理由がない限り、取り消しを使用してください。

## セットアップの手順

1. ダッシュボードで **モデレーション** を開き、**罰則** に移動します。
2. スタッフだけが閲覧できる **警告のログチャンネル** を選択します。
3. ラダーにルールを追加します。最初は、2件で60分のMute、3件で1440分のTimeout、5件でBANから始めると良いでしょう。
4. 既にミュート用のロールがある場合は `muterole @Muted` を実行します。そうでなければ、初回使用時にBotが `Mewdeko-mute` を作成させます。
5. `warnexpire 90 clear` で有効期限を決め、古い警告が3か月後にカウントされなくなるようにします。
6. **BAN 時のメッセージ削除** では、テンポラリBANで履歴を削除したくない場合は **Temporary ban** を0に設定します。Botのスパム用チャンネルでより多く削除したい場合は、チャンネルごとの上書きを追加します。
7. 代理アカウントでテストします。`warn @alt test` を実行してログチャンネルを確認し、その後 `warnclear @alt` を実行します。

| --- | --- | --- | --- |
| `warn <user> [reason]` | | メンバーをBAN | メンバーに警告し、ラダーのペナルティがあれば適用します |
| `warnlog <user or id>` | | メンバーをBAN | メンバーの警告を表示します |
| `warnlogall` | | メンバーをBAN | すべてのメンバーの警告件数を表示します |
| `warnclear <user> [index]` | `warnc` | メンバーをBAN | すべての警告、または番号を指定して1件の警告を取り消します |
| `warnexpire <days> <clear|delete>` | `warne` | 管理者 | 指定日数後に警告を自動で取り消す、または削除します |
| `warnpunish <number> <punishment> [time]` | `warnp` | メンバーをBAN | ラダーのルールを設定します。数字だけを指定すると削除します |
| `warnpunishlist` | `warnpl` | なし | ペナルティのラダーを表示します |
| `setwarnchannel <#channel>` | `warnchannel` | 管理者 | 警告ログチャンネルを設定します |

| `mwarnlogall` | `mwarnlogs` | メンバーをミュート | すべてのメンバーのミニ警告件数を表示します |

## ヒントと注意点

- Botのロールは、ミュート、キック、BANの対象となるメンバーよりも、またミュートロール自体よりも上位にある必要があります。「ペナルティを適用できません」というエラーのほとんどは、ロールの階層の問題です。
- 対応するコマンドには、Botの「メンバーをBAN」「メンバーをキック」「メンバーをタイムアウト」「ロールの管理」「メッセージの管理」権限が必要です。各コマンドは実行前にBot自身の権限を確認します。
- ラダーは件数が完全に一致したときだけ発動します。「3件以上」と仮定せず、必要な段階をすべて設定してください。
- Botを通じて発行された警告だけがカウントされます。Discord自身のタイムアウトやBANは警告として加算されません。
- ミュートロールは、チャンネルごとに権限を拒否します。ロールが作成された後に作られたチャンネルは、即座にではなく、次回誰かがミュートされたときに上書きが適用されます。
- Discordの一括削除は14日より前のメッセージには届きません。それより古いメッセージは、削除コマンドではスキップされます。
- BANに伴う削除は、設定内容にかかわらず、Discordの仕様により7日が上限です。
- ダッシュボードからの警告には有効な理由が必要で、モデレーター名にはダッシュボードのアカウント名が使われます。
