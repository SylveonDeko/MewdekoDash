## 概要

アナリティクスは、Botを運用しているオーナーのための履歴ページです。表示されるのはBotのオーナーだけで、オーナー以外にはサイドバーに表示されず、URLを直接開いてもダッシュボードのホームに戻されます。サーバーのスタッフが設定する項目はありません。

[パフォーマンス](/wiki/performance) がリアルタイムのプロセスの状態を表示し、再起動するとその情報は失われますが、アナリティクスはBotが自身のデータベースに書き込んだ内容を読み取ります。実行中の各インスタンスは、コマンド、ゲートウェイイベント、シャードのレイテンシ、REST呼び出し、データベースの処理時間、プロセスの指標、例外、機能の利用、AIと音楽の活動、ダッシュボードのページビューを記録します。数値は1分ごとにメモリ上で集計されて毎分書き出され、5分単位と1時間単位のバケットにまとめられ、固定のスケジュールで整理されます。そのため、先週の状況を見たり、その前の週と比較したり、インスタンス、シャード、サーバーごとに絞り込んだりできます。

週次のダイジェストはDiscordのWebhookに投稿でき、保存されているどの指標にもアラートルールを設定して、しきい値を超えたときにWebhookで通知できます。

## 使う理由

- エラーの急増がデプロイの前に始まったのか後に始まったのかを知りたい。現在の失敗内容だけでなく、その経緯を確認したい。
- あるサーバーからBotが遅いと報告があったので、日付の範囲を指定してそのサーバーのコマンドのレイテンシ、活動、セキュリティイベントを確認したい。
- サーバーが実際にどの機能を設定して使っているか、そしてそれが数か月でどう変わったかを見たい。
- シャードのレイテンシ、エラー率、REST 429が上限を超えたときに、監視せずにDiscordへの通知を受け取りたい。
- 毎週月曜日に、成長、コマンド、エラー、主要な機能の概要をチャンネルで受け取りたい。

パイプラインの状態は、最後のフラッシュが60秒以内、最後のロールアップが10分以内、フラッシュエラーがない場合に `healthy` になります。それ以外の場合は、`flush stale` または `rollup stale` になります。フラッシュが失敗した場合は `error`、Botの設定でアナリティクスが無効になっている場合は `disabled` になります。最後のサーバー数が3分より古いインスタンスは黄色、10分より古いインスタンスは赤で表示されます。

> [!NOTE]
> すべての時刻はUTCです。スナップショット、集計の行、日次の合計は1日1回夜間に書き込まれるため、Botが一度でも00:05 UTCを過ぎて稼働していないと、**サーバー** と **機能** のタブは空になります。

### フィルターバー

タブの上にあるバーはすべてのタブに適用され、URLに保存されます。そのためタブを切り替えたり、再読み込みしたり、リンクを共有したりしても、同じ表示が維持されます。

| コントロール | 動作 |
| --- | --- |
| Range | `15m`、`1h`、`6h`、`24h`、`7d`、`30d`、またはUTCの開始と終了を指定した最大31日間のカスタム範囲 |
| compare | 対応するグラフやタイルに、1つ前の同じ長さの期間を重ねて表示します |
| Bot | パイプラインが認識しているインスタンスから1つ選択するか、すべてを選択します |
| Shard | 1つのシャードIDまたはすべて |
| guild id | 生のテーブルとサーバーの表示を1つのサーバーに限定します。Enterキーで適用します |
| Refresh | ページが表示されている間は30秒ごとにすべてを再読み込みします。ボタンで即座に更新できます |
| Copy link | すべてのフィルターを含む現在のURLをコピーします |

タイルをクリックすると、その指標の内訳を示すドリルダウンが開きます。グラフでは、小さい系列を **その他** にまとめたり、累計の表示を切り替えたり、範囲のスライダーで拡大したり、凡例の項目を右クリックして1つの系列だけを表示したりできます。

## 設定

ページ自体には設定項目はありません。設定できるのはアラートのルールと、3つのBot設定キーだけです。

### アラートのルール

各ルールは1つの指標を監視します。編集フィールドは次のとおりです。

| フィールド | 意味 |
| --- | --- |
| Name, Description, Severity, enabled | ラベルと、`info`、`warning`、`critical` のいずれか。Webhookの色とタイトルが決まります |
| Metric, Filters, Group by | 保存されている任意の指標、任意のラベルフィルター、そして各値を個別に評価するための任意のラベル（例：`shard` ごと） |
| Agg, Window | `sum`、`avg`、`min`、`max`、`last`、`rate`、`count`、`p50`、`p95`、`p99`。期間は1分から1日まで |
| Comparator, Threshold, High | `gt`、`gte`、`lt`、`lte`、`outside`（Threshold未満またはHigh超過）、`pct_change`（同じ期間の1つ前の基準と比較したパーセント変化）、`deviates`（直近N日間の平均に対するz値）、`nodata`（期間内に何も報告がない） |
| Baseline, Direction | `pct_change` と `deviates` 用。前日または先週、そして `up`、`down`、`both` |
| For | 違反がこの期間続いた場合に発火します。`immediately` は保留状態をスキップします |
| Cooldown | 発火通知の最小間隔 |
| Repeat | 発火中は再通知するか、1回だけにするか |
| Min samples | 期間内のサンプル数がこれより少ない場合は評価をスキップします |
| Webhook URL, Mention role id, Thread id | DiscordのWebhook、発火時にメンションするロール（任意）、投稿先のスレッド（任意） |
| Quiet from, Quiet to | 何も送信しないUTCの時間帯。深夜をまたぐこともできます |
| notify on resolve | グループが正常に戻ったときにも投稿します |

右側のプレビューグラフでは、絶対値の比較演算子の場合に、ドラフトのしきい値を破線の帯で示します。

ルールは1分ごとに評価されます。各グループは `ok` から（For が設定されている場合のみ）`pending`、そして `firing` へと移行し、`ok` に戻ります。イベントログでは、`firing` から `ok` への遷移は `resolved` として記録されます。テーブルからミュートすると、ルールは1時間静かになります。APIでは最大30日まで指定できます。ミュートされたルールや静かな時間帯でも状態は変化しますが、投稿はされません。**テスト送信** を押すと、ルールのWebhookにテストメッセージが送信されます。

### Botの設定キー

`bot.yml` で設定するか、オーナーの `config` コマンドで設定します。すべてデフォルトでオン、30、空です。

| キー | 意味 |
| --- | --- |
| `analyticsEnabled` | `false` にすると収集が何もしなくなります。Pipelineタブには `disabled` と表示されます |
| `analyticsRetentionDays` | 生のコマンドの行、ページビュー、ギルドのイベントログを保存する日数 |
| `analyticsDigestWebhook` | 週次ダイジェストを投稿するDiscordのWebhook。空の場合はダイジェストが無効になります |

### 保存される内容と期間

| データ | 保存期間 |
| --- | --- |
| 1分単位のバケット | 48時間 |
| 5分単位のバケット | 14日 |
| 1時間単位のバケット | 400日 |
| コマンドの実行、ページビュー、サーバーのセキュリティイベント | `analyticsRetentionDays` |
| エラーのサンプル、サーバーごとの1時間単位の機能とイベントの活動 | 90日 |
| アラートのイベント | 180日 |
| 日次のスナップショット、集計、日次の合計 | 削除されません |

生の行は15秒ごとに書き出され、1分単位のバケットは毎分書き出されます。1分単位のバケットは5分ごとに5分単位のバケットにまとめられ、5分単位のバケットは1時間単位にまとめられます。削除は6時間ごとに実行されます。

### 保存されない内容

- メッセージの内容。コマンドの行には、コマンド名、モジュール、種類、結果、処理時間、失敗した場合は例外のクラスと、そのメッセージの最大200文字が含まれます。
- ユーザーID。アナリティクスのデータは、コマンドを実行した人ごとにキー付けされることはありません。
- クライアントのIPアドレス。ページビューには、IPアドレスとユーザーエージェントから作られた訪問者のハッシュを保存します。ソルトは毎日変わるため、訪問者を日をまたいで追跡することはできません。`/api/`、`/cdn/`、静的アセット、アナリティクスページ自体へのリクエストは記録されません。

統計の収集をオプトアウトしたサーバーとユーザーは尊重されます。そのコマンドは集計には含まれますが、生の行はギルドIDとサーバー規模なしで書き込まれます。

## セットアップの手順

1. ボットのオーナーのアカウントでダッシュボードにサインインし、サイドバーから **アナリティクス** を開きます。オーナーにしか表示されません。
2. 最初に **パイプライン** を開きます。ピルには `healthy` と表示され、すべてのインスタンスに最近のハートビートがあるはずです。フラッシュが古い場合は、Botがデータを書き込んでいないことを意味します。
3. 範囲を選択し、インスタンスを複数運用している場合はフィルターバーでBotを選択します。前の期間と比較するには **比較** をオンにします。
4. **アラート** に移動して **新しいルール** を押し、`shard.latency` のような指標を選択し、5分間の `max`、`gt` と上限値、`shard` でグループ化、Webhookを貼り付けます。保存した行で **テスト送信** を押します。
5. Botの設定で `analyticsDigestWebhook` を設定し、**今すぐダイジェストを送信** を押して、次の月曜日の投稿の内容を確認します。
6. 一晩経ったら、**サーバー**、**機能**、およびその集計の推移を確認します。

## コマンド

Analyticsページはダッシュボード専用で、対応するBotのモジュールはありません。オーナーの `config` コマンドで上記の3つのキーを変更できます。関連する内容の一部は、オーナーのコマンドでチャットからも操作できます。サーバーのプレフィックス（変更していない場合は `.`）を付けて実行します。

| コマンド | エイリアス | 必要な権限 | 用途 |
| --- | --- | --- | --- |
| `config bot analyticsEnabled false` | `conf` | Botのオーナー | 分析の記録を停止します。`true` で再開します |
| `config bot analyticsRetentionDays 14` | `conf` | Botのオーナー | 生の行を保存する期間を変更します |
| `config bot analyticsDigestWebhook <url>` | `conf` | Botのオーナー | 月曜日のダイジェストの投稿先 |
| `stats` | | なし | Botのバージョン、5秒ごとに実行されたコマンド数、メモリ、キャッシュ数、シャードと稼働時間 |
| `commandstats` | `cstats` | Botのオーナー | 最も使われたコマンド、モジュール、サーバー、ユーザー |
| `shardstats` | | Botのオーナー | すべてのシャードの状態 |

## ヒントと注意点

- このページはBotを通じてオーナーであることを確認します。そのため、あるBotインスタンスではオーナーでも、別のインスタンスではオーナーでないアカウントは、2つ目のインスタンスでリダイレクトされます。
- ダイジェストは月曜日の09:00 UTC以降に送信され、直近7日間を、その前の7日間と比較して集計します。対象はサーバー、コマンド、エラー、イベント、新規および失ったサーバー、ページビュー、AIのトークン、音楽のトラックで、さらに上位5件のコマンド、エラー、機能を含みます。
- 長い範囲の系列は1時間単位のバケットから作られるため、パーセンタイルは平滑化されます。分単位の詳細を見るには範囲を狭めてください。分単位のデータは直近48時間分しかありません。
- フラッシュ前に収集のメモリ内バッファがいっぱいになると、その間隔の余分な生のコマンドの行は破棄されますが、集計は継続してカウントされます。パイプラインの **保留中の行** の値が増え続ける場合はその兆候です。
- アラートのルールにはDiscordのWebhook URLが必要です。それ以外は保存時に拒否されます。
- 推定AIコストは定価が分かっているモデルのみを対象とするため、合計は下限値になります。
