## 概要

プロセスログは、Botがコンソールに書き出した内容を、pm2が保持しているログファイルから直接表示します。サーバーにシェルでアクセスする必要はありません。Botのオーナーだけが利用できます。オーナー以外にはサイドバーに表示されず、URLを直接開いてもダッシュボードのホームに戻されます。さらに、サインインしたアカウントがオーナーでない限り、Botはリクエストを拒否します。

このページは、選択されたBotのインスタンスに対して、pm2のプロセス一覧を要求します。そのホストでpm2が管理しているすべてのプロセスが、Botだけでなく一覧に表示されます。各プロセスのステータス、PID、稼働時間、再起動回数、CPUとメモリ、2つのログファイルのサイズが示されます。プロセスを1つ選ぶと、そのstdoutログの末尾数百行が読み込まれます。**追従中** がオンの間は、2秒ごとに新しい行が追加され続けます。

ログの行はSerilogが出力する色を保持し、各行にはレベルのタグが付きます。そのため、ノイズになる行を非表示にできます。スタックトレースなどの継続行は、その上の行に付いたままになるため、infoを非表示にしても、トレースが取り残されることはありません。

## 使う理由

- Botが再起動したりクラッシュしたりしたので、停止する直前に何を出力していたかを確認したい。その情報はstderr側にあります。
- メンバーがコマンドの失敗を報告してきたので、そのメンバーが再度試している間にログをリアルタイムで監視したい。
- サーバーにSSHで入らずに、数千行の最近のログからギルドIDやメッセージを検索したい。
- バグレポート用に、ログファイル全体が必要なので、ダウンロードして手元で使いたい。

## 操作

| コントロール | 動作 |
| --- | --- |
| プロセスカード | ホスト上のpm2のプロセスごとに1枚。**このBot** と表示されたカードは、そのリクエストに応答しているインスタンスです。クリックするとそのログを読めます。 |
| **stdout** / **stderr** | 通常のログが出力される、プロセスの出力ログと、クラッシュや実行時の診断が記録されるエラーログを切り替えます。 |
| **100** から **2k** | ログを開くとき、または再読み込みするときに読み込む行数。追跡モードでは、ページに最大5,000行を保持し、それを超えると古い行から削除します。 |
| フィルターボックス | 入力した文字列を含まない行をすべて非表示にします。大文字と小文字は区別されません。 |
| **追従中** / **追従** | ライブ更新のオン・オフを切り替えます。オンの間、ページは2秒ごとに新しい行を取得し、上にスクロールしていない限り、それに合わせて下にスクロールします。 |
| **折り返し** | 長い行を横スクロールせずに折り返します。 |
| **コピー** | 表示されている行を、色を取り除いてクリップボードにコピーします。 |
| **再読み込み** | ファイルの末尾を読み直します。 |
| **Download** | ディスク上のログファイル全体を、カラーコードを含めたまま保存します。その横のサイズは、ファイルの現在のサイズです。 |
| レベルのチップ | **VRB**、**DBG**、**INF**、**WRN**、**ERR**、**FTL**。それぞれに、読み込まれたタグ付きの行数が表示されます。クリックすると、そのレベルの行を非表示または表示にします。 |

追跡中に上にスクロールすると、新しい行は保留され、右下のボタンに待機中の行数が表示されます。そのボタンをクリックすると下に戻り、ログのスクロールを再開します。

> [!NOTE]
> 1回の読み取りは1 MBが上限です。要求された行がその範囲に収まらない場合、ページには古い行が省略されたことが表示されます。すべてを見るにはファイルをダウンロードしてください。

## Botがログを見つける方法

Botは、自分のホストで `pm2 jlist` を実行し、pm2が各プロセスについて報告するログファイルのパスを読み取ります。これは、同じユーザーでpm2のデーモンがすでに実行されている場合にのみ行われるため、誤ってデーモンを起動することはありません。pm2はインストールされているが問い合わせできない場合、このページはpm2のログディレクトリにあるファイルにフォールバックし、そのことを表示します。pm2がまったくない場合は、空の一覧ではなく、その旨を説明します。

複数のBotインスタンスに接続されたダッシュボードでは、プロセス一覧は選択されているインスタンスのものになります。各インスタンスは、自分のホストしか見ることができないためです。

## セットアップの手順

1. Botのサーバーでpm2を使ってBotを実行します。例：`pm2 start dotnet --name mewdeko -- Mewdeko.dll`。
2. Botのオーナーのアカウントでダッシュボードにサインインし、サイドバーから **プロセスログ** を開きます。
3. **このBot** と表示されたプロセス、またはホスト上の他のプロセスを選びます。
4. ログをリアルタイムで見るには **追従中** をオンのままにします。オフにして、フィルターとレベルのチップを使って読み込まれた内容を詳しく調べることもできます。
5. クラッシュの後は **stderr** に切り替えて、停止するまでにランタイムが出力した内容を確認します。

## ヒントと注意点

- ログはファイルから読み取られるため、pm2の外で起動されたプロセスにはログがありません。Botのコンソール出力が表示されるのは、Bot自体がpm2の下で動いている場合だけです。
- `pm2 flush` を実行したり、`pm2-logrotate` を使ったりすると、pm2はファイルをローテーションまたは切り詰めします。このページは、ファイルが小さくなったことを検知し、自動的に末尾を再読み込みします。
- フィルターとレベルのチップは、すでに読み込まれた行にしか適用されません。さらに過去を検索するには、より多くの行を読み込むか、ファイルをダウンロードしてください。
- このページでBotが変更されることはありません。ここからプロセスを再起動したり、ログを消去したりすることはできません。それにはオーナーの `restartinstance` コマンドと、サーバー上の `pm2 flush` を使用してください。
