## What it does

Switch モジュールは、Nintendo Switch のホームブリューとエミュレーションに関するサーバーのためのサポートツールキットです。`2168-0002` のようなエラーが投稿されると、サポート担当者が `err 2168-0002` を実行し、ボットはそのエラーが属するモジュール、わかっていること、そしてあれば Nintendo のサポートページへのリンクを返信します。

2つの小さな変換機能は、`NNNN-NNNN` の形式を、コードで使われる生の16進数の値に変換し、その逆も行います。`switchbrew` は switchbrew.org の wiki を検索するため、Discord を離れなくても、SVC、結果コード、ハードウェアのページを見つけられます。

最も大きな機能は、Ryujinx のログ分析機能です。ユーザーが `Ryujinx.log` を添付し、誰かがそのメッセージに対して、または返信として `analyselog` を実行すると、ボットはゲーム、エミュレーターのバージョン、ハードウェア、関連するすべての設定、最後のエラー、インストールされた MOD とチート、そして一般的な設定ミスを指摘する注意事項の一覧を含む埋め込みを作成します。

設定が必要なものはなく、何も保存されません。すべてのコマンドは全員が使えます。

## Why you would use it

- サポートチャンネルには、「2811-5001 はどういう意味ですか」という同じ質問が毎日届きます。
- Ryujinx のトラブルシューティングは、ログを読むことから始まりますが、多くの人は何を探せばよいかわかりません。
- 開発者は、ソースコードを検索するために、エラーの16進数の形式がほしいと考えています。
- 誰でも Discord から switchbrew.org のページを表示できます。

## Error code lookups

`err <code>` は、どちらの形式も受け付けます。

- `NNNN-NNNN`。最初のグループは 2 で始まります（例: `2168-0002`）。モジュール番号は最初のグループから 2000 を引いた値で、説明は2番目のグループです。
- `0x` の接頭辞が付いた16進数の値（例: `0x2A2`）。下位9ビットがモジュールで、残りが説明です。

返信には、両方の形式のコード、モジュール名と番号、説明の番号、そして説明が表示されます。説明は次の順に探されます。その正確なコードに対してわかっている説明、その正確なコードに対する Nintendo のサポートページ、そのコードがモジュール内で属する範囲についての説明、そして最後に "unknown"。わかっているコードは通常の色で、わからないコードはエラーの色で表示されます。

`2-AAB6A-3400` のように、パターンに従わないコードもいくつかあります。これらは短いリストと完全に一致するかどうかで照合され、そのコードが属するゲームとともに報告されます。

`err2hex <NNNN-NNNN>` は16進数の値を表示します。`hex2err <hex>` はハイフン付きの形式を表示します。`0x` の接頭辞は省略できます。

## Switchbrew search

`switchbrew <query>` は、wiki の検索 API に問い合わせ、上位5件の一致結果を、リンクと、それぞれ最大200文字の抜粋とともに返します。`svc` はエイリアスなので、`svc SetThreadPriority` のように自然に使えます。

## Ryujinx log analysis

`analyselog` は、メッセージに添付された `.log` または `.txt` ファイルを探します。添付がなく、メッセージが返信である場合は、返信先のメッセージに添付されたファイルを使い、フッターにその投稿者をクレジットします。埋め込みのタイトルはゲーム名で、次の内容を含みます。

| Field | Contents |
| --- | --- |
| General Info | Ryujinx のバージョン、ファームウェア、CPU、GPU、RAM、オペレーティングシステム |
| System Settings | オーディオバックエンド、ドッキングまたは携帯モード、PPTC、シェーダーキャッシュ、VSync、ハイパーバイザー（macOS のみ） |
| Graphics Settings | グラフィックスバックエンド、解像度スケール、異方性フィルタリング、アスペクト比、テクスチャの再圧縮 |
| Errors | ログの最後のエラーブロック。エラーがない場合は "no errors" |
| Mods | ExeFS または RomFS の各 MOD。多い場合は件数とともに省略されます |
| Cheats | 各チート。同じように省略されます |
| Notes | 検出された問題と対処のアドバイス |

注意事項では、次のようなことを扱います。シェーダーキャッシュの衝突または破損、不正なダンプのハッシュ、古いキー、ファームウェアの不足、ファイルの権限エラー、セーブデータの欠如、サービスの不足、Vulkan のメモリ不足、既定のユーザープロファイル、コントローラーが設定されていないこと、Vulkan を使うべき Intel または AMD の GPU、Apple シリコン上の Rosetta、ダミーのオーディオバックエンド、PPTC またはシェーダーキャッシュの無効化、RAM の拡張、ソフトウェアのメモリマネージャー、不足しているサービスの無視、VSync のオフ、ファイルシステムの整合性チェックのオフ、バックエンドのスレッド処理のオフ、カスタムビルド。各注意事項には、情報から重大までの重要度のマークが付きます。

ファイルをダウンロードできない場合、またはファイルが Ryujinx のログではない場合、ボットはログが無効であることを伝えます。

## Settings

このモジュールに設定項目はなく、ダッシュボードのページもありません。

## Setup walkthrough

1. ボットがサポートチャンネルでメッセージ履歴を読み取れ、ファイルを添付できることを確認します。
2. ユーザーに、`Ryujinx.log` をメッセージに直接添付してもらいます。
3. サポート担当者が、そのメッセージに `analyselog` と返信します。
4. エラーコードについては、`err <code>` を実行し、サポートリンクが表示された場合は共有します。
5. 必要に応じて、この2つのコマンドを人々に思い出させるチャットトリガーや固定メッセージを追加します。

## Commands

これらのコマンドは、サーバーのプレフィックスを付けて実行します（変更していなければ `.`）。

| Command | Aliases | Needs | Purpose |
| --- | --- | --- | --- |
| `err <code>` | `nxerr`, `serr` | Nobody | ハイフン付きまたは16進数の形式の Switch エラーコードを説明します |
| `err2hex <NNNN-NNNN>` | `e2h` | Nobody | ハイフン付きのコードを16進数に変換します |
| `hex2err <hex>` | `h2e` | Nobody | 16進数をハイフン付きの形式に変換します |
| `switchbrew <query>` | `sb`, `svc` | Nobody | switchbrew.org を検索します |
| `analyselog` | `analyzelog`, `analyselogs`, `analyzelogs`, `analyze`, `analyse` | Nobody | 添付された Ryujinx のログを分析します |

## Tips and gotchas

- ハイフン付きの形式は、2で始まる4桁、ハイフン、4桁でなければなりません。文字を含むコードは、特別なケースのリストでのみ扱われます。
- ログは `.log` または `.txt` として添付する必要があります。コードブロックに貼り付けたログは読み取られません。
- 分析機能はファイル全体を読むため、新しく起動したものではなく、問題が発生したセッションのログをユーザーに依頼してください。
- switchbrew.org の検索はリアルタイムのリクエストです。サイトが遅い場合は、このコマンドも遅くなります。
- メンバーは `setswitchfc` で、Switch のフレンドコードをプロフィールに保存できます。これは User Profile モジュールの一部です。
