## 概要

ダッシュボードがあなたのサーバーについてボットに送ったすべてのリクエストは、ログインしていたDiscordアカウントに紐づけて記録されます。監査ログのページでは、これをタイムラインとして表示します。誰がXPの設定を開いたか、誰がウェルカムメッセージを編集したか、誰がチャットトリガーを削除したか、そして変更前と変更後の値が分かります。

これはDiscord自身の監査ログや、ログ機能とは別のものです。Discordのログは、Discord内で行われた操作を記録します。Mewdekoのログ機能は、参加、編集、ロールの変更などのサーバーイベントを、選んだチャンネルに投稿します。ダッシュボードの監査ログは、ダッシュボードでの操作だけを記録します。

有効にする必要はありません。誰かがダッシュボードにログインしてサーバーを開いた時点から記録が作成され、90日後に自動的に削除されます。

## 利用する理由

- ダッシュボードを使える人が複数いて、先週Anti-Raidを誰がオフにしたのかを知りたいとき。
- 設定が変わったのに、誰も名乗り出ないとき。
- ダッシュボードのアクセス権をより多くのスタッフに渡す前に、記録を残しておきたいとき。
- 依頼した変更が実際に行われたことと、それが何を置き換えたのかを確認したいとき。

## 記録される内容

各項目には次の情報が含まれます。

- **日時**：リクエストの時刻です。UTCで保存され、ページでは自分のタイムゾーンで表示されます。
- **ユーザー**：Discordのユーザー名とIDです。ダッシュボードのログイン情報から取得され、ユーザーが入力した内容からは取得されません。
- **アクション**：以下の表のいずれかの操作です。
- **セクション**：ダッシュボードの領域です。「AFK System」「Triggers」「Protection」などの分かりやすい名前で表示されます。
- **Endpoint**：正確なリクエストです。例：`PUT Afk/123/settings`。セクションの下に小さく表示されます。
- **Changes**：表示以外の操作について、送信または変更された値です。**詳細** で項目を展開すると表示されます。

ボットは、各項目と一緒にブラウザのユーザーエージェント文字列も保存します。

### 操作

操作は、ダッシュボードが行ったリクエストの種類によって決まります。

| 操作 | 記録されるタイミング |
| --- | --- |
| Viewed | ダッシュボードがデータを読み取ったとき（GETリクエスト）。ページを開くたびに記録されます。 |
| Created | 何かが追加されたとき（POSTリクエスト）。 |
| Updated | 既存のものが変更されたとき（PUTまたはPATCHリクエスト）。 |
| Deleted | 何かが削除されたとき（DELETEリクエスト）。 |
| Accessed | ダッシュボードのセッション開始のために予約されています。フィルターには表示されますが、現在のバージョンではこの操作の項目は書き込まれません。 |

### 変更のセット

表示だけの操作では、変更データは保存されません。それ以外の操作では、ボットは次の2種類のいずれかの情報を保存します。

- **変更前と変更後の差分**：ダッシュボードのセクションが、変更の前に設定のスナップショットを取った場合、項目には変更されたフィールドだけが、それぞれの古い値と新しい値とともに記載されます。ほとんどの設定ページはこの方式です。
- **リクエストの本文**：スナップショットが取られていない場合、ダッシュボードが送信した内容が保存されます。古い値はありません。

フィールド名に `token`、`secret`、`password`、`apikey`、`api_key`、`authorization`、`clientsecret` が含まれる場合、保存前にその値は `[redacted]` に置き換えられます。そのため、認証情報が監査ログに残ることはありません。

ページでは、真偽値はOnとOff、リストは「3 items」、空の文字列は「empty」、値がない場合は「none」と表示されます。フィールド名は読みやすいラベルに変換されます。

> [!NOTE]
> 「Viewed」の項目は、ログの大部分を占めます。ダッシュボードの各ページは、開かれたときに設定を読み込むためです。変更を探すときは、Created、Updated、Deleted で絞り込んでください。

### 記録されない内容

- Discord内でコマンドを使って行われた操作。これらの操作は、ボットが動作した場所であればDiscordの監査ログに表示され、ログ機能を設定していればそちらにも表示されます。
- ログインしたダッシュボードのユーザーに紐づいていないリクエスト。
- 監査ログのページ自体を開くこと、退出フィードバック、そしてボットの状態、パフォーマンス、システム情報、インスタンス管理などのインフラやポーリング用のエンドポイントの一部。
- 明示的に除外されているいくつかのエンドポイント：埋め込みビルダーに提供されるペルソナのアバター画像、セットアップウィザードの「表示すべきか」の確認、ダッシュボードのページ表示のビーコン。

## ページの見方

ダッシュボードの Security の下にある **監査ログ** を開きます。リストには新しい項目から順に、1ページに50件ずつ表示されます。**前へ** と **次へ** のボタンと、項目の総数が表示されます。

リストの上には2つのフィルターがあります。

| フィルター | 機能 |
| --- | --- |
| **アクション** | Viewed、Created、Updated、Deleted、Accessed のうち、その操作の項目だけを表示します。 |
| **セクション** | ダッシュボードの1つの領域の項目だけを表示します。選択肢は、現在読み込まれている項目に含まれるセクションから作られます。 |

**更新** は一覧を再読み込みします。フィルターを変更すると、1ページ目に戻ります。

デスクトップでは、各項目は行として表示され、変更データがある場合は **詳細** ボタンが付きます。スマートフォンでは、各項目はカードとして表示され、**詳細を表示** ボタンが付きます。

> [!EXAMPLE]
> **アクション** を Updated、**セクション** を Protection に設定すると、誰かが保護機能を変更したすべての項目が表示されます。行を展開すると、どのフィールドがどの値からどの値に変わったかが分かります。

## 保存期間

項目は **90日間** 保存されます。クリーンアップの処理は1日に1回、ボットがオンラインになってから5分後に始まり、それより古いものを削除します。エクスポートの機能はないため、その期間を超えて記録が必要な場合は、消える前に保存してください。

## 閲覧できる人

このページは、ダッシュボードにログインでき、あなたのサーバーのメンバーである人だけが利用できます。サーバーのオーナーと Administrator 権限を持つ人は、常に開けます。それ以外の人は、ダッシュボードのアクセス権（ユーザーごとまたはロールごとに付与）で **監査ログ** セクションの **表示** 権限が必要です。

> [!PERMISSION]
> ユーザーはダッシュボードのログイントークンから取得されるため、誰かが別の人の名前で項目を表示させることはできません。

## ヒントと注意点

- セクションのフィルターには、表示中のページにあるセクションだけが一覧に出ます。ドロップダウンにセクションが見当たらない場合でも、後のページには存在する可能性があります。操作のフィルターを解除してページを移動するか、先に操作で絞り込んでください。
- タイムスタンプは、ページを見ているブラウザのタイムゾーンで表示され、管理設定にあるサーバーのタイムゾーンではありません。
- 「Created」の項目は、POSTリクエストが行われたことを意味します。ダッシュボードは一部のトグルや更新にもPOSTを使うため、実際に何が起きたかは、エンドポイントの行と詳細で確認してください。
- 古い値がなく、値だけが表示される項目は、以前の状態をスナップショットしていないセクションから来ています。何が送られたかは分かりますが、何を置き換えたかは分かりません。
- ログはサーバーごとに記録されます。ダッシュボードでサーバーを切り替えると、ログも切り替わります。
