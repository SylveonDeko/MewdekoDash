## 概要

メッセージ集計をオンにすると、ボットは、最低文字数を満たす人間のメッセージが投稿されるたびに、メンバーごと、チャンネルごとに1件ずつ集計を記録します。メッセージの内容は保存されず、誰が、どこで、いつ投稿したかだけが記録されます。集計はキューに入れられ、まとめてデータベースに書き込まれるため、活発なサーバーでもボットの動作が遅くなりません。

メンバーは `usermessages` で自分の合計を確認でき、`channelmessages` で最も活発なチャンネルを確認できます。`servermessages` ではサーバー全体を確認できます。`topusers` は、全メッセージに占める各メンバーの割合とともに、上位10人のランキングを表示します。`activitygraph` は、最も活発な曜日または時間帯の棒グラフを画像で描画します。

ダッシュボードには、同じ数値がグラフで表示されます。スタッフは集計のオン・オフを切り替えたり、集計をリセットしたり、データをCSVまたはJSONでエクスポートしたりできます。

## 使いどころ

- 報酬、ロール、モデレーターの募集のために、最も活発なメンバーを見つけます。
- サーバーを再編成する前に、どのチャンネルが閑散としていて、どのチャンネルが盛り上がっているかを確認します。
- 最も活発な時間帯のグラフを、自分のタイムゾーンで確認し、イベントの時間を決めます。
- メッセージ数と投稿内容の質を比較して、ボットやスパムアカウントを見つけます。

## 集計される内容

| ルール | 動作 |
| --- | --- |
| 集計が有効 | `togglemsgcount` またはダッシュボードのスイッチをオンにするまで、何も記録されません |
| ボット | 一度も集計されません |
| DM | 一度も集計されません。サーバーのチャンネルのみが対象です |
| 最低文字数 | **最低メッセージ長** の文字数より短いメッセージは、スキップされます。既定値は0で、すべてのメッセージが集計されます |
| タイムスタンプ | 時間帯と曜日のグラフのために、メッセージの時刻は90日間保持されます。合計は無期限に保持されます |

最低文字数は、最大4098まで指定できます。数値を指定せずに `minmsglength` を実行すると、現在の値が表示されます。

## アクティビティグラフ

`activitygraph days` は、過去4週間について、週の7日すべてのデータを必要とします。`activitygraph hours` は、過去7日間について、24時間すべてのデータを必要とします。時間単位のグラフでは、ボットが最初にタイムゾーンを選ぶよう求めます。一般的なタイムゾーンの一覧が表示され、IANAのタイムゾーン名も受け付けます。回答がない場合は、キャンセルされます。グラフはPNG画像として投稿されます。

## 設定

メッセージ統計のページには、**統計** と **管理** の2つの上位タブがあります。**統計** には、**概要**、**上位ユーザー**、**上位チャンネル** があります。**管理** には、**設定** と **データのエクスポート** があります。

| 設定 | 既定値 | 制御する内容 |
| --- | --- | --- |
| メッセージ集計を有効化 | オフ | 新しいメッセージを記録するかどうか |
| 最低メッセージ長 | 0 | 0から4098までのスライダー。集計される最短のメッセージ |
| 集計をリセット | | **サーバーのすべての集計をリセット** を押して確認すると、サーバーに保存されているすべての集計が削除されます |
| エクスポート形式 | CSV | 読み込まれた統計をCSVまたはJSONでダウンロードします |
| ユーザー統計を含める | オン | エクスポートに上位ユーザーの行を追加します |
| チャンネル統計を含める | オン | エクスポートに上位チャンネルの行を追加します |
| 時間帯別の内訳を含める | オフ | エクスポートに最も活発な時間帯と最も活発な曜日の行を追加します |

**概要** タブには、**1日のメッセージ数**、**メッセージの合計**、**最終更新**、**ステータス** のタイルのほか、最も活動の少ないユーザーとチャンネル、**24時間のアクティビティ** のグラフ、**週間の推移** のグラフが表示されます。**上位ユーザー** タブには **メッセージの送信数の上位** が、**上位チャンネル** タブには **最も活発なチャンネル** が一覧表示されます。

> [!NOTE]
> エクスポートは、ページに読み込まれている統計をもとに、ブラウザ上で作成されます。入力した開始日と終了日はファイルのヘッダーに書き込まれますが、行の絞り込みには使われません。

## セットアップの手順

1. ダッシュボードで **メッセージ統計** を開き、**管理** に移動してから **設定** を選びます。
2. **メッセージ集計を有効化** をオンにします。
3. 必要であれば **最低メッセージ長** を5に設定するか、Discordで `minmsglength 5` を実行して、1文字の返信を無視するようにします。
4. サーバーで1日間チャットをしてもらい、**統計** で最初の数値を確認します。
5. 1週間後に `activitygraph hours` を実行し、タイムゾーンを選んで、サーバーが最も活発になる時間帯を確認します。

## コマンド

サーバーのプレフィックスを付けて実行します（変更していなければ `.`）。

| コマンド | エイリアス | 必要な権限 | 用途 |
| --- | --- | --- | --- |
| `usermessages [@user]` | `usermsg`, `umsg` | なし | 自分または指定したメンバーの合計、最も活発なチャンネル、最も活発でないチャンネルを表示します |
| `channelmessages [#channel]` | `channelmsg`, `cmsg` | なし | チャンネルの合計、最も活発なメンバー、最も活発でないメンバーを表示します |
| `servermessages` | `servermsg`, `smsg`, `guildmessages`, `guildmsg` | なし | サーバー全体の合計と、最も活発なメンバーおよびチャンネル、最も活発でないメンバーおよびチャンネルを表示します |
| `topusers` | `topu` | なし | メッセージ数の上位10人を、割合とともに表示します |
| `activitygraph [days or hours]` | `actgraph` | なし | 最も活発な曜日または時間帯の棒グラフを表示します。既定は曜日です |
| `minmsglength [number]` | `mmlength`, `minmlength` | サーバーの管理 | メッセージが集計されるための最低文字数を表示または設定します |
| `togglemsgcount` | `togglemessagecount` | 管理者 | 集計のオンまたはオフを切り替えます |
| `resetmessagecounts [@user] [#channel]` | `rmc`, `resetmsgcounts`, `resetmessages`, `resetcounts` | メッセージの管理 | 確認後に、サーバー全体、1人のメンバー、1つのチャンネル、または特定のチャンネルの特定のメンバーの集計をリセットします |

## ヒントと注意点

- 集計は、有効にした時点からのみ始まります。それ以前に送信されたメッセージが、後から集計されることはありません。
- 古いデータがある場合でも、集計が有効になるまで、すべての統計コマンドとダッシュボードは「無効」と表示します。
- 集計は最大100件のイベントごとにまとめて書き込まれるため、合計がライブのチャットより数秒遅れることがあります。
- チャンネルを削除しても、その集計は削除されません。チャンネルを削除する前に、そのチャンネルの集計も消したい場合は `resetmessagecounts #channel` を実行してください。
- 時間単位のグラフの正確さは、選んだタイムゾーンに依存します。スタッフ全員で一貫した結果を得るには、管理モジュールのタイムゾーンのコマンドで、サーバーのタイムゾーンを保存してください。
- XPシステムは独自のアクティビティ追跡を持っており、これらの集計は使用しません。
