## 概要

スタッフは、ほとんどのメンバーには見えないチャンネルに「ゲート」を設置します。メンバーは **Apply for access** ボタンをクリックするか、`channelaccessapply` を実行して、最大5つの質問からなる短いフォームに記入します。申請は審査チャンネルに埋め込みとして投稿され、**承認**、**拒否**、任意の **Abstain**、**内訳** のボタンが付きます。

すでにそのチャンネルを見られる人が投票します。承認が十分に集まると、申請者はロールを付与されるか、チャンネルに対する個人の権限上書きを与えられて参加します。拒否が十分に集まるか、投票期間が終了すると、申請は却下されます。スタッフはいつでも、どちらの結果も強制できます。

ゲートで許可されていれば、申請者はDMで結果を通知されます。却下された申請者は、再度申請する前にクールダウンを待つ必要があります。すべての出来事は、任意のログチャンネルに記録されます。

## 利用する理由

- 既存メンバーが参加者を決めるメンバー限定のラウンジや「インナーサークル」。
- 少人数の信頼できるグループが新規参加者を保証する、認証された成人向けチャンネル。
- 誰かが投稿する前に確認を行いたい、取引やマーケットプレイスのチャンネル。
- スタッフがすべての申請を自分で読まなくても、文書による申請を求めたいすべてのチャンネル。

## ゲート

ゲートは、1つのチャンネルとそのルールからなります。各チャンネルにはゲートを1つだけ設定できます。ロールを指定してゲートを作成すると **ロールゲート** になり、ロールを指定せずに作成すると **直接ゲート** になります。

| 付与の方法 | ダッシュボードの表示 | アクセスの付与方法 | 「中にいる」とみなされる人 |
| --- | --- | --- | --- |
| Role | Give them a role | アクセスロールが申請者に追加されます | アクセスロールを持つ人 |
| Channel permission | Add them to the channel directly | そのメンバーに対して View Channel の許可の上書きが書き込まれます | 現在そのチャンネルを見られる人 |

承認されたメンバーは自動的に削除されることはありません。ロールを取り除くか、権限の上書きを自分で削除してください。

## 申請

申請を開く前に、ボットは次の順番で確認を行います。ゲートが申請を受け付けているか、メンバーがすでにアクセス権を持っていないか、ブロックされていないか、アカウントとサーバー参加が十分に古いか、このゲートに未処理の申請がないか、再申請のクールダウンが過ぎているか、です。いずれかの確認に失敗すると、理由を説明する本人だけに見えるメッセージが返されます。

ゲートに質問がある場合は、質問ごとに入力欄があるモーダルが開きます。Discordのモーダルの制限により、質問は45文字までです。回答欄は1行（200文字）か複数行（1000文字）のいずれかで、必須にすることもできます。質問のないゲートは、すぐに送信されます。

審査メッセージは **審査チャンネル** に送られます。設定されていない場合は、ゲートされたチャンネルそのものに送られます。メッセージには、申請者、アカウントの作成日と参加日、各質問と回答、リアルタイムの投票の集計、そして投票の締め切りを示すフッターが表示されます。**投票が終わるまで申請者を非表示にする** がオンの場合、保留中は名前が「Hidden until the vote closes」に置き換えられます。

### ステータス

| ステータス | 意味 |
| --- | --- |
| Pending | 受付中で、投票が行われています |
| Approved | 可決され、アクセスが付与されました |
| Denied | 投票、期限切れ、またはスタッフによって却下されました |
| Withdrawn | 申請者が `channelaccesswithdraw` で取り下げました |
| Expired | 現在の期限ルールでは使用されません。履歴のために残しています |

## 投票

誰が投票できるかは、ゲートによって決まります。**投票者のロール** が設定されている場合は、そのロールを持つメンバーだけが投票できます。設定されていない場合は、チャンネルへのアクセス権を持つ人と、Manage Roles を持つ人が投票できます。申請者が自分の申請に投票することはできません。

ボタンをクリックすると投票が記録されます。別のボタンをクリックすると投票が変更されます。同じボタンを再度クリックすると、投票が取り消されます。集計は、変更のたびにメッセージ上で更新されます。

承認数が **必要な承認数** に、または拒否数が **必要な却下数** に達すると、申請は直ちに解決されます。どちらかのしきい値を0に設定すると、その側は無効になります。たとえば **必要な却下数** を0にしたゲートは、スタッフか期限切れによってのみ却下されます。

**内訳** は、誰がどちらに投票したかを投票者だけに表示します。**誰がどちらに投票したかを非表示にする** がオンの場合、Manage Roles を持つメンバーだけが見られます。

### 投票期間が終了したとき

投票期間を過ぎた申請については、1分ごとにバックグラウンドで確認が行われます。何が起こるかはゲートごとに設定されます。

| オプション | ダッシュボードの表示 | 結果 |
| --- | --- | --- |
| Deny | Deny the application | 申請が却下されます。デフォルトです。 |
| Majority | Whichever side has more votes | 承認数が拒否数を上回っている場合は承認され、そうでなければ却下されます |
| StayOpen | Leave it open for staff | スタッフが解決するまで何も起こりません |

**Voting window** を0にすると、時間制限がなくなります。

## 申請者のブロック

スタッフは、1つのゲートから、またはサーバー内のすべてのゲートから、ユーザーをブロックできます。ブロックされたユーザーが申請しようとすると、「You are blocked from applying for this channel」と表示されます。ブロックにはオプションの理由を付けられ、ブラックリストに表示されます。

## 設定

**チャンネルアクセス** ページには3つのタブがあります。**ゲート**、**応募**、**ブロック済み** です。

**ゲート** には、各ゲートの **参加申請を受け付け中** トグルが一覧表示されます。展開すると、設定、**申請時の質問**、**申請パネル** の掲載機能が表示されます。以下のデフォルトは、新しいゲートに適用されます。

| 設定 | デフォルト | 制御する内容 |
| --- | --- | --- |
| Locked channel | 必須 | ゲートされるチャンネルです |
| How people get in | Give them a role | ロールゲートか直接ゲートか |
| Role granted on approval | なし | ロールゲートのためのアクセスロールです |
| Approvals needed | 3 | 承認として解決される承認数です。0で無効になります |
| Denials needed | 3 | 却下として解決される拒否数です。0で無効になります |
| Voting window (hours) | 72 | 期限ルールが実行されるまでの時間です。0で無制限になります |
| When the window closes | Deny the application | 3つの期限オプションのうちの1つです |
| Review channel | ゲートされたチャンネル自身 | 投票のために申請が投稿される場所です |
| Log channel | ログなし | 新しい申請と結果が記録される場所です |
| Voter role | アクセスロールを持つ全員 | 投票を1つのロールに限定します |
| Ping role on new applications | メンションなし | 申請が届いたときにメンションされるロールです |
| Min account age (days) | 0 | これより新しいアカウントを拒否します |
| Min time in server (days) | 0 | これより最近に参加したメンバーを拒否します |
| Reapply cooldown (hours) | 168 | 拒否または期限切れの後、再度申請するまでの待機時間です |
| Offer an abstain button | オン | 審査メッセージに Abstain ボタンを追加します |
| Hide the applicant until the vote closes | オフ | 保留中は申請者を匿名にします |
| Hide who voted which way | オフ | 内訳は Manage Roles を持つ人だけに表示されます |
| DM the applicant on a decision | オン | 結果をDMで送信します |

**応募** には、ゲートとステータスで絞り込んだ申請が一覧表示され、保留中のものには集計と **承認** および **拒否** ボタンが表示されます。**ブロック済み** にはスコープ別のブロックされたユーザーが一覧表示され、1つのゲートから、または **すべてのゲート** から誰かを **ブロック** でき、理由も任意で指定できます。

## セットアップの手順

1. Discordでチャンネルを非公開にし、ロールゲートの場合は、そのチャンネルを見られるロールを作成します。
2. ダッシュボードで **チャンネルアクセス** を開き、**チャンネルへの参加申請を開始** を使います。**ロックされたチャンネル** を選び、**参加方法** を選択し、必要であればロールを選びます。
3. ゲートを展開します。申請がロックされたチャンネルに届かないように **審査チャンネル** を設定し、記録を残したい場合は **ログチャンネル** を設定します。
4. 想定する投票者の数に合わせて、**必要な承認数**、**必要な却下数**、**Voting window** を調整します。
5. **申請時の質問** の下で、最大5つの質問を追加します。必要に応じて **必須** と **複数行の回答** にチェックを入れます。
6. **申請パネル** の下で、ボタンを置く場所を選び、**パネルを投稿** をクリックします。
7. テスト用のアカウントから申請し、アクセス権を持つメンバーとして投票し、申請者が参加できることを確認します。

## コマンド

コマンドは、サーバーのプレフィックスで実行します（変更していなければ `.`）。スラッシュ版のコマンドは `/channelaccess` の下にあります。

| コマンド | エイリアス | 必要な権限 | 目的 |
| --- | --- | --- | --- |
| `channelaccesssetup <#channel> [@role]` | `casetup` | Manage Roles | ゲートを作成します。ロールを省略すると直接ゲートになります |
| `channelaccessremove <#channel>` | `caremove` | Manage Roles | 質問と履歴を含めてゲートを削除します |
| `channelaccesslist` | `calist` | Nobody | しきい値、期間、ステータスとともにゲートを一覧表示します |
| `channelaccessconfig <#channel> [setting] [value]` | `caconfig` | Manage Roles | 1つの設定を変更します。設定を指定せずに実行すると一覧が表示されます |
| `channelaccesspanel <#channel> [#target]` | `capanel` | Manage Roles | 申請ボタンを投稿します。デフォルトは現在のチャンネルです |
| `channelaccessquestionadd <#channel> <question>` | `caqadd` | Manage Roles | 必須の複数行の質問を追加します |
| `channelaccessquestionremove <#channel> <position>` | `caqremove` | Manage Roles | 表示されている番号で質問を削除します |
| `channelaccessquestionlist <#channel>` | `caqlist` | Manage Roles | 質問を順番に表示します |
| `channelaccessapply <#channel>` | `caapply` | Nobody | 自分用の申請ボタンを投稿します |
| `channelaccesswithdraw <id>` | `cawithdraw` | Nobody | 自分の未処理の申請を取り下げます |
| `channelaccesshistory [@user]` | `cahistory` | Nobody | 自分の申請履歴です。他のユーザーの場合は Manage Roles が必要です |
| `channelaccesspending [#channel]` | `capending` | Nobody | 未処理の申請を一覧表示します。1つのゲートに絞ることもできます |
| `channelaccessapprove <id> [reason]` | `caapprove` | Manage Roles | 投票に関係なく承認します |
| `channelaccessdeny <id> [reason]` | `cadeny` | Manage Roles | 投票に関係なく却下します |
| `channelaccessblacklistadd <@user> [#channel]` | `cabladd` | Manage Roles | 1つのゲートからブロックします。チャンネルを指定しない場合はすべての場所でブロックします |
| `channelaccessblacklistremove <@user> [#channel]` | `cablremove` | Manage Roles | ブロックを解除します。ブロックしたときと同じチャンネルを指定してください |
| `channelaccessblacklist` | `cablacklist` | Manage Roles | ブロックされたユーザーを一覧表示します |

`channelaccessconfig` で受け付ける設定は、`enabled`、`approvals`、`denials`、`votehours`、`onexpiry`（`deny`、`majority`、`stayopen`）、`reviewchannel`、`logchannel`、`voterrole`、`pingrole`、`anonymousapplicant`、`anonymousvotes`、`allowabstain`、`minaccountage`、`minserverage`、`reapplycooldown`、`dmondecision` です。

> [!EXAMPLE]
> `caconfig #inner-circle approvals 5` の後に `caconfig #inner-circle onexpiry majority` を実行します。

## ヒントと注意点

- ボットには、ロールゲートでは Manage Roles が、直接ゲートでは Manage Channels（そのチャンネルの上書きを編集する権限付き）が必要です。ボットの最上位のロールは、アクセスロールより上にある必要があります。
- **審査チャンネル** が設定されていない場合、申請はロックされたチャンネル内に投稿されます。「メンバーが新規参加者に投票する」場合はこれで問題ありませんが、スタッフが代わりに投票する場合は別のチャンネルを設定してください。
- コマンドで追加した質問は、常に必須で複数行です。質問を任意または1行にしたり、プレースホルダーのテキストを設定したりするには、ダッシュボードを使ってください。
- ゲートを削除すると、その質問、申請、投票は完全に削除されます。
- 投票が終わる前にサーバーを退出したメンバーは、承認されていてもアクセス権が付与されません。
- 投票と期限切れの結果がDMで送られるのは、承認と却下の場合のみです。取り下げられた申請にはDMが送られません。
- ブロックされたユーザーは、ブロックしたときと同じスコープで解除する必要があります。サーバー全体のブロックは、チャンネルを指定した解除では解除されません。
