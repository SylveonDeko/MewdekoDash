## 概要

スタッフは、名前とアドレスを指定してMinecraftサーバーを1つ以上登録します。その後、どのメンバーも `mcstatus` を実行して、サーバーが稼働しているか、MOTD、バージョン、レイテンシー、オンラインのプレイヤーを確認できます。サーバーを監視することもできます。ボットはチャンネルに状態の埋め込みを投稿し、タイマーに従って編集するか、チャンネルのトピックにプレイヤー数を書き込みます。また、サーバーがダウンしたときや復旧したときに通知します。

サーバーでRCONが有効になっている場合、スタッフはゲームに参加せずに、Discordまたはダッシュボードのコンソールからコンソールコマンドを送信し、ホワイトリストを管理できます。

任意のコンパニオンプラグインを使うと、この連携は双方向の中継になります。プレイヤーのチャット、参加、退出、死亡、実績を、選択したDiscordチャンネルに投稿します。中継チャンネルに入力されたメッセージは、ゲーム内のプレイヤーに配信されます。

## 利用するメリット

- 「誰がオンラインか」のライブ埋め込みを表示し、メンバーがいつログインすればよいかをわかるようにします。
- サーバーがクラッシュしたとき、またはメンテナンス後に復旧したときに、すぐにコミュニティへ通知します。
- サーバーのコンソールを開かずに、Discordから新しいメンバーをホワイトリストに追加します。
- Discordだけのメンバーにも、ゲーム内のチャット、死亡、実績を届けます。
- 申請やレポートを処理するときに、プレイヤーのUUIDやスキンの画像を確認します。

## サーバーの種類

| 種類 | デフォルトのポート | 問い合わせ方法 |
| --- | --- | --- |
| Java Edition | 25565 | サーバーリストのping。**Query Port** を設定し、`enable-query=true` の場合は、クエリプロトコルも使われます。 |
| Bedrock Edition | 19132 | Bedrockのping |
| Geyser（Java + Bedrock） | 25565 | Javaのping。Geyserとしてマークされます。 |

各サーバーには名前があり、小文字で保存されます。最初に追加したサーバーが、引数なしの `mcstatus` で使われるデフォルトになります。プライベート、予約済み、ループバックのアドレスは、ボットのホストがそれを許可していない限り拒否されます。

## サーバーの監視

**監視チャンネル** を設定すると、ボットは **Watch Interval** の分ごとにサーバーを問い合わせます（デフォルトは5分、最小は1分）。結果に対する動作は **監視モード** によって決まります。

| モード | 動作 |
| --- | --- |
| Embed（その場で編集） | 状態の埋め込みを1つ投稿し、毎回の更新で編集します。メッセージが削除された場合は再投稿します。 |
| Channel Topic | チャンネルのトピックに短い状態の行を書き込みます。最大で5分に1回です。 |
| Both | 上記の両方を行います。 |

更新のたびに、オンラインの状態、プレイヤー数、レイテンシー、バージョンのスナップショットも記録されます。ダッシュボードの **履歴** タブで、これらの推移をグラフで確認できます。

オンラインの状態が切り替わると、ボットは監視チャンネルに通知を投稿します。デフォルトでは、緑色の「came online」または赤色の「went offline」の埋め込みです。独自の **サーバーオンライン時の通知** と **サーバーオフライン時の通知** のテンプレートを使うこともできます。

### 状態のプレースホルダー

**カスタム監視埋め込み** と両方の通知テンプレートは、埋め込みパーサーで処理され、以下のプレースホルダーに対応しています。

| プレースホルダー | 値 |
| --- | --- |
| `%mc.server.name%` | 登録された名前 |
| `%mc.server.address%` | ホスト名またはIP |
| `%mc.server.port%` | ポート |
| `%mc.online%` | `Online` または `Offline` |
| `%mc.players.online%` | 現在のプレイヤー数 |
| `%mc.players.max%` | プレイヤーの定員 |
| `%mc.player.list%` | オンラインのプレイヤー名 |
| `%mc.motd%` | 書式コードを除去したMOTD |
| `%mc.version%` | 報告されたバージョン |
| `%mc.latency%` | ping（例：`42ms`） |
| `%mc.favicon%` | サーバーアイコンのURL |
| `%mc.map%` | ワールド名（クエリプロトコルのみ） |
| `%mc.gamemode%` | ゲームモード（クエリプロトコルのみ） |
| `%mc.software%` | サーバーソフトウェア（クエリプロトコルのみ） |
| `%mc.plugins%` | プラグインの一覧（クエリプロトコルのみ） |
| `%mc.query%` | 拡張クエリに応答があった場合は `Yes` |
| `%mc.geyser%` | Geyserが検出された場合は `Yes` |

## RCONとホワイトリスト

サーバーの **RCON の設定** をオンにし、`server.properties` の **RCON ポート** と **RCON パスワード** を入力します。すると、`mcrcon` が任意のコンソールコマンドを送信し、その出力を返します。`mcwhitelist` は、ホワイトリストのコマンドを `add`、`remove`、`list`、`on`、`off`、`reload` のアクションで扱えるようにします。ダッシュボードでは、ホワイトリストが追加と削除のボタン付きの一覧で表示されます。RCONが有効なサーバーには、**コンソール** タブにコマンドの入力欄が表示されます。

> [!WARNING]
> RCONにはコンソールへの完全なアクセス権があります。`mcrcon` は管理者に限定し、パスワードは他のサーバーの認証情報と同様に扱ってください。

## コンパニオンプラグインによる中継

中継には、ゲームサーバーにMewdekoMCプラグインが必要です。Paper 1.21以降のPaperプラグイン、または21.1.xのNeoForgeモッドのどちらかで、いずれもJava 21で動作します。ダッシュボードで、サーバーの **コンパニオンプラグイン** セクションを開き、キーを生成します。**API URL** と **APIキー** を、プラグインの `config.yml`（Paper）または `config/mewdeko-server.toml`（NeoForge）にコピーし、再起動するか `/mewdeko reconnect` を実行します。キーは一度しか表示されません。置き換えるには新しいキーを生成してください。

接続されると、プラグインはWebSocketでイベントを送信し、ボットがそれらを適切なチャンネルに振り分けます。

| イベント | 投稿先 | デフォルトの見た目 |
| --- | --- | --- |
| プレイヤーの参加 | **参加 / 退出** チャンネル | プレイヤー名とアバターを含む緑色の埋め込み |
| プレイヤーの退出 | **参加 / 退出** チャンネル | プレイヤー名とアバターを含む赤色の埋め込み |
| チャット | **チャットブリッジ** チャンネル | `**player**: message` |
| 死亡 | **死亡** チャンネル | 死亡メッセージを含む灰色の埋め込み |
| 実績 | **実績** チャンネル | 実績名を含む緑色の埋め込み |
| サーバーの状態 | 投稿されません。TPSとメモリを含む履歴スナップショットとして保存されます。 | |

空のイベントチャンネルは、**監視チャンネル** にフォールバックします。Chat Bridge チャンネル（未設定の場合は監視チャンネル）に、ボット以外のユーザーが送信したメッセージは、デフォルトで `[Discord] user: message` の形式でゲームに転送されます。プラグイン自身の設定では、イベントの種類ごとにオフにできます。コンソールのストリーミングはデフォルトでオフで、ボットでは表示されません。

### 中継イベントのテンプレート

Discordに送信されるイベントごとに、**ブリッジイベントのテンプレート** の下で個別のテンプレートを設定できます。テンプレートは埋め込みビルダーの出力を受け付けます。メンションは無効化され、以下のプレースホルダーが置き換えられます。

| テンプレート | プレースホルダー |
| --- | --- |
| Player Join (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| Player Leave (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| Chat Message (Discord) | `%mc.player%`, `%mc.message%`, `%mc.avatar%` |
| Death Message (Discord) | `%mc.player%`, `%mc.death.message%`, `%mc.avatar%` |
| Advancement (Discord) | `%mc.player%`, `%mc.advancement%`, `%mc.avatar%` |
| Discordからのチャット（ゲーム内の形式） | `%user%`, `%message%`, `%channel%`。Minecraftのセクション記号による色コードを使用します。 |

## 設定

Minecraftのページには、**サーバー** タブ、**サーバーを追加** タブ、**履歴**、**コンソール** があり、さらに選択したサーバー名のタブで編集できます。

| 設定 | デフォルト | 内容 |
| --- | --- | --- |
| Name | | コマンドで使う短い識別子（例：`survival`） |
| Address | | ホスト名またはIP |
| Port | 25565 | ゲームのポート。Bedrockの場合は19132 |
| Type | Java Edition | Java、Bedrock、またはGeyser |
| Query Port (0 = game port) | 0 | 拡張クエリプロトコル用のポート |
| Watch Channel | なし | 状態の埋め込みと通知を受け取るチャンネル |
| Watch Interval (minutes) | 5 | サーバーを問い合わせる頻度 |
| Watch Mode | Embed | Embed、Channel Topic、またはBoth |
| Custom Watch Embed | デフォルトの埋め込み | 上のプレースホルダーを使った独自の状態の埋め込み |
| Server Online Alert | デフォルトの埋め込み | サーバーが復旧したときに投稿 |
| Server Offline Alert | デフォルトの埋め込み | サーバーがダウンしたときに投稿 |
| Event Channels | 監視チャンネル | Chat Bridge、Join/Leave、Deaths、Advancements |
| Bridge Event Templates | デフォルト | 上に一覧されたイベントごとのテンプレート |
| RCON Settings | オフ | 有効化トグル、RCON Port、RCON Password |
| Companion Plugin | キーなし | プラグインのAPIキーを生成または取り消し、API URLをコピー |

## セットアップの流れ

1. ダッシュボードで **Minecraft** を開き、**サーバーを追加** に移動します。
2. **名前**、**アドレス**、**ポート** を入力し、**種類** を選択して、**監視チャンネル** と **監視モード** を設定します。保存します。
3. **サーバー** タブを確認します。数秒以内に、状態のカードにサーバーがオンラインと表示されるはずです。
4. コンソールとホワイトリストへのアクセスが必要な場合は、サーバーを編集して **RCON の設定** を有効にし、**コンソール** タブを試します。
5. チャットの中継をする場合は、**Event Channels** を設定し、**コンパニオンプラグイン** でキーを生成して、ゲームサーバーにプラグインをインストールし、URLとキーをその設定に貼り付けます。
6. ゲームに参加して何か発言します。Chat Bridge チャンネルに表示され、そこでの返信がゲーム内に表示されるはずです。

## コマンド

これらのコマンドは、サーバーのプレフィックス（変更していない場合は `.`）で実行します。スラッシュコマンドは `/minecraft` にあります。

| コマンド | エイリアス | 必要な権限 | 目的 |
| --- | --- | --- | --- |
| `mcstatus [name or address]` | `mcs` | なし | デフォルトのサーバー、登録されたサーバー、または入力した `host:port` の状態 |
| `mcadd <name> <address[:port]>` | | サーバー管理 | サーバーを登録。Bedrockの場合はアドレスの前に `bedrock:` を付けます。 |
| `mcremove <name>` | `mcrm` | サーバー管理 | 登録されたサーバーを削除 |
| `mclist` | `mcl` | なし | 登録されたサーバーを、種類、デフォルトのマーカー、監視チャンネルとともに一覧表示 |
| `mcdefault <name>` | `mcdef` | サーバー管理 | `mcstatus` が使うデフォルトのサーバーを選択 |
| `mcwatch <name> [#channel]` | `mcw` | サーバー管理 | チャンネルへの状態の投稿を開始。チャンネルを指定しない場合は停止。 |
| `mcwatchmode <name> <embed, channeltopic or both>` | `mcwm` | サーバー管理 | 監視で状態をどう表示するかを選択 |
| `mcembed <name> [template]` | `mce` | サーバー管理 | 独自の状態の埋め込みを設定、または `-` でリセット |
| `mcplayer <username>` | `mcp` | なし | プレイヤーのUUID、アバター、スキンを表示 |
| `mcskin <username>` | | なし | プレイヤーのスキンの画像を表示 |
| `mcrcon <name> <command>` | | 管理者 | RCONでコンソールコマンドを実行 |
| `mcwhitelist <name> <action> [player]` | `mcwl` | サーバー管理 | `add`、`remove`、`list`、`on`、`off`、または `reload` |

## ヒントと注意点

- `mcstatus` は、Discordサーバーごとに1分あたり10回のクエリに制限されています。この制限はすべてのメンバーで共有されます。
- 登録せずに `mcstatus play.example.com:25565` のようにアドレスを直接指定しても確認できますが、プライベートアドレスとローカルアドレスはブロックされます。
- チャンネルトピックモードでは、ボットには監視チャンネルでの **チャンネルの管理** 権限が必要です。また、Discord自体がトピックの編集を制限するため、トピックモードは5分より頻繁には更新されません。
- マップ、ゲームモード、プラグインなどの詳細情報は、`server.properties` で `enable-query=true` が設定され、**Query Port** が一致している場合にのみ表示されます。
- 監視の埋め込みが削除された場合、次の更新で失敗せずに新しいものが投稿されます。
- 中継のメッセージは、`@everyone`、`@here`、ユーザーのメンションを無効化するため、プレイヤーはゲーム内からDiscordにpingを送ることができません。
