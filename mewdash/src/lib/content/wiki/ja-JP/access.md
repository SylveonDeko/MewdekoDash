## 概要

初期状態では、サーバーオーナーと管理者権限を持つメンバーだけが、ダッシュボードでサーバーを開けます。ダッシュボードアクセスを使うと、この範囲を広げられます。メンバーまたはロールを選び、利用できるダッシュボードのセクションと、各セクションを **表示**（閲覧）または **管理**（管理）のどちらにするかを選択します。その後、そのサーバーは、対象ユーザーのダッシュボードのサーバー一覧に表示され、付与したセクションが利用できるようになります。それ以外の操作は拒否されます。

チェックは、Webページだけでなく、ボットのAPI側で行われます。サーバーを指定するすべてのリクエストには、サインインしているユーザーの識別情報が含まれます。そのユーザーがオーナーまたは管理者であれば、リクエストは通ります。そうでなければ、ボットはそのリクエストが属するセクションを調べ、読み取りは **表示**、変更は **管理** として扱います。そして、ユーザーが直接、またはいずれかのロールを通じて持つ最上位の権限レベルと比較します。

サーバーオーナーは、アクセス一覧自体を誰が編集できるかも決めます。デフォルトではオーナーのみです。オーナーは特定のアクセス管理者を任命できるほか、1つのスイッチで、管理者またはサーバー管理の権限を持つ人が編集できるように変更できます。

## 利用するメリット

- コミュニティのチームが、Discordで管理者権限を持たなくても、ダッシュボードからgiveaway、提案、チケットを運用できます。
- モデレーターのロールには、Moderation と Logging に対する **管理** と、それ以外に対する **表示** を与えます。これにより、自分の管轄外の設定は閲覧だけでき、変更はできません。
- ボットのヘルパーに、XPと通貨の編集だけを許可し、セキュリティに関する設定は許可しません。
- オーナーは、オーナー専用の操作を渡さずに、アクセス一覧の管理をコオーナーのロールに委任できます。

## アクセスレベル

| レベル | 許可される操作 |
| --- | --- |
| None | そのセクションでは何もできません。セクションは付与されません。 |
| View | 読み取りのリクエストのみ。ページを開いたり、そのデータを読み込んだりできます。 |
| Manage | View で許可される操作に加え、作成、編集、削除ができます。 |

メンバーが複数の付与に一致する場合（例えば、個人への付与とロールへの付与の両方）、セクションごとに最も高いレベルが適用されます。少なくとも1つのセクションが付与されているメンバーは、ダッシュボードのサーバー切り替えでそのサーバーを見られます。どの付与も持たないメンバーには表示されません。

オーナーと管理者は、付与の設定にかかわらず、常に完全なアクセス権を持ちます。

## セクション

セクションは、ダッシュボードのサイドバーに対応しています。選択ツールの各機能は、ボットのAPIの1つ以上の領域に対応します。そのため、「Administration」を付与すると、Administration と Protection のエンドポイントの両方が対象になり、「Moderation」は Protection も対象に含みます。選択ツールはサイドバーのカテゴリごとにセクションをグループ化します。Performance のように、サーバーごとのデータではなくボット全体のインフラに関する機能は、付与できません。

付与された機能が複数の領域に対応する場合、選択ツールには、それらの領域で共通する最も低いレベルが表示されます。グループを設定すると、そのすべての領域が一度に設定されます。

## アクセス一覧を管理できる人

| 対象 | できること |
| --- | --- |
| サーバーオーナー | すべて：委任のスイッチ、管理者の一覧、すべての付与 |
| 任命されたアクセス管理者 | 付与の追加、編集、削除 |
| 管理者またはサーバー管理の権限を持つメンバー | 委任のスイッチがオンの間のみ、付与の追加、編集、削除 |
| その他すべての人 | 「You can't manage dashboard access here」と表示されます。 |

アクセス管理者は、メンバーまたはロールのいずれにもできます。管理者の一覧と委任のスイッチを見たり変更したりできるのはオーナーだけです。それ以外の人からの、これらの操作に対するAPIのリクエストは拒否されます。

> [!WARNING]
> ダッシュボードアクセスに対する **管理** は付与できません。アクセスコントローラーはセクションのチェックの対象外になっているためです。アクセス一覧を管理する権限を渡す場合は、管理者の一覧または委任のスイッチを使ってください。

## 設定

すべてダッシュボードアクセスの1つのページにあります。

| 設定 | デフォルト | 内容 |
| --- | --- | --- |
| Allow Administrators and Manage Guild members to manage dashboard access | オフ | **権限の委任設定** の下にあります。オンにすると、管理者とサーバー管理の権限を持つメンバーが付与を編集できます。オーナーのみ設定できます。 |
| Access Managers | なし | 付与を編集するために任命されたメンバーまたはロール。オーナーのみ設定できます。 |
| Access Grants | なし | メンバーまたはロールごとに1件で、セクションごとのレベルを一覧表示します。オーナーと管理者が確認できます。 |

**制限付きのアクセス権を付与** のフォームでは、対象の種類（ユーザーまたはロール）、対象、そして機能グループごとのレベルを指定します。同じ対象に対して2回目の付与を保存すると、最初の付与が置き換えられます。既存の付与を編集すると、**アクセス権を編集** と同じフォームが開きます。

## セットアップの流れ

1. サーバーオーナーとしてダッシュボードの **ダッシュボードアクセス** を開きます。
2. 誰が一覧を管理するかを決めます。**権限の委任設定** で委任のスイッチをオンにするか、**Access Managers** でメンバーまたはロールを追加します。
3. **制限付きのアクセス権を付与** で **ロール** を選び、スタッフのロールを選択します。
4. 日常的に運用する機能には **管理** を、確認だけさせたい機能には **表示** を設定します。残りは **なし** のままにします。
5. **アクセス権を付与** をクリックします。付与が **Access Grants** に表示されます。
6. そのロールを持つメンバーに、ダッシュボードへのサインインを依頼します。そのサーバーが一覧に表示され、付与されたページだけが使えるはずです。

## コマンド

ダッシュボードアクセスは、ダッシュボードからのみ設定します。対応するボットのコマンドはありません。

## ヒントと注意点

- 付与は、ボットがキャッシュしているメンバー一覧に対して確認されるため、付与が機能するには、メンバーがサーバーに参加しており、ボットから見える必要があります。
- ロールの付与は、メンバーの現在のロールに従います。ロールを削除すると、アクセスもすぐに失われます。
- すべてのセクションが **なし** に設定された付与は、付与なしとみなされて削除され、そのメンバーはサーバー切り替えからサーバーが消えます。
- 管理者は、付与の内容にかかわらず完全なアクセス権を保持します。アクセスを制限するには、まずDiscordで管理者権限を外してから、ここで必要なものを付与してください。
- ダッシュボードのプロキシは、すべてのリクエストに共有のAPIキーを付けますが、そのキーだけではサーバーへのアクセスは付与されません。サインインしているユーザーの識別情報が常に必要です。
- グローバルなコマンド一覧など、特定のサーバーに紐づかないエンドポイントは、セクションのチェックの対象外で、制限されたユーザーでも引き続き利用できます。
