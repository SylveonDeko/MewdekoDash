## 기능 소개

Switch 모듈은 Nintendo Switch 홈브루와 에뮬레이션을 다루는 서버를 위한 지원 도구 모음이에요. 누군가 `2168-0002`처럼 오류를 올리면, 도우미가 `err 2168-0002`를 실행하고 봇이 해당 오류가 속한 모듈, 알려진 정보, 그리고 해당 오류의 Nintendo 지원 페이지 링크(있는 경우)를 답해요.

`NNNN-NNNN` 형식을 코드에서 쓰는 16진수 값으로 바꾸거나, 그 반대로 바꾸는 간단한 변환기가 두 개 있어요. `switchbrew`는 switchbrew.org 위키를 검색해서 사람들이 Discord를 떠나지 않고도 SVC, 결과 코드, 하드웨어 페이지를 찾을 수 있게 해줘요.

가장 큰 기능은 Ryujinx 로그 분석기예요. 사용자가 `Ryujinx.log`를 첨부하면, 누군가 그 메시지에 `analyselog`를 실행하거나 그 메시지에 답장으로 실행해요. 그러면 봇이 게임, 에뮬레이터 버전, 하드웨어, 관련 설정 전체, 마지막 오류, 설치된 모드와 치트, 흔한 잘못된 설정을 가리키는 메모를 담은 임베드를 만들어요.

설정할 것이 없고, 저장되는 데이터도 없어요. 모든 명령어는 누구나 사용할 수 있어요.

## 사용하면 좋은 이유

- 지원 채널에 "2811-5001이 무슨 뜻이에요?"라는 질문이 매일 올라온다면 유용해요.
- Ryujinx 문제 해결은 로그를 읽는 데서 시작하는데, 대부분의 사람은 로그에서 무엇을 봐야 하는지 몰라요.
- 개발자는 오류의 16진수 형식으로 소스 코드를 검색하고 싶을 때가 있어요.
- 누구나 Discord에서 switchbrew.org 페이지를 바로 찾아볼 수 있어요.

## 오류 코드 찾아보기

`err <code>`는 두 가지 형식을 모두 받아요.

- `NNNN-NNNN`: 첫 번째 그룹이 2로 시작해야 해요(예: `2168-0002`). 모듈 번호는 첫 번째 그룹에서 2000을 뺀 값이고, 설명 번호는 두 번째 그룹이에요.
- `0x` 접두사가 붙은 16진수 값(예: `0x2A2`). 하위 9비트가 모듈이고, 나머지가 설명 번호예요.

응답에는 두 형식으로 표시된 코드, 모듈 이름과 번호, 설명 번호, 그리고 설명이 나와요. 설명은 다음 순서로 찾아요. 정확한 코드에 대해 알려진 설명, 정확한 코드에 대한 Nintendo 지원 페이지, 모듈 안에서 그 코드가 속한 범위의 설명, 마지막으로 "unknown"이에요. 알려진 코드는 일반 색상으로, 알 수 없는 코드는 오류 색상으로 표시돼요.

몇몇 코드는 이 패턴을 따르지 않아요. 예를 들어 `2-AAB6A-3400`은 짧은 목록과 정확히 일치하는지 확인하고, 해당하는 게임과 함께 알려줘요.

`err2hex <NNNN-NNNN>`은 16진수 값을 출력하고, `hex2err <hex>`는 대시 형식을 출력해요. `0x` 접두사는 생략해도 돼요.

## Switchbrew 검색

`switchbrew <query>`는 위키의 검색 API를 조회해서, 링크와 최대 200자의 발췌문이 포함된 상위 5개 결과를 보여줘요. `svc`는 별칭이므로 `svc SetThreadPriority`처럼 자연스럽게 쓸 수 있어요.

## Ryujinx 로그 분석

`analyselog`는 메시지에 첨부된 `.log` 또는 `.txt` 파일을 찾아요. 첨부 파일이 없고 메시지가 답장이라면, 답장한 메시지의 첨부 파일을 사용하고 푸터에 그 작성자를 표시해요. 임베드 제목은 게임 이름이고, 아래 내용이 들어 있어요.

| 필드 | 내용 |
| --- | --- |
| General Info | Ryujinx 버전, 펌웨어, CPU, GPU, RAM, 운영체제 |
| System Settings | 오디오 백엔드, 도킹 또는 휴대 모드, PPTC, 셰이더 캐시, VSync, 하이퍼바이저(macOS 전용) |
| Graphics Settings | 그래픽 백엔드, 해상도 배율, 이방성 필터링, 종횡비, 텍스처 재압축 |
| Errors | 로그의 마지막 오류 블록, 또는 "no errors" |
| Mods | 각 모드의 ExeFS 또는 RomFS 여부. 많으면 개수와 함께 잘라서 표시 |
| Cheats | 각 치트를 같은 방식으로 잘라서 표시 |
| Notes | 발견된 문제와 조언 |

메모에는 셰이더 캐시 충돌이나 손상, 잘못된 덤프 해시, 오래된 키, 펌웨어 누락, 파일 권한 오류, 세이브 데이터 누락, 누락된 서비스, Vulkan 메모리 부족, 기본 사용자 프로필, 설정되지 않은 컨트롤러, Vulkan을 써야 하는 Intel 또는 AMD GPU, Apple 실리콘의 Rosetta, 더미 오디오 백엔드, PPTC나 셰이더 캐시가 꺼져 있는 경우, 확장 RAM, 소프트웨어 메모리 관리자, 누락된 서비스 무시, VSync 꺼짐, 파일 시스템 무결성 검사 꺼짐, 백엔드 스레딩 꺼짐, 사용자 지정 빌드 같은 내용이 포함돼요. 각 메모에는 정보성부터 치명적까지의 심각도 표시가 붙어요.

파일을 다운로드할 수 없거나 Ryujinx 로그가 아니라면, 봇은 로그가 잘못되었다고 알려줘요.

## 설정

이 모듈에는 설정 항목이 없고 대시보드 페이지도 없어요.

## 설정 순서

1. 봇이 지원 채널의 메시지 기록을 읽고 파일을 첨부할 수 있는지 확인하세요.
2. 사용자에게 `Ryujinx.log`를 메시지에 직접 첨부해 달라고 요청하세요.
3. 도우미가 그 메시지에 답장으로 `analyselog`를 실행하세요.
4. 오류 코드는 `err <code>`를 실행하고, 지원 링크가 표시되면 공유하세요.
5. 필요하다면 이 두 명령어를 알려주는 채팅 트리거나 고정 메시지를 추가하세요.

## 명령어

명령어는 서버의 접두사(바꾸지 않았다면 `.`)와 함께 실행해요.

| 명령어 | 별칭 | 권한 | 용도 |
| --- | --- | --- | --- |
| `err <code>` | `nxerr`, `serr` | 누구나 | 대시 형식 또는 16진수 형식의 Switch 오류 코드 설명 |
| `err2hex <NNNN-NNNN>` | `e2h` | 누구나 | 대시 형식 코드를 16진수로 변환 |
| `hex2err <hex>` | `h2e` | 누구나 | 16진수를 대시 형식으로 변환 |
| `switchbrew <query>` | `sb`, `svc` | 누구나 | switchbrew.org 검색 |
| `analyselog` | `analyzelog`, `analyselogs`, `analyzelogs`, `analyze`, `analyse` | 누구나 | 첨부된 Ryujinx 로그 분석 |

## 팁과 주의 사항

- 대시 형식은 정확히 4자리 숫자, 대시, 4자리 숫자여야 하고 2로 시작해야 해요. 문자가 들어간 코드는 특수 목록으로만 처리돼요.
- 로그는 `.log` 또는 `.txt` 파일로 첨부해야 해요. 코드 블록에 붙여 넣은 로그는 읽지 않아요.
- 분석기는 파일 전체를 읽으므로, 새로 실행한 로그보다는 문제가 발생한 세션의 로그를 요청하세요.
- switchbrew.org 검색은 실시간 요청이에요. 사이트가 느리면 명령어도 느려져요.
- 멤버는 `setswitchfc`로 자신의 Switch 친구 코드를 프로필에 저장할 수 있어요. 이 기능은 User Profile 모듈에 속해요.
