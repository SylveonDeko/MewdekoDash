## What it does

스태프는 경품, 채널, 당첨자 수, 기간을 정해 이벤트를 시작해요. 봇은 해당 채널에 경품, 주최자, 종료 시간, 요구 사항을 보여 주는 임베드를 게시해요. 멤버는 이벤트를 시작한 방식에 따라 서버의 이벤트 이모지에 반응하거나, **Enter** 버튼을 누르거나, 대시보드에서 캡차를 풀어서 참여해요.

타이머가 끝나면 봇은 참여한 사람 중 요구 사항을 충족하는 사람들에게서 무작위로 당첨자를 뽑아요. 원래 메시지를 수정해 당첨자를 보여 주고, 채널에 축하 메시지를 게시하며, 설정되어 있다면 각 당첨자에게 이벤트 링크를 DM으로 보내요. 스태프는 이벤트를 조기에 끝내거나, 종료된 뒤 재추첨할 수 있어요.

요구 사항은 참여할 때가 아니라 추첨할 때 확인해요. 반응은 했지만 나중에 필요한 역할을 잃은 사람은 당첨자를 고를 때 건너뛰어요.

## Why you would use it

- 게임 키, Nitro, 굿즈를 이름을 직접 고르지 않고 활동적인 멤버에게 나눠 주고 싶을 때.
- 최소 메시지 수를 요구해서 실제로 대화에 참여한 사람에게 보상하고 싶을 때.
- 부스터나 후원자 역할을 요구해서 경품을 특정 역할에게만 주고 싶을 때.
- 캡차 참여를 사용해 부계정과 봇이 참여 수를 부풀리는 것을 막고 싶을 때.

## Entry methods

각 이벤트는 이 중 하나의 방식만 사용해요. 단계별 `gstart` 마법사가 방식을 물어보고, 슬래시 명령어에는 `use_button`과 `use_captcha` 옵션이 있으며, 대시보드에는 **참여 방식** 선택지가 있어요.

| Method | How members enter | Notes |
| --- | --- | --- |
| 반응 (Reaction) | 서버의 이벤트 이모지에 반응 | 기본값이에요. 봇은 이벤트가 끝날 때 반응 목록을 읽어요. 최대 1000명까지 읽어요. |
| 버튼 (Button) | 임베드 아래의 **Enter** 버튼 누르기 | 참여 정보는 봇이 저장해요. 두 번 참여하거나, 이벤트가 끝난 뒤에 참여하거나, 서버에 없을 때는 거부돼요. |
| 캡차 (Captcha) | **Enter (Web Captcha)**를 누르고, 대시보드에 Discord로 로그인한 뒤, Cloudflare Turnstile 확인을 통과하기 | 버튼 참여와 같은 방식으로 저장해요. 참여는 로그인한 Discord 계정에 기록돼요. |

이벤트 이모지는 `gemote`로 서버마다 설정해요. 봇은 그 이모지에 직접 반응해서 확인하므로, 다른 서버의 커스텀 이모지는 봇도 그 서버에 있을 때만 작동해요. 반응 이벤트에는 봇의 반응 추가와 외부 이모지 사용 권한도 필요하며, 권한이 없으면 `gstart`는 시작을 거부해요.

## Requirements

| Requirement | Set by | Effect at draw time |
| --- | --- | --- |
| 필요한 역할 | 마법사, 슬래시 `required_roles`, 대시보드 **필요한 역할** | 멤버는 나열된 역할을 모두 가지고 있어야 해요 |
| 필요한 메시지 수 | 마법사, 슬래시 `required_messages`, 대시보드 **필요한 메시지 수** | 멤버가 이 서버에서 집계된 메시지 수가 이 값 이상이어야 해요. 메시지 집계 서비스를 사용하므로, 집계가 켜진 뒤의 메시지만 알고 있어요. |

봇은 항상 제외되며, 서버를 나간 사람도 제외돼요. 요구 사항은 이벤트 임베드에 **필수 역할** 줄과 "N Messages Required" 줄로 표시돼요.

## The giveaway message

임베드의 제목은 경품이에요. 설명에는 "React with (emote) to enter!"가 표시되고, 주최자의 이름과 종료 시간이 상대 시간과 절대 시간 Discord 타임스탬프로 표시돼요. 푸터에는 당첨자 수, 서버 이름, 종료 날짜가 표시돼요. 메시지 내용에는 핑 역할 멘션이 있을 때 그 멘션이 들어가요.

서버 전체의 외관 설정은 다음과 같아요.

| Setting | Command | Effect |
| --- | --- | --- |
| 임베드 색상 | `gembedcolor` | 이벤트 임베드의 색상이에요. 색 이름이나 `#hex`로 지정해요 |
| 배너 | `gbanner` | 모든 이벤트에 표시되는 이미지예요. 마법사와 슬래시 명령어에서는 URL이나 첨부 파일로 이벤트마다 바꿀 수 있어요. |
| 핑 역할 | 없음, 마법사에서만 재정의 | 마법사는 역할을 핑할지 제안해요. 서버 핑 역할이 저장되어 있으면 그것을 재정의할지 물어봐요 |
| 당첨자 DM | `gdm` | 당첨자에게 DM을 보낼지 정해요. 기본값은 켜짐이에요. |

### When it ends

참여 자격이 있는 사람이 충분하면, 봇은 임베드를 "Winner: @user"로 수정하고, 주최자를 표시하고, 푸터를 "Ended at (time)"으로 바꾸고, 내용을 "**Giveaway Ended!**"로 바꿔요. 그리고 이벤트 링크와 재추첨 명령어를 보여 주는 별도의 축하 메시지를 게시해요. 아무도 참여하지 않았거나, 당첨자 수보다 참여 자격이 있는 사람이 적으면 임베드는 "There were not enough participants!"로 교체되고 이벤트는 종료로 표시돼요. 참여한 사람은 있지만 요구 사항을 충족하는 사람이 없으면 그렇게 알려 줘요.

당첨자가 한 명인 이벤트는 `GiveawayWon` 이벤트도 발생시키므로, 채팅 트리거가 당첨에 반응할 수 있어요.

### Winner DM

**당첨자 DM**을 켜 두면 각 당첨자는 DM을 받아요. 기본 메시지는 당첨 사실과 이벤트 메시지 링크가 담긴 임베드예요. 사용자 지정 종료 메시지가 저장되어 있으면 그 메시지가 대신 전송되며, 일반적인 서버, 사용자, 채널 자리표시자에 더해 다음 자리표시자를 사용할 수 있어요.

| Placeholder | Value |
| --- | --- |
| `%messagelink%` | 이벤트 메시지 링크 |
| `%giveawayitem%` | 경품 |
| `%giveawaywinners%` | 당첨자 수 |

텍스트 없이 `gdmmessage`를 실행하면 예시 값으로 저장된 메시지를 미리 볼지 물어보고, 미리 보기를 거절하면 저장된 메시지를 지워요. 텍스트와 함께 실행하면 메시지를 저장하지 않고 저장된 메시지를 지워요.

## Settings

**이벤트** 대시보드 페이지에는 세 개의 탭이 있어요. **진행 중인 이벤트**, **이벤트 만들기**, **종료된 이벤트**예요. 위의 서버 전체 설정(이모지, 색상, 배너, DM 토글)은 명령어로만 바꿀 수 있어요.

**이벤트 만들기** 양식은 다음과 같아요.

| Setting | Default | What it controls |
| --- | --- | --- |
| 이벤트 경품 | 비어 있음 | 경품이에요. 임베드 제목으로 표시돼요 |
| 당첨자 수 | 1 | 뽑을 당첨자 수예요. 최소 1명이어야 해요 |
| 채널 | 없음 | 임베드를 게시할 채널이에요 |
| 기간 | 24 hours | 이벤트가 끝나는 시점이에요 |
| 필요한 역할 | 없음 | 당첨되려면 멤버가 가지고 있어야 하는 역할이에요 |
| 필요한 메시지 수 | 0 | 집계된 최소 메시지 수예요 |
| 반응 이모지 | 파티 팝퍼 | 반응 참여에 쓰는 이모지예요. 커스텀 이모지나 붙여넣은 이모지 코드를 사용할 수 있어요 |
| 참여 방식 | 반응 | 반응, 버튼, 캡차 중 하나예요 |

**진행 중인 이벤트**에는 각 이벤트와 종료 시간이 나열돼요. 항목을 펼치면 당첨자, 채널, 필요한 역할, 메시지 요구 사항, 참여 방식이 보이고 **이벤트 종료** 버튼이 있어요. 재추첨은 명령어로만 할 수 있어요.

## Setup walkthrough

1. `gemote`로 멤버가 반응할 이모지를 설정하세요. 예: `gemote :tada:`.
2. 필요하면 `gembedcolor`와 `gbanner`를 설정해 이벤트가 서버 분위기와 어울리게 하세요.
3. 대시보드에서 **이벤트**를 열고 **이벤트 만들기**를 누르세요.
4. **이벤트 경품**, **당첨자 수**, **채널**, **기간**을 입력하세요.
5. 경품을 오래 활동한 멤버에게 주고 싶다면 **필요한 역할**이나 **필요한 메시지 수**를 추가하세요.
6. **참여 방식**을 고르고 **이벤트 만들기**를 누르세요.
7. 종료되면 채널을 확인하세요. 잘못된 사람이 당첨되었거나 당첨자가 응답하지 않으면 `greroll <message id>`를 실행하세요.

## Commands

이 명령어는 서버의 접두사로 실행하세요(변경하지 않았다면 `.`). 같은 명령어가 `/giveaways` 아래의 슬래시 명령어로도 있어요.

| Command | Aliases | Needs | Purpose |
| --- | --- | --- | --- |
| `gstart [#channel <time> <winners> <prize>]` | `giveawaystart` | 메시지 관리 | 이벤트 시작. 인자 없이 실행하면 주최자, 메시지 요구 사항, 배너, 핑 역할, 참여 방식, 필요한 역할을 묻는 마법사가 실행돼요. 시간은 `2d3h`처럼 써요. |
| `gend <message id>` | `giveawayend` | 메시지 관리 | 이벤트를 즉시 끝내고 당첨자를 뽑아요 |
| `greroll <message id>` | `giveawayreroll`, `reroll` | 메시지 관리 | 종료된 이벤트의 참여자 중에서 다시 뽑아요 |
| `glist` | `giveaways`, `giveawaylist` | 메시지 관리 | 진행 중인 이벤트의 메시지 ID, 경품, 당첨자 수, 링크를 나열해요 |
| `gstats` | `giveawaystats` | 없음 | 진행 중이거나 종료된 이벤트 합계, 주최자, 채널별 개수를 보여 줘요 |
| `gemote <emote>` | `giveawayemote` | 메시지 관리 | 반응 참여 이모지를 설정해요 |
| `gembedcolor <colour>` | `giveawayembedcolor` | 메시지 관리 | 이벤트 임베드 색상을 설정해요 |
| `gwinembedcolor <colour>` | `giveawaywinembedcolor` | 메시지 관리 | `gembedcolor`와 같은 색상 값을 설정해요 |
| `gbanner <url>` | `giveawaybanner` | 메시지 관리 | 기본 배너 이미지를 설정해요 |
| `gdm` | `giveawaydm` | 메시지 관리 | 당첨자 DM을 전환해요 |
| `gdmmessage [text]` | `gdmmsg` | 메시지 관리 | 당첨자 사용자 지정 DM을 미리 보거나 지워요 |

## Tips and gotchas

- `gend`와 `greroll`에 쓰는 메시지 ID는 이벤트 임베드의 ID예요. 개발자 모드를 켜고 복사하거나 `glist`에서 확인할 수 있어요.
- 재추첨은 같은 요구 사항으로 참여자 중에서 다시 뽑으므로, 이전 당첨자가 다시 당첨될 수도 있어요.
- 봇을 재시작하면 다음 24시간 안에 끝나는 이벤트는 바로 예약되고, 그 이후에 끝나는 이벤트는 매시간 확인하는 작업에서 처리돼요. 그래서 기간이 긴 이벤트도 제때 끝나요.
- 반응 이벤트에서 봇이 반응을 읽을 수 없으면 현재 서버 이모지로 대체하지만, 이모지가 아무도 반응하지 않은 것으로 바뀌었다면 추첨할 참여자가 없어요.
- 대시보드의 **진행 중인 이벤트** 목록에는 종료된 이벤트도 함께 표시되고, **종료된 이벤트** 탭은 현재 비어 있어요. 종료 시간과 **이벤트 종료** 버튼이 없다는 점으로 구분하세요.
- 캡차 참여에는 대시보드에 접속할 수 있어야 하고, 멤버가 Discord로 로그인해야 해요. 참여는 페이지에 입력한 내용이 아니라 그 계정에 연결돼요.
- 당첨자가 DM을 차단해 두었다면 DM은 조용히 실패해요. 채널 공지는 그대로 게시돼요.
