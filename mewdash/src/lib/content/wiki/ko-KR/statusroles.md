## 기능 설명

스태프는 `discord.gg/yourserver`나 `playing minecraft`처럼 감시할 텍스트를 하나 이상 추가해요. 봇은 프레즌스 업데이트를 감시해요. 멤버의 사용자 지정 상태에 그 텍스트가 포함되기 시작하면 봇은 **제거할 역할**에 적은 역할을 빼고, **추가할 역할**에 적은 역할을 줘요. 채널과 메시지가 설정되어 있다면 그 채널에 알림도 보내요.

상태에서 그 텍스트가 다시 사라지면 두 개의 토글이 동작을 정해요. **추가된 역할 제거**는 준 역할을 도로 빼앗아요. **제거된 역할 다시 부여**는 빼앗았던 역할을 돌려줘요. 두 토글 모두 기본으로 꺼져 있어서, 아무것도 바꾸지 않으면 멤버는 최종적으로 가진 역할을 그대로 유지해요.

사용자 지정 상태만 확인해요. Discord에서 "Set a custom status" 아래에 입력한 텍스트만 봐요. 게임, Spotify, 스트리밍 활동은 무시해요. 오프라인이거나 보이지 않음 상태인 멤버는 건너뛰어요. 일치 검사는 단순한 부분 문자열 검사라서 `mewdeko`는 `I love mewdeko`와 일치하지만 대소문자를 구분해요.

서버마다 상태 역할 항목을 원하는 만큼 둘 수 있고, 항목마다 역할, 채널, 메시지를 따로 설정할 수 있어요. 명령어는 `liststatusroles`가 보여주는 번호인 인덱스로 항목을 가리켜요.

## 사용 이유

- 서버 초대 링크를 상태에 넣은 멤버에게 후원자 역할과 혜택을 줘요.
- 누군가 상태에 "스트리밍" 또는 "플레이 구함"을 광고하는 동안 역할을 주고, 그만두면 역할을 빼요.
- 멤버가 서버를 홍보하기 시작하면 채널에 알려서 스태프가 감사 인사를 전할 수 있게 해요.
- 상태가 활성인 동안 역할을 바꿔요. 예를 들어 특정 상태일 때 "멘션 금지" 역할을 빼고 다른 역할을 주는 식이에요.

## 일치와 역할 변경

| 상황 | 봇의 동작 |
| --- | --- |
| 상태에 감시 텍스트가 새로 포함됨 | **제거할 역할**을 빼고, **추가할 역할**을 주고, 설정되어 있다면 알림을 보내요 |
| 상태에 감시 텍스트가 계속 포함됨 | 아무것도 하지 않아요. 변경은 한 번만 처리해요 |
| 상태에서 감시 텍스트가 사라짐, **추가된 역할 제거** 켜짐 | 멤버가 아직 가진 **추가할 역할**을 빼요 |
| 상태에서 감시 텍스트가 사라짐, **제거된 역할 다시 부여** 켜짐 | 멤버가 더 이상 갖고 있지 않은 **제거할 역할**을 다시 줘요 |
| 멤버가 오프라인이거나 보이지 않음 상태가 됨 | 아무것도 하지 않아요. 역할은 그대로 유지돼요 |

봇은 각 프레즌스 업데이트를 그 사용자의 마지막 캐시된 상태와 비교해요. 그래서 관련 없는 부분을 고친 멤버는 다시 처리되지 않아요. 감시 텍스트는 서버 안에서 고유해야 해요. 명령어는 128자까지만 받지만, 대시보드에는 글자 수 제한이 없어요.

## 알림 메시지

항목에 **알림 채널**과 **알림 메시지**가 모두 있으면, 멤버의 상태가 일치하기 시작할 때마다 봇이 그 채널에 메시지를 보내요. 텍스트는 임베드 파서를 거치므로 임베드 빌더가 만들 수 있는 것은 무엇이든 쓸 수 있어요. 일반 텍스트, 최대 열 개의 임베드, 컴포넌트를 포함해요. 상태가 더 이상 일치하지 않아도 아무것도 보내지 않아요.

### 플레이스홀더

메시지는 멤버, 알림 채널, 서버에 대한 표준 치환 세트를 거쳐요. 가장 유용한 플레이스홀더는 아래와 같아요. 전체 목록은 플레이스홀더 페이지의 사용자, 서버, 채널, 봇, 시간 항목에 있어요.

| 플레이스홀더 | 값 |
| --- | --- |
| `%user.mention%` | 멤버 멘션 |
| `%user.name%` | 멤버의 사용자 이름 |
| `%user.fullname%` | 태그가 포함된 사용자 이름 |
| `%user.avatar%` | 멤버 아바타 URL |
| `%user.id%` | 멤버의 사용자 ID |
| `%server.name%` | 서버 이름 |
| `%server.icon%` | 서버 아이콘 URL |
| `%channel.mention%` | 알림 채널 멘션 |
| `%server.time%` | 서버에 설정된 시간대의 현재 시간 |

> [!NOTE]
> 대시보드 편집기에는 `%status%` 플레이스홀더가 나열되어 있지만, 봇은 이를 치환하지 않아요. 상태 텍스트는 메시지에 직접 적으세요.

> [!EXAMPLE]
> `%user.mention% is now repping the server in their status, thank you!`

## 설정

모든 설정은 상태 역할 페이지에 있어요. 이 페이지에는 **상태 역할**, **새로 추가**, **통계** 세 개의 탭이 있어요. 목록의 각 항목을 펼치면 설정이 나와요.

| 설정 | 기본값 | 제어하는 내용 |
| --- | --- | --- |
| 감시할 상태 텍스트 | 없음 | 사용자 지정 상태에 포함되어야 하는 텍스트. 대시보드에는 길이 제한이 없고, 명령어로는 128자까지 가능해요 |
| 추가할 역할 | 없음 | 상태가 일치할 때 줄 역할 ID를 공백으로 구분해 입력해요. 저장하면 목록 전체가 바뀌어요 |
| 제거할 역할 | 없음 | 상태가 일치할 때 빼앗을 역할 ID를 공백으로 구분해 입력해요. 저장하면 목록 전체가 바뀌어요 |
| 알림 채널 | 없음 | 알림 메시지를 받을 채널 |
| 알림 메시지 | 없음 | 채널에 보낼 텍스트 또는 임베드. 플레이스홀더를 쓸 수 있어요 |
| 추가된 역할 제거 | 꺼짐 | 상태가 일치하지 않게 되면 추가했던 역할을 도로 빼앗아요 |
| 제거된 역할 다시 부여 | 꺼짐 | 상태가 일치하지 않게 되면 빼앗았던 역할을 돌려줘요 |

**통계** 탭에는 전체 항목 수, 역할을 바꾸는 항목 수, 알림 채널이 있는 항목 수가 표시돼요.

## 설정 순서

1. 대시보드에서 **상태 역할**을 열고 **새로 추가** 탭으로 가요.
2. 감시할 텍스트를 입력하고 **상태 역할 추가**를 눌러요.
3. **상태 역할** 탭으로 돌아가서 새 항목을 펼쳐요.
4. **설정 편집**을 누르고, **추가할 역할**과 **제거할 역할**에 역할 ID를 붙여넣어요. 원한다면 **알림 채널**을 고르고 **알림 메시지**를 작성한 뒤 **저장**을 눌러요.
5. 항목의 두 토글 버튼으로 **추가된 역할 제거**를 켜고, 필요하다면 **제거된 역할 다시 부여**도 켜요.
6. 직접 테스트해 보세요. 내 사용자 지정 상태를 감시 텍스트로 바꾸고 역할이 붙는지 확인한 뒤, 상태를 지우고 역할이 빠지는지 확인하세요.

## 명령어

서버의 접두사로 실행하세요(변경하지 않았다면 `.`). 모든 명령어에는 서버 관리 권한이 필요해요. `<index>`는 `liststatusroles`가 보여주는 번호이고 1부터 시작해요. 슬래시 명령어 버전은 `/statusroles` 아래에 있어요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `addstatusrole <text>` | `asr` | 서버 관리 | 감시할 상태 텍스트를 추가해요 |
| `removestatusrole <index>` | `rsr` | 서버 관리 | 항목을 삭제해요 |
| `liststatusroles` | `lsr` | 서버 관리 | 모든 항목을 번호와 설정과 함께 페이지별로 보여줘요 |
| `setaddroles <index> <@role...>` | `sar` | 서버 관리 | 상태가 일치할 때 줄 역할 목록에 역할을 추가해요 |
| `setremoveroles <index> <@role...>` | `srr` | 서버 관리 | 상태가 일치할 때 빼앗을 역할 목록에 역할을 추가해요 |
| `removeaddroles <index> <@role...>` | `remar` | 서버 관리 | "추가할 역할" 목록에서 역할을 빼요 |
| `removeremoveroles <index> <@role...>` | `rmremoveroles` | 서버 관리 | "제거할 역할" 목록에서 역할을 빼요 |
| `setstatusrolechannel <index> <#channel>` | `statusrolechannel`, `ssrc` | 서버 관리 | 알림 채널을 설정해요 |
| `setstatusroleembed <index> [text]` | `statusroleembed`, `asre` | 서버 관리 | 알림 메시지를 설정해요. 텍스트를 생략하면 현재 메시지를 미리 보여줘요 |
| `toggleremoveadded <index>` | `togglerma` | 서버 관리 | **추가된 역할 제거**를 전환해요 |
| `togglereaddremoved <index>` | `togglermrm` | 서버 관리 | **제거된 역할 다시 부여**를 전환해요 |

`setaddroles`와 `setremoveroles`는 기존 목록을 대체하지 않고 뒤에 추가해요. 다시 빼려면 `remove...` 명령어를 쓰세요. 대시보드 편집기는 반대로 동작해요. 저장할 때 상자에 있는 내용이 전체 목록이 되지만, 비운 상자는 무시돼요. 그래서 목록을 완전히 비우려면 `remove...` 명령어를 써야 해요.

## 팁과 주의 사항

- 봇에게 역할 관리 권한이 필요하고, 봇의 가장 높은 역할이 봇이 주거나 빼앗는 모든 역할보다 위에 있어야 해요. 실패하면 로그에만 남고 멤버에게는 아무것도 보이지 않아요.
- 봇이 사용자 지정 상태를 볼 수 있으려면 프레즌스 인텐트가 있어야 해요. 상태를 바꿔도 아무 일도 없다면 먼저 이것부터 확인하세요.
- 일치 검사는 대소문자를 구분하고, 상태 텍스트의 어느 위치에 있든 찾아요. 감시 텍스트는 짧고 뚜렷하게 유지하세요.
- 봇은 멤버 프레즌스의 첫 번째 활동만 봐요. Discord는 보통 사용자 지정 상태를 맨 앞에 나열하지만, 다른 활동이 먼저 보고되면 상태를 확인하지 못해요.
- 역할은 상태가 바뀔 때만 변경돼요. 항목을 만들 때 이미 상태에 감시 텍스트가 있던 멤버는 상태가 바뀌기 전까지 처리되지 않아요.
- 알림은 상태가 일치하기 시작할 때마다 보내져요. 그래서 상태를 계속 바꾸는 멤버에게는 알림이 반복해서 갈 수 있어요.
- 대시보드는 역할 이름이 아니라 역할 ID를 받아요. Discord에서 개발자 모드를 켜고 역할을 우클릭하면 ID를 복사할 수 있어요.
