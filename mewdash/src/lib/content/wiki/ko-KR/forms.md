## 기능 소개

스태프가 대시보드에서 양식을 만들어요. 이름, 질문 목록, 누가 답변할 수 있는지와 제출 후 어떻게 처리할지에 대한 규칙을 정하면 돼요. 게시하면 영구적인 공유 링크가 만들어져요. 멤버가 링크를 열고 디스코드로 로그인한 뒤 페이지 단위로 질문에 답하고, 답변을 검토하고, 제출해요. 입력하는 동안 진행 상황이 임시 저장되므로 나중에 이어서 작성할 수 있어요.

각 제출 내용은 선택한 채널에 임베드로 게시돼요. 결정이 필요한 양식이라면 **승인**(승인)와 **거절**(거절) 버튼이 함께 붙어요. 검토자는 디스코드에서 버튼을 누르거나 대시보드의 **응답** 탭을 사용할 수 있어요. 제출자는 결정과 메모가 담긴 DM을 받고, 언제든 상태 페이지에서 진행 상황을 확인할 수 있어요.

양식에는 세 가지 유형이 있어요. 일반 양식은 멤버용이에요. 차단 이의 신청 양식은 현재 차단된 사람을 위한 것이고, 승인하면 차단이 해제돼요. 가입 신청 양식은 서버 밖 사람을 위한 것이고, 승인하면 가입할 때 역할이 부여되는 1회용 초대가 보내져요.

양식에는 명령어가 없어요. 검토 버튼 두 개를 제외한 모든 작업은 대시보드에서 해요.

## 사용하는 이유

- 디스코드 DM으로 받던 지원서를 제대로 된 검토 큐로 관리하고 싶은 스태프, 파트너, 이벤트 지원
- 대기 기간, 시도 횟수 제한, 승인 시 자동 차단 해제가 있는 차단 이의 신청 절차
- 지원자를 검증한 뒤에만 초대를 보내는 폐쇄형 커뮤니티
- 응답 수 제한과 CSV 내보내기가 있는 피드백 설문

## 양식 유형

| 유형 | 제출할 수 있는 사람 | 승인 시 |
| --- | --- | --- |
| 일반 양식 | 멤버, 또는 **서버 밖 사용자 허용**(서버 밖 사용자 허용)를 켰다면 누구나 | 설정했다면 역할 변경만 적용 |
| 차단 이의 신청 | 현재 서버에서 차단된 사람 | 차단이 해제돼요 |
| 가입 신청 | 서버에 없는 사람 | 초대가 만들어지고, **가입할 때 부여할 역할**(가입할 때 부여할 역할)이 있다면 역할 상태로 저장되어 해당 사람이 가입할 때 적용돼요 |

양식 유형은 만든 뒤에는 바꿀 수 없어요. 차단 이의 신청과 가입 신청은 항상 검토를 거쳐요. 일반 양식은 **답변 승인 필요**(답변 승인 필요)을 켰을 때만 검토를 거쳐요.

## 질문

질문은 빌더의 **질문**(질문)에서 추가해요. 질문 유형은 다음과 같아요.

| 유형 | 답변 | 옵션 |
| --- | --- | --- |
| Short Text (단문 텍스트) | 한 줄 | 최소 및 최대 길이, 최대 5000자 |
| Long Text (장문 텍스트) | 여러 줄 | 같은 길이 제한 |
| Multiple Choice (객관식) | 제시된 옵션 중 하나 | 옵션 최대 25개 |
| Checkboxes (체크박스) | 여러 옵션 | 옵션 최대 25개. **최솟값**(최솟값)와 **최댓값**(최댓값)로 선택할 수 있는 개수를 제한해요 |
| Dropdown (드롭다운) | 목록에서 옵션 하나 | 옵션 최대 25개 |
| Number (숫자) | 숫자 | 최솟값과 최댓값 |
| Email (이메일) | 올바른 이메일 주소 | |
| URL | `http` 또는 `https` 주소 | |
| Section Break (섹션 나누기) | 없음. 새 페이지를 시작하며 제목과 소개를 넣을 수 있어요 | |

질문 텍스트는 500자, 플레이스홀더는 200자, 답변은 4000자까지 입력할 수 있어요. 각 질문에는 이미지 URL을 넣을 수 있고 필수로 표시할 수도 있어요. 질문을 특정 조건이 맞을 때만 필수로 만들 수도 있어요.

### 답변 연결

질문의 답변 연결을 켜고 질문 텍스트나 플레이스홀더에 `{{Q12}}`를 쓰면, 12는 앞에 있는 질문의 ID예요. 그 질문의 답변이 100자까지 잘려서 들어가요. 해당 질문에 답변하지 않았다면 질문 텍스트가 대괄호와 함께 표시돼요. 질문은 자신보다 위에 있는 질문의 답변만 연결할 수 있어요.

### 조건

각 질문은 조건이 충족될 때만 표시할 수 있어요. 숨겨진 질문은 페이지에서 건너뛰며, 숨겨진 질문에 대해 보낸 답변은 서버에서 버려요.

| 조건 유형 | 표시되는 경우 |
| --- | --- |
| Answer-Based (답변 기반) | 앞선 답변이 **같음**(같음), **같지 않음**(같지 않음), **포함**(포함), **보다 큼**(보다 큼), **보다 작음**(보다 작음) 중 하나에 맞을 때 |
| Role-Based (역할 기반) | 멤버가 선택한 역할 중 **하나 이상 해당**(하나 이상), **모두 해당**(모두 해당), **해당 없음**(해당 없음) 조건을 만족할 때 |
| Server Tenure (서버 참여 기간) | 멤버가 서버에 N일 이상 머물렀거나, 계정이 N일 이상 되었을 때 |
| Boost/Nitro (부스트/Nitro) | 멤버가 서버를 부스트하고 있을 때. Nitro 확인은 아바타와 부스트 데이터를 바탕으로 한 추정이에요 |
| Permission-Based (권한 기반) | 멤버가 선택한 권한을 모두 가지고 있을 때 |
| Multiple Conditions (다중 조건) | 여러 행을 조합해요. 같은 그룹의 행은 모두 참이어야 하고(AND), 그룹 중 하나라도 참이면 질문이 표시돼요(OR) |

텍스트 비교는 대소문자를 구분하지 않아요. Greater than과 Less than은 숫자를 비교해요.

## 제출 가능 여부

양식은 다음 순서로 확인하고, 이유와 함께 참여를 막을 수 있어요. 임시 저장 상태인지, 응답을 받지 않는 상태인지, **시작 시간**(시작 시간) 전인지, **마감 시간**(마감 시간)이 지났는지, 계정이 **Discord 계정 최소 기간**(Discord 계정 최소 기간)보다 짧은지, **총 접수 응답 수**(총 접수 응답 수) 제한에 도달했는지, 이미 답변했고 여러 답변이 꺼져 있는지, **제출에 필요한 역할**(제출에 필요한 역할)이 없는지, 마지막으로 위의 유형 규칙을 순서대로 확인해요.

**거절된 사람이 다시 시도하도록 허용**(거절된 사람이 다시 시도하도록 허용)을 켜면 거절된 응답은 더 이상 "이미 답변함"으로 간주되지 않아요. **캡차 필요**(캡차 필요)를 켜면 검토 단계에서 Cloudflare Turnstile 확인이 나타나요.

차단 이의 신청에는 **이의 신청 제한**(이의 신청 제한) 항목에서 추가 제한을 둘 수 있어요. 차단 후 대기 시간(차단의 감사 로그 항목 기준), 최대 이의 신청 횟수, 이의 신청 사이의 쿨다운, **한 번 거절되면 최종 결정**(한 번 거절되면 최종 결정)이 있어요. 대기 중인 이의 신청이 있으면 새로운 이의 신청을 할 수 없어요.

## 양식 작성하기

공개 페이지는 디스코드 로그인이 필요해요. 답변은 마지막 키 입력 후 약 1.5초가 지나거나 다음 페이지로 넘어갈 때 임시 저장돼요. 30일 안에 다시 들어오면 임시 저장된 내용이 복원되고, "We brought back what you had already written"(이전에 작성했던 내용을 다시 불러왔어요) 배너와 **처음부터 다시**(처음부터 다시 작성) 버튼이 표시돼요.

진행률 표시줄에서 답변한 질문의 비율을 확인할 수 있어요. 마지막 페이지에서는 **검토 후 계속**(검토 후 계속)를 누르면 모든 답변과 각 답변의 **편집**(수정) 링크가 나오고, 이어서 **확인 후 제출**(확인 후 제출)을 누르면 돼요. 제출 후에는 **제출 후 메시지**(제출 후 메시지)(또는 유형별 기본 메시지)과 **제출 상태 확인**(제출 상태 확인) 링크가 표시돼요. 상태 페이지에는 로그인한 사용자가 여러 서버에 한 익명이 아닌 응답을 모두 보여주는 **내 제출 내역**(내 제출 내역) 링크(`/forms/submissions`)도 있어요.

응답이 아직 대기 중이고 양식이 익명이 아니며 마감되지 않았다면, 제출자는 상태 페이지에서 답변을 수정할 수 있어요. 이전 답변은 수정본으로 남아요. 제출자가 응답을 철회할 방법은 없어요.

## 제출 시 동작

1. **제출 시 부여할 역할**(제출 시 부여할 역할)과 **검토 대기 중 역할**(검토 대기 중 역할)가 부여돼요.
2. **답변이 게시될 위치**(답변이 게시될 위치)를 설정했다면, 사용자(또는 "Anonymous (login required)"), 시간, 최대 20개의 답변을 보여주는 임베드가 그곳에 게시되고 **응답이 도착하면 멘션**(응답이 도착하면 멘션)에 설정한 대상이 멘션돼요. 양식을 검토할 때 승인 및 거절 버튼이 함께 붙어요.
3. **웹후크로 보내기**(웹후크로 보내기)을 설정했다면, 같은 임베드가 버튼 없이 해당 웹후크로 전송돼요. 나중에 응답이 승인되거나 거절되면, 결과와 검토자, 사유가 담긴 두 번째 메시지도 웹후크로 전송돼요. URL은 디스코드 웹후크여야 하며, 그렇지 않으면 무시되고 봇 로그에 경고가 남아요. 웹후크 전송이 실패해도 제출은 막히지 않아요.
4. 응답이 **응답** 탭에 Pending Review(검토 대기 중) 상태로 표시돼요.

익명 양식은 사용자 ID를 저장하지 않으므로 역할을 바꿀 수 없고, 응답도 수정할 수 없어요.

## 검토 과정

응답은 검토 대기 중에서 승인됨이나 거절됨으로 바뀌어요. **승인 또는 거절할 수 있는 사람**(승인 또는 거절할 수 있는 사람)에는 역할을 지정하며, 서버 관리 권한이나 관리자 권한이 있는 사람은 언제나 결정할 수 있어요. 검토자 역할을 설정하지 않았다면 승인 역할을 가진 사람도 결정할 수 있어요.

디스코드에서 **승인**(승인)를 누르면 즉시 결정돼요. **거절**(거절)를 누르면 사유를 묻는 모달이 열리며, 사유는 제출자에게 전달되므로 필수예요. 어느 쪽이든 임베드 색이 바뀌고, 검토자와 시간이 담긴 "Approved" 또는 "Rejected" 필드와 사유(있다면)가 추가되며, 버튼은 사라져요. 대시보드에서는 큐에서 **제출자에게 보낼 메모**(제출자에게 보낼 메모) 칸과 함께 같은 결정을 내릴 수 있어요.

결정이 내려지면 봇은 다음을 수행해요.

- **승인 시 추가**(승인 시 추가), **승인 시 제거**(승인 시 제거), **거절 시 추가**(거절 시 추가), **거절 시 제거**(거절 시 제거)에 설정된 역할을 추가하거나 제거하고, 검토 대기 중 역할은 항상 제거해요. 양쪽에 모두 있는 역할은 제거돼요.
- 승인된 차단 이의 신청이면 사용자의 차단을 해제하고, 승인된 가입 신청이면 초대를 만들어요.
- 제출자에게 "Your response was approved" 또는 "Your response was not accepted" 메시지와 메모, 승인 시의 **제출 후 메시지**, 초대를 DM으로 보내요. DM 전송에 실패하면 임베드와 큐에 그 사실이 표시돼요.

검토 버튼 이모지는 양식에 설정된 값을 먼저 쓰고, 없으면 **설정**(설정) 탭의 **서버 기본값**(서버 기본값)를 쓰고, 그것도 없으면 기본 체크 표시와 X 표시를 써요.

## 버전

양식을 저장할 때마다 버전이 만들어지며, 최근 20개까지 보관돼요. **버전 기록**(버전 기록)에서 각 버전을 확인할 수 있고, 설정과 질문의 차이(diff)와 **복원**(복원) 버튼이 함께 표시돼요. 복원하면 질문이 새 ID로 다시 만들어지고, 조건과 답변 연결도 그에 맞게 다시 작성돼요.

## 설정

**양식**(양식) 페이지에는 **양식**, **만들기**(만들기), **설정**(설정) 탭이 있고, 양식을 선택하면 **편집**(수정)과 **응답**(응답) 탭도 나타나요. 만들기 탭과 수정 탭은 같은 설정 패널을 공유해요.

| 설정 | 기본값 | 제어하는 내용 |
| --- | --- | --- |
| Name | 비어 있음, 필수 | 양식 제목, 최대 255자 |
| Description | 비어 있음 | 제목 아래와 디스코드 링크 미리보기에 표시 |
| Where answers are posted | 없음 | 제출 임베드를 게시할 채널. 비워 두면 답변은 대시보드에만 남아요 |
| Message after submitting | 없음 | 확인 페이지와 승인 DM의 텍스트 |

## 설정 순서

1. 대시보드에서 **양식**를 열고 **만들기**를 누르세요.
2. **양식 유형**(양식 유형)을 고르세요. 나중에는 바꿀 수 없어요.
3. **이름**과 **설명**을 입력하고, **답변이 게시될 위치**를 고르세요.
4. **질문**에서 질문을 추가하고, 필수 질문을 표시하고, 긴 양식은 **페이지 추가**(페이지 추가)로 나누세요.
5. 제출 대상을 정하고, 검토 단계가 필요하면 **답변 승인 필요**을 켜고 **승인 또는 거절할 수 있는 사람**를 고르세요.
6. **양식 저장**(양식 저장)을 누르세요. 카드의 **미리보기**(미리보기)를 사용하면 관리자로서 양식을 직접 확인할 수 있어요.
7. 카드에서 **게시**(게시)를 누른 뒤 **링크 복사**(링크 복사)로 링크를 복사해서 지원자가 찾을 수 있는 곳에 올리세요.
8. **응답** 탭이나 제출 채널을 지켜보면서 각 응답을 결정하세요.

## 명령어

양식에는 텍스트 명령어나 슬래시 명령어가 없어요. 디스코드에서 할 수 있는 유일한 상호작용은 각 제출 임베드의 **승인**와 **거절** 버튼이에요.

## 팁과 주의 사항

- 봇에는 역할 관리 권한이 필요하고, 봇의 역할은 양식이 부여하거나 제거하는 모든 역할보다 위에 있어야 해요. 봇보다 높은 역할, 관리되는 역할, everyone 역할은 조용히 건너뛰어요.
- 차단 이의 신청의 "차단 후 대기" 확인에는 감사 로그 보기 권한이 필요해요. 차단 해제에는 멤버 차단 권한이, 가입 신청 초대에는 모두에게 보이는 채널의 초대 생성 권한이 필요해요.
- 제출 임베드에는 답변이 최대 20개까지만 표시돼요. 전체 응답은 대시보드에서 확인할 수 있어요.
- **응답** 탭의 **CSV 내보내기**(CSV 내보내기)에는 질문마다 열이 하나씩 포함되며, 여러 개를 선택한 답변은 세미콜론으로 구분돼요.
- 응답 필터와 페이지는 URL에 포함되므로, "pending only"를 북마크해서 검토자와 공유할 수 있어요.
- 임시 저장 내용은 검증하지 않으므로, 복원한 임시 저장 내용도 제출 시점에 검증에 실패할 수 있어요.
- 마감된 양식은 1분마다 실행되는 검사로 닫혀요. 참여 자격은 제출 시에도 다시 확인하므로 그 사이에 빠져나가는 응답은 없어요.
