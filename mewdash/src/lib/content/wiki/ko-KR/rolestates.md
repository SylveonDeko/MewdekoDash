## 기능 소개

역할 상태를 켜면 봇이 멤버의 퇴장을 감시해요. 누군가 나가는 순간 그 시점에 가지고 있던 역할 목록을 기록해요. 나중에 그 사람이 다시 들어오면, 봇이 저장된 역할을 모두 다시 붙여 줘요. 그래서 멤버가 운영진에게 다시 인증이나 역할 부여를 요청할 필요가 없어요.

멤버 입장에서는 나갈 때 달라지는 것이 없어요. 다시 들어오면 환영 채널을 다 읽기 전에 역할이 이미 있어요.

운영진은 멤버별 저장된 역할 목록을 확인, 수정, 삭제할 수 있어요. 절대 복원하지 않을 역할을 위한 제외 목록도 있고, 기능을 켜기 전부터 서버에 있던 멤버도 포함하도록 "지금 모두 저장" 작업도 할 수 있어요.

## 이런 때 사용해요

- 실수로 나가거나 알림을 줄이려고 나간 인증된 멤버도 접근 권한을 잃지 않고 돌아와요.
- 역할 메뉴에서 고른 색상, 멘션, 취미 역할이 재가입 후에도 유지돼요.
- 수동 인증 절차가 있는 서버에서는 이미 승인된 사람을 다시 확인하지 않아도 돼요.
- 임시 음소거 역할이나 운영진 역할처럼 다시 돌아오면 안 되는 역할을 직접 골라서 제외할 수 있어요.
- 커뮤니티를 새 서버로 옮길 때, 역할 상태를 이전하고 이름이 같은 역할에 맞춰 연결할 수 있어요.

## 역할 상태가 저장되는 방식

멤버가 나갈 때 봇은 다음을 확인해요.

1. 이 서버에서 역할 상태가 켜져 있는지.
2. **봇 무시**가 꺼져 있거나, 해당 멤버가 봇이 아닌지.
3. 멤버가 **거부된 사용자** 목록에 없는지.

모두 통과하면 멤버의 현재 역할을 가져와서 `@everyone` 역할과 관리되는 역할(봇 역할, 부스터 역할, 연동 역할)을 뺀 뒤, **거부된 역할** 목록에 있는 역할을 제거해요. 남은 역할이 없으면 아무것도 저장하지 않아요. 남은 역할이 있으면 이전에 저장된 그 멤버의 목록을 대체해요.

차단은 따로 처리돼요. **차단 시 지우기**가 켜져 있으면 멤버를 차단할 때 저장된 상태가 삭제되므로, 차단 해제 후 다시 들어와도 아무것도 복원되지 않아요.

## 역할 상태가 복원되는 방식

멤버가 들어오면 봇은 다시 기능이 켜져 있는지, 봇이라면 무시 설정이 아닌지, 거부된 사용자 목록에 없는지 확인해요. 그다음 저장된 역할을 한 번의 요청으로 모두 추가해요. 존재하지 않는 역할이거나 봇의 가장 높은 역할보다 위에 있는 역할이 있으면 요청 전체가 실패하고, 그 실패는 로그에만 남아요.

> [!PERMISSION]
> 봇에는 역할 관리 권한이 있어야 하고, 봇의 가장 높은 역할이 돌려줘야 하는 모든 역할보다 위에 있어야 해요.

### 자동 지급 역할 건너뛰기

운영 모듈의 자동 지급 역할도 사용한다면, 돌아온 멤버는 보통 저장된 역할과 자동 지급 역할을 모두 받아요. **자동 지급 건너뛰기**를 켜면(`togglerolestatesskipautoassign`), 저장된 역할 상태가 있는 멤버에게는 자동 지급 역할을 건너뛰어서, 돌아온 멤버는 이전에 가졌던 역할만 받아요. 이 토글은 명령어로만 설정할 수 있고 대시보드에는 없어요.

## 저장된 상태를 직접 관리하기

멤버가 나갈 때까지 기다리지 않고, 운영진이 상태를 만들거나 수정할 수 있어요.

- `setuserrolestate`는 멤버의 저장 목록을 입력한 역할로 바꿔요. 관리되는 역할과 `@everyone`은 제외돼요.
- `addrolestorolestate`와 `removerolesfromrolestate`는 기존 저장 목록을 변경해요.
- `deleteuserrolestate`는 멤버의 상태를 완전히 잊게 해요.
- `saveallrolestates`는 현재 모든 멤버를 한꺼번에 저장해요. 자동 저장과 같은 봇 및 거부 필터를 적용해요.

대시보드에는 명령어에 없는 기능이 하나 있어요. 바로 **역할 상태 복사**예요. 한 멤버의 저장된 역할을 현재 서버에 있는 다른 멤버에게 바로 적용해요.

## 다른 서버로 옮기기

`transferrolestates <serverId>`는 현재 서버의 모든 저장된 상태를, 봇이 들어가 있는 다른 서버로 복사해요. 역할은 대소문자를 무시하고 이름으로 맞춰지고, 관리되는 역할은 건너뛰어요. 대상 서버에서 이름이 맞는 역할이 없는 멤버는 건너뛰어요. 대상 서버에서 역할 상태가 꺼져 있었다면 자동으로 켜지고, 대상 서버에 별도 설정이 없으면 원본 서버의 **봇 무시**와 **차단 시 지우기** 값을 물려받아요.

## 설정

역할 상태 페이지의 **설정** 탭에는 **일반**과 **거부 목록** 두 개의 하위 탭이 있어요.

| 설정 | 기본값 | 조정하는 내용 |
| --- | --- | --- |
| 역할 상태 | 꺼짐 | 저장과 복원을 켜거나 끄는 주 스위치 |
| 차단 시 지우기 | 꺼짐 | 멤버가 차단되면 저장된 상태 삭제 |
| 봇 무시 | 꺼짐 | 봇 계정의 역할을 저장하거나 복원하지 않아요 |
| 현재 상태 저장 | 버튼 | 지금 모든 현재 멤버의 역할을 저장해요 |
| 거부된 역할 | 없음 | 저장하지 않으므로 복원되지도 않는 역할 |
| 거부된 사용자 | 없음 | 역할을 저장하거나 복원하지 않는 멤버 |

**관리** 탭에는 **사용자 역할 관리**(선택한 역할을 멤버의 저장된 상태에 추가하거나 제거)와 **역할 상태 복사**가 있어요. **역할 상태** 탭은 저장된 모든 상태를 멤버 이름, ID, 역할과 함께 보여 주고, 항목별로 자세히 보거나 삭제할 수 있어요.

## 설정 따라 하기

1. 봇의 역할이 복원해야 하는 모든 역할보다 위에 있는지 확인하세요.
2. 대시보드에서 **역할 상태**를 열고, **설정**의 **일반**에서 **역할 상태**를 켜세요.
3. 봇 계정의 역할을 기억할 특별한 이유가 없다면 **봇 무시**를 켜 두세요.
4. **차단 시 지우기**를 정하세요. 차단 해제된 멤버가 역할을 되돌려 받기를 원하면 꺼 두세요.
5. **거부** 탭에서 운영진 역할, 제재 역할, 임시 역할을 **거부된 역할**에 추가하세요.
6. **현재 상태 저장**의 **모두 저장**을 누르면 기존 멤버도 오늘부터 보호돼요.
7. **역할 상태** 탭에서 스냅샷이 채워졌는지 확인하세요.

## 명령어

이 명령어는 서버의 접두사(바꾸지 않았다면 `.`)와 함께 실행해요. 이 모듈의 모든 명령어는 관리자 권한이 필요해요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `togglerolestates` | `trs` | 관리자 | 역할 상태 켜기 또는 끄기 |
| `viewrolestatessettings` | `vrss` | 관리자 | 현재 설정과 거부 목록 보기 |
| `viewuserrolestates` | `viewrolestates`, `vurs` | 관리자 | 저장된 모든 상태를 페이지로 보기 |
| `saveallrolestates` | `saveserverstates`, `backuprolestates` | 관리자 | 현재 모든 멤버의 스냅샷 저장 |
| `transferrolestates <serverId>` | `copyrolestates`, `moverolestates` | 관리자 | 다른 서버로 상태 복사. 이름으로 역할 맞춤 |
| `togglerolestatesignorebots` | `trsib` | 관리자 | 봇 계정 무시 토글 |
| `togglerolestatesclearonban` | `trscob` | 관리자 | 차단 시 상태 지우기 토글 |
| `togglerolestatesskipautoassign` | `trssaa`, `rsskipautoassign` | 관리자 | 저장된 상태가 있는 멤버의 자동 지급 역할 건너뛰기 토글 |
| `rolestatesadddenyrole @role...` | `rsadr` | 관리자 | 거부 목록에 역할 추가 |
| `rolestatesremovedenyrole @role...` | `rsrra` | 관리자 | 거부 목록에서 역할 제거 |
| `rolestatesadddenyuser @user...` | `rsadu` | 관리자 | 거부 목록에 멤버 추가 |
| `rolestatesremovedenyuser @user...` | `rolestatesremoveadduser`, `rsrau` | 관리자 | 거부 목록에서 멤버 제거 |
| `setuserrolestate @user @role...` | `surs` | 관리자 | 멤버의 저장된 역할 교체 |
| `addrolestorolestate @user @role...` | `arsrs` | 관리자 | 멤버의 저장된 상태에 역할 추가 |
| `removerolesfromrolestate @user @role...` | `rrfrs` | 관리자 | 멤버의 저장된 상태에서 역할 제거 |
| `deleteuserrolestate @user` | `dur` | 관리자 | 멤버의 저장된 상태 잊기 |

슬래시 명령어는 `/rolestates` 아래에 있어요.

## 팁과 주의 사항

- 기능을 켰을 때 이미 서버에 있던 멤버는, 나가거나 **모두 저장**을 실행하기 전까지 저장되지 않아요. 설정 직후 한 번 실행하세요.
- 퇴장만 저장을 실행해요. 추방도 퇴장으로 셈해요. 차단도 퇴장으로 셈하지만, **차단 시 지우기**가 켜져 있으면 상태가 다시 삭제돼요.
- 역할 복원은 역할 추가 요청 하나로 처리해요. 역할 하나가 없거나 너무 높으면 전체 복원이 조용히 실패하므로, 역할을 삭제하거나 순서를 바꿀 때 거부 목록을 최신으로 유지하세요.
- 관리되는 역할(봇 연동 역할, 부스터 역할)은 저장되지 않아요. 이 역할은 Discord가 직접 지급해요.
- `viewuserrolestates`는 한 페이지에 멤버 세 명씩 보여 줘요.
- `setuserrolestate`와 `deleteuserrolestate`는 이미 나간 사용자에게도 쓸 수 있어요. 그래서 멤버가 다시 들어오기 전에 상태를 고칠 수 있어요.
- 거부된 사용자는 자동 저장과 복원에만 영향을 줘요. 수동 명령어와 **역할 상태 복사**는 그 멤버에게도 여전히 작동해요.
