## 기능 소개

피드 URL과 채널을 봇에게 알려 주면, 그때부터 봇이 주기적으로 피드를 확인하고 마지막 확인 이후 게시된 항목을 올려요. 사이트에 새 글이 올라올 때마다 멤버는 채널에서 새 메시지를 보게 되고, 메시지에는 항목 제목, 링크, 그리고 피드가 제공하는 경우 설명과 이미지가 포함돼요.

스태프는 서버당 최대 10개의 피드를 구독할 수 있고, 피드마다 따로 메시지를 설정할 수 있어요. 메시지는 임베드 파서를 거치므로, 피드 업데이트는 일반 텍스트, 임베드, 또는 버튼이 달린 임베드가 될 수 있어요. 항목의 제목, 링크, 작성자 등을 가져오는 플레이스홀더도 쓸 수 있어요.

멤버가 따로 해야 할 일은 없어요. 채널을 읽기만 하면 돼요.

## 사용하는 이유

- 커뮤니티의 블로그, 패치 노트, 변경 로그를 공지 채널에 자동으로 올리고 싶을 때
- 뉴스 사이트나 서브레딧 피드를 토론 채널에 연결하고 싶을 때
- 유튜브 채널이나 팟캐스트를 RSS 피드로 따라가고 싶을 때
- 누군가 링크를 직접 복사하지 않아도 상태나 릴리스 피드가 계속 보이게 하고 싶을 때

## 업데이트 게시 방식

봇은 구독 중인 모든 피드 URL을 차례로 가져오고, 다음 피드를 확인하기 전까지 약 10초를 기다려요. 시작 후 처음 가져올 때는 가장 최근 항목의 날짜만 기록하고 아무것도 게시하지 않아요. 그 이후에는 마지막으로 확인한 날짜보다 게시일이 새로운 항목을 오래된 순서부터 모두 게시하고, 기록된 날짜를 앞으로 옮겨요. Atom 피드에서는 게시일이 없으면 업데이트 날짜를 사용해요. 두 날짜가 모두 없는 항목은 무시해요.

한 번의 확인에서 게시되는 항목 수에는 제한이 없어요. 그래서 날짜가 과거인 항목을 한꺼번에 20개 올리는 피드는 메시지 20개를 만들어요.

읽을 수 없는 피드는 다음 확인 때까지 조용히 건너뛰어요. 피드가 목록에서 삭제되지는 않으며, 봇은 실패를 알리지도 않아요.

### 기본 메시지

피드에 사용자 지정 메시지가 없으면 봇은 다음 내용을 담은 임베드를 보내요.

| 항목 | 값 |
| --- | --- |
| 제목 | 항목 제목, 256자까지 잘라서 표시 |
| 설명 | HTML을 제거한 항목 설명, 2048자까지 잘라서 표시 |
| URL | 항목 링크이며, 제목을 클릭할 수 있게 해요 |
| 이미지 | 피드의 이미지 첨부 파일, 또는 Atom의 `preview` 또는 `thumbnail` 요소가 있다면 그 이미지 |
| 바닥글 | 피드 URL |

### 사용자 지정 메시지와 플레이스홀더

`feedmessage` 명령어나 대시보드의 **메시지 수정**(메시지 수정) 버튼으로 사용자 지정 메시지를 설정할 수 있어요. 텍스트는 임베드 파서를 거치므로, [임베드 빌더](/wiki/embedbuilder)에서 쓸 수 있는 방식은 모두 사용할 수 있어요. 일반 텍스트, 임베드 JSON, 또는 둘 다 가능해요. 일반 텍스트 부분의 역할 멘션과 사용자 멘션은 실제로 알림을 보내요.

이 플레이스홀더는 사용자 지정 메시지에서 치환되며, 플레이스홀더 페이지에 있는 서버, 채널, 봇의 일반 플레이스홀더와 함께 사용할 수 있어요.

| 플레이스홀더 | 값 |
| --- | --- |
| `%title%` | 항목 제목 |
| `%author%` | 항목 작성자, 없으면 "Unknown" |
| `%content%` | HTML을 제거한 항목 설명 |
| `%url%` | 항목 링크 |
| `%feedurl%` | 피드 자체의 URL |
| `%image_url%` | 피드가 제공하면 항목 이미지, 없으면 피드의 이미지 |
| `%categories%` | 항목의 카테고리, 쉼표로 구분 |
| `%timestamp%` | 게시일을 디스코드 타임스탬프로 표시 |

> [!EXAMPLE]
> `feedmessage 1 New post: **%title%** by %author%
> %url%`

메시지를 `-`로 설정하면 기본 임베드로 되돌아가요.

## 설정

피드에는 서버 전체 설정이 없어요. 각 구독에는 추가할 때 고른 채널과 URL이 있고, 선택 사항으로 메시지를 설정할 수 있어요. 대시보드 페이지의 이름은 **RSS 피드**(RSS 피드)이며, 탭은 세 개예요.

| 탭 | 표시 내용 |
| --- | --- |
| RSS Feeds (RSS 피드) | 모든 구독의 채널, URL, 추가 날짜. **메시지 수정**(메시지 수정)나 **사용자 지정 메시지 추가**(사용자 지정 메시지 추가)를 누르면 텍스트 상자가 열리고, 아래에 메시지 미리보기가 표시돼요. **삭제**(삭제)는 확인 후 피드를 제거해요. |
| Add Feed (피드 추가) | **채널**(채널) 선택기와 **RSS 피드 URL**(RSS 피드 URL) 입력 상자, 그리고 **RSS 피드 추가**(RSS 피드 추가) 버튼 |
| Statistics (통계) | **전체 피드**(전체 피드), **고유 피드**(고유 피드), **채널**(채널), 그리고 **채널별 피드**(채널별 피드) 내역 |

기존 피드의 채널과 URL은 바꿀 수 없어요. 피드를 삭제하고 다시 추가하세요.

## 설정 순서

1. 대시보드에서 **피드**(피드)를 열고 **피드 추가**(피드 추가) 탭으로 이동하세요.
2. 업데이트를 보낼 **채널**(채널)을 고르세요.
3. 피드 주소를 **RSS 피드 URL**(RSS 피드 URL)에 붙여 넣고 **RSS 피드 추가**(RSS 피드 추가)를 누르세요. 사이트 홈페이지가 아니라 RSS 또는 Atom 문서의 전체 `http` 또는 `https` 주소여야 해요.
4. **RSS 피드**(RSS 피드)에서 원하는 문구가 있다면 **사용자 지정 메시지 추가**(사용자 지정 메시지 추가)를 누르고 **저장**(저장)를 누르세요.
5. 디스코드에서 `feedtest 1`을 입력해 가장 최신 항목을 게시하고 결과를 확인하세요. 숫자는 `feedlist`에서 보이는 피드의 순서예요.

## 명령어

서버의 접두사로 실행하세요(변경하지 않았다면 `.`). 모든 피드 명령어는 메시지 관리 권한이 필요해요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `feedadd <url> [#channel]` | `rss` | 메시지 관리 | 채널을 피드에 구독시켜요. 기본값은 현재 채널이에요. 봇이 먼저 피드를 가져오며, 읽을 수 없으면 거부해요. |
| `feedlist` | `feeds` | 메시지 관리 | 구독 목록을 번호와 함께 보여줘요. 페이지당 10개예요 |
| `feedremove <number>` | `feedrm`, `feeddel` | 메시지 관리 | 목록의 번호로 구독을 제거해요 |
| `feedmessage <number> <message>` | `rssmessage` | 메시지 관리 | 구독의 사용자 지정 메시지를 설정해요 |
| `rsstest <number>` | `feedtest` | 메시지 관리 | 피드의 가장 최신 항목을 현재 채널에 게시해요 |

## 팁과 주의 사항

- 서버당 피드는 최대 10개이며, 같은 URL은 두 번 추가할 수 없어요. `feedadd`는 읽을 수 없는 링크, 중복, 개수 제한 오류를 하나의 메시지로 알려 주므로, 무엇 때문인지 확실하지 않다면 `feedlist`를 확인하세요.
- 대시보드에서 피드를 추가해도 URL을 먼저 테스트하지 않아요. 봇이 피드를 읽을 수 있는지 확인하려면 나중에 `feedtest`를 사용하세요.
- `feedremove`, `feedmessage`, `feedtest`의 번호는 피드가 추가된 순서대로 정렬되는 `feedlist`에서 가져와요.
- 봇에는 대상 채널에서 메시지 보내기와 링크 임베드 권한이 필요해요. 링크 임베드 권한이 없으면 기본 임베드가 나타나지 않아요.
- 게시일(Atom은 업데이트 날짜)이 있는 항목만 게시돼요. 항목에 날짜가 없는 피드에서는 업데이트가 전혀 게시되지 않아요.
- 봇은 재시작 후 첫 확인에서 아무것도 게시하지 않아요. 그 시점의 가장 최신 항목부터 시작하므로, 봇이 꺼져 있을 때 올라온 항목은 나중에 따라잡지 않아요.
- 사용자 지정 메시지는 임베드 파서를 쓰므로, 임베드 빌더와 같은 규칙을 지켜야 해요. 유효한 JSON이거나 일반 텍스트여야 해요.
