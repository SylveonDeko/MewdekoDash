## 무엇을 하나요

스태프는 대부분의 멤버가 볼 수 없는 채널에 "게이트"를 설치해요. 멤버는 **"Apply for access"** 버튼을 누르거나 `channelaccessapply`를 실행한 뒤, 최대 다섯 개 질문으로 된 짧은 양식을 작성해요. 지원서는 검토 채널에 임베드로 올라가고, 그 메시지에는 **"Approve"**, **"Deny"**, 선택 사항인 **"Abstain"**과 **"Breakdown"** 버튼이 붙어요.

이미 채널을 볼 수 있는 멤버들이 투표해요. 찬성이 충분히 모이면 지원자는 역할을 받거나 채널에 개인 권한 덮어쓰기를 받아 입장해요. 반대가 충분히 모이거나 투표 기간이 끝나면 거절돼요. 스태프는 언제든 어느 쪽이든 결과를 강제로 정할 수 있어요.

게이트 규칙이 허용하면 지원자는 DM으로 결과를 받아요. 거절된 지원자는 다시 지원하기 전에 쿨다운을 기다려야 해요. 모든 내용은 선택 사항인 기록 채널에 남아요.

## 왜 사용하나요

- 기존 멤버가 누가 들어올지 정하는 멤버 전용 라운지나 "내부 서클".
- 소수의 믿을 수 있는 멤버가 신규 멤버를 보증하는 성인 인증 채널.
- 누군가 글을 올리기 전에 한 번 확인이 필요한 거래 또는 장터 채널.
- 스태프가 모든 지원서를 일일이 읽지 않고도 글로 된 지원서를 받고 싶은 모든 채널.

## 게이트

게이트는 채널 하나와 그 채널의 규칙을 묶은 것이에요. 채널마다 게이트는 하나만 둘 수 있어요. 역할을 지정해서 게이트를 만들면 **역할 게이트**가 되고, 역할 없이 만들면 **직접 게이트**가 돼요.

| 입장 방식 | 대시보드 표시 이름 | 접근을 주는 방법 | "안에 있는" 사람의 기준 |
| --- | --- | --- | --- |
| 역할 | 역할 지급 | 접근 역할을 지원자에게 추가해요 | 접근 역할을 가진 모든 사람 |
| 채널 권한 | 채널 권한으로 직접 추가 | 그 멤버에게 채널 보기 허용 덮어쓰기를 적어요 | 지금 그 채널을 볼 수 있는 모든 사람 |

승인된 멤버는 자동으로 제거되지 않아요. 역할을 빼거나 덮어쓰기를 직접 삭제해야 해요.

## 지원

지원서를 열기 전에 봇은 다음 순서로 확인해요. 게이트가 지원을 받는 상태인지, 멤버가 이미 접근 권한이 있는지, 차단되었는지, 계정과 서버 가입 기간이 충분한지, 이 게이트에 열린 지원서가 없는지, 재지원 쿨다운이 지났는지 확인해요. 하나라도 실패하면 이유를 알려 주는 개인 메시지가 나와요.

게이트에 질문이 있으면 질문마다 입력칸이 있는 모달이 열려요. Discord 모달 제한 때문에 질문은 45자까지예요. 답변 칸은 한 줄(200자) 또는 여러 줄(1000자)이며, 필수로 표시할 수 있어요. 질문이 없는 게이트는 바로 제출돼요.

검토 메시지는 **검토 채널**로 가고, 검토 채널을 정하지 않으면 잠긴 채널 자체에 올라가요. 메시지에는 지원자, 계정 생성일과 서버 가입일, 질문과 답변, 실시간 투표 집계, 투표 마감 시각이 있는 바닥글이 포함돼요. **투표가 끝날 때까지 지원자 숨기기**를 켜면 대기 중에는 이름 대신 "투표가 끝날 때까지 숨김"이 표시돼요.

### 상태

| 상태 | 의미 |
| --- | --- |
| 대기 중 | 열려 있고 투표 중이에요 |
| 승인됨 | 통과해서 접근 권한이 부여됐어요 |
| 거부됨 | 투표, 기간 만료 또는 스태프에 의해 거절됐어요 |
| 철회됨 | 지원자가 `channelaccesswithdraw`로 지원서를 되돌렸어요 |
| 만료됨 | 현재 만료 규칙에서는 사용하지 않아요. 기록용으로만 남아 있어요 |

## 투표

누가 투표할 수 있는지는 게이트마다 달라요. **투표 역할**을 정하면 그 역할을 가진 멤버만 투표할 수 있어요. 정하지 않으면 채널에 접근 권한이 있는 모든 사람과 역할 관리 권한이 있는 사람이 투표할 수 있어요. 지원자는 자신의 지원서에 투표할 수 없어요.

버튼을 누르면 투표가 기록돼요. 다른 버튼을 누르면 투표가 바뀌고, 같은 버튼을 다시 누르면 투표가 취소돼요. 투표할 때마다 메시지의 집계가 갱신돼요.

**찬성 필요 수**나 **반대 필요 수**에 도달하면 지원서가 바로 결정돼요. 두 값 중 하나를 0으로 두면 그쪽 결과는 사용하지 않아요. 예를 들어 **반대 필요 수**가 0인 게이트는 스태프나 기간 만료로만 거절될 수 있어요.

**"Breakdown"**은 누가 어떤 의견에 투표했는지 투표자에게만 보여줘요. **누가 어떤 의견에 투표했는지 숨기기**를 켜면 역할 관리 권한이 있는 멤버만 볼 수 있어요.

### 투표 기간이 끝났을 때

백그라운드 검사가 1분마다 **투표 기간**이 지난 지원서를 확인해요. 무슨 일이 일어날지는 게이트마다 정해요.

| 옵션 | 대시보드 표시 이름 | 결과 |
| --- | --- | --- |
| Deny | 지원 거절 | 지원서가 거절돼요. 기본값이에요. |
| Majority | 찬성과 반대 중 표가 더 많은 쪽 | 찬성이 반대보다 많으면 승인, 아니면 거절 |
| StayOpen | 스태프가 처리할 때까지 열어 두기 | 스태프가 결정하기 전까지 아무 일도 일어나지 않아요 |

**투표 기간**을 0으로 두면 시간 제한이 없어요.

## 지원 차단

스태프는 한 게이트에서 또는 서버의 모든 게이트에서 사용자를 차단할 수 있어요. 차단된 사용자가 지원하려고 하면 "이 채널에 지원할 수 없도록 차단되었어요"라는 메시지를 받아요. 차단에는 선택 사항인 사유를 남길 수 있고, 사유는 블랙리스트에 표시돼요.

## 설정

**채널 접근** 페이지에는 **게이트**, **지원서**, **차단됨** 세 개의 탭이 있어요.

**게이트** 탭은 모든 게이트를 **지원 받는 중** 토글과 함께 보여주고, 펼치면 설정, **지원 질문**, **지원 패널** 게시 기능이 나와요. 아래 기본값은 새 게이트에 적용돼요.

| 설정 | 기본값 | 역할 |
| --- | --- | --- |
| 잠긴 채널 | 필수 | 게이트를 적용할 채널 |
| 입장 방식 | 역할 지급 | 역할 게이트 또는 직접 게이트 |
| 승인 시 지급할 역할 | 없음 | 접근 역할, 역할 게이트에서 사용해요 |
| 찬성 필요 수 | 3 | 승인으로 결정되는 찬성 수, 0이면 비활성화 |
| 반대 필요 수 | 3 | 거절로 결정되는 반대 수, 0이면 비활성화 |
| 투표 기간 (시간) | 72 | 만료 규칙이 실행되기 전까지의 시간, 0이면 제한 없음 |
| 투표 기간이 끝나면 | 지원 거절 | 세 가지 만료 옵션 중 하나 |
| 검토 채널 | 잠긴 채널 자체 | 투표를 위해 지원서를 올리는 곳 |
| 기록 채널 | 기록 안 함 | 새 지원서와 결과를 기록하는 곳 |
| 투표 역할 | 접근 역할을 가진 모든 사람 | 투표를 한 역할로 제한 |
| 새 지원서에 역할 멘션 | 멘션 없음 | 지원서가 도착하면 멘션할 역할 |
| 최소 계정 기간 (일) | 0 | 이 기간보다 어린 계정을 거절 |
| 서버 가입 최소 기간 (일) | 0 | 이 기간보다 최근에 들어온 멤버를 거절 |
| 재지원 쿨다운 (시간) | 168 | 거절되거나 만료된 뒤 다시 지원하기까지의 대기 시간 |
| 기권 버튼 제공 | 켜짐 | 검토 메시지에 기권 버튼을 추가해요 |
| 투표가 끝날 때까지 지원자 숨기기 | 꺼짐 | 대기 중에는 지원자를 익명으로 표시해요 |
| 누가 어떤 의견에 투표했는지 숨기기 | 꺼짐 | 역할 관리 권한이 있는 사람에게만 상세 내역을 보여줘요 |
| 결정 시 지원자에게 DM 보내기 | 켜짐 | 결과를 DM으로 보내요 |

**지원서** 탭은 게이트와 상태로 지원서를 걸러서 보여주고, 대기 중인 지원서에는 집계와 **"Approve"**, **"Deny"** 버튼이 있어요. **차단됨** 탭은 차단된 사용자를 범위별로 보여주고, 한 게이트 또는 **모든 게이트**에서 차단하거나 사유를 함께 남길 수 있어요.

## 설정 순서

1. Discord에서 채널을 비공개로 바꾸고, 역할 게이트라면 그 채널을 볼 수 있는 역할을 만드세요.
2. 대시보드에서 **채널 접근**을 열고 **채널 지원 받기**를 사용하세요. **잠긴 채널**을 고르고, **입장 방식**을 선택한 뒤, 필요하면 역할을 고르세요.
3. 게이트를 펼쳐서 **검토 채널**을 정하세요. 지원서가 잠긴 채널에 바로 올라가지 않게 하려면 꼭 필요해요. 기록을 남기려면 **기록 채널**도 정하세요.
4. **찬성 필요 수**, **반대 필요 수**, **투표 기간**을 예상되는 투표자 수에 맞게 조정하세요.
5. **지원 질문**에서 질문을 최대 다섯 개까지 추가하세요. 필요에 따라 **필수**와 **여러 줄 답변**을 체크하세요.
6. **지원 패널**에서 버튼을 올릴 위치를 고르고 **패널 게시**를 누르세요.
7. 테스트 계정으로 지원하고, 접근 권한이 있는 멤버로 투표한 뒤, 지원자가 입장하는지 확인하세요.

## 명령어

서버의 접두사로 실행하세요. 접두사를 바꾸지 않았다면 `.`이에요. 슬래시 명령어는 `/channelaccess` 아래에 있어요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `channelaccesssetup <#channel> [@role]` | `casetup` | 역할 관리 | 게이트 만들기, 역할을 생략하면 직접 게이트 |
| `channelaccessremove <#channel>` | `caremove` | 역할 관리 | 질문과 기록을 포함해 게이트 삭제 |
| `channelaccesslist` | `calist` | 없음 | 기준값, 기간, 상태와 함께 게이트 목록 보기 |
| `channelaccessconfig <#channel> [setting] [value]` | `caconfig` | 역할 관리 | 설정 하나 변경, 설정 없이 실행하면 설정 목록 보기 |
| `channelaccesspanel <#channel> [#target]` | `capanel` | 역할 관리 | 지원 버튼 게시, 기본값은 현재 채널 |
| `channelaccessquestionadd <#channel> <question>` | `caqadd` | 역할 관리 | 필수 여러 줄 질문 추가 |
| `channelaccessquestionremove <#channel> <position>` | `caqremove` | 역할 관리 | 표시된 번호로 질문 제거 |
| `channelaccessquestionlist <#channel>` | `caqlist` | 역할 관리 | 질문을 순서대로 보기 |
| `channelaccessapply <#channel>` | `caapply` | 없음 | 본인을 위한 지원 버튼 게시 |
| `channelaccesswithdraw <id>` | `cawithdraw` | 없음 | 본인의 열린 지원서 철회 |
| `channelaccesshistory [@user]` | `cahistory` | 없음 | 본인의 지원 기록, 다른 사용자는 역할 관리 권한 필요 |
| `channelaccesspending [#channel]` | `capending` | 없음 | 열린 지원서 목록, 특정 게이트로 좁힐 수 있어요 |
| `channelaccessapprove <id> [reason]` | `caapprove` | 역할 관리 | 투표와 관계없이 승인 |
| `channelaccessdeny <id> [reason]` | `cadeny` | 역할 관리 | 투표와 관계없이 거절 |
| `channelaccessblacklistadd <@user> [#channel]` | `cabladd` | 역할 관리 | 한 게이트에서 차단, 채널을 생략하면 모든 곳에서 차단 |
| `channelaccessblacklistremove <@user> [#channel]` | `cablremove` | 역할 관리 | 차단 해제, 차단할 때 지정했던 채널을 같이 입력해야 해요 |
| `channelaccessblacklist` | `cablacklist` | 역할 관리 | 차단된 사용자 목록 |

`channelaccessconfig`가 받는 설정은 `enabled`, `approvals`, `denials`, `votehours`, `onexpiry`(`deny`, `majority`, `stayopen`), `reviewchannel`, `logchannel`, `voterrole`, `pingrole`, `anonymousapplicant`, `anonymousvotes`, `allowabstain`, `minaccountage`, `minserverage`, `reapplycooldown`, `dmondecision`이에요.

> [!EXAMPLE]
> `caconfig #inner-circle approvals 5`를 실행한 다음 `caconfig #inner-circle onexpiry majority`를 실행하세요.

## 팁과 주의 사항

- 역할 게이트에는 봇에게 역할 관리 권한이 필요하고, 직접 게이트에는 그 채널의 덮어쓰기를 편집할 수 있는 채널 관리 권한이 필요해요. 봇의 최상위 역할은 접근 역할보다 위에 있어야 해요.
- **검토 채널**을 정하지 않으면 지원서가 잠긴 채널 안에 올라가요. "멤버들이 신규 멤버를 투표한다"면 괜찮지만, 스태프가 투표해야 한다면 별도의 채널을 정하세요.
- 명령어로 추가한 질문은 항상 필수이고 여러 줄이에요. 질문을 선택 사항이나 한 줄로 바꾸거나 안내 문구를 넣으려면 대시보드를 사용하세요.
- 게이트를 삭제하면 질문, 지원서, 투표 기록이 영구적으로 사라져요.
- 투표가 끝나기 전에 서버를 떠난 멤버는 승인되었더라도 접근 권한을 받지 못해요.
- 승인과 거절 결과만 DM으로 보내요. 철회된 지원서는 DM을 받지 않아요.
