## What it does

성능은 봇을 운영하는 사람을 위한 모니터링 페이지예요. 봇 소유자에게만 보여요. 사이드바에서 다른 사용자에게는 숨겨지고, 소유자가 아닌 사용자가 URL을 직접 열면 대시보드 홈으로 돌아가요. 서버 스태프가 설정할 항목은 없어요.

이 페이지는 실행 중인 봇 프로세스의 실시간 수치를 읽어요. 한 탭은 시스템 리소스를 보여 주고, 다른 탭은 CPU 시간을 가장 많이 쓰는 메서드를 나열하며, 나머지 두 탭은 디스코드 이벤트 처리를 이벤트 유형별과 봇 모듈별로 나눠서 보여 줘요. 각 항목에는 개수, 평균 실행 시간, 오류율이 표시돼요. 페이지가 열려 있는 동안 모든 내용이 자동으로 새로 고침돼요.

이벤트와 모듈 수치는 봇의 내부 이벤트 핸들러에서 가져오며, 이 핸들러는 디스패치하는 모든 게이트웨이 이벤트를 기록해요. 메서드 시간은 추적 대상 메서드를 감싸는 성능 모니터에서 가져와요. 두 값 모두 메모리에만 있으므로 봇이 재시작되면 초기화되고, 이벤트 지표는 1시간마다 자동으로 초기화돼요. 같은 수치의 저장된 기록이 필요하다면 [분석](/wiki/analytics)을 사용하세요.

## Why you would use it

- 봇이 느려져서 CPU, 메모리, 또는 느린 메서드 하나 중 무엇이 원인인지 확인하고 싶을 때
- 모듈에서 오류가 나고 있어서 로그를 읽지 않고 모듈별 오류율을 보고 싶을 때
- 배포 후 몇 분 동안 메모리를 관찰하면서 안정적인지 확인하고 싶을 때
- 지원 문의에 필요한 가동 시간과 스레드 수를 확인해야 할 때

## Tabs

| 탭 | 섹션 | 표시 내용 | 새로 고침 |
| --- | --- | --- | --- |
| 개요 | 시스템 리소스 | **CPU 사용량**, **메모리 사용량**(사용량과 전체), **가동 시간**, **스레드 수**, 그리고 평균 시간이 포함된 **CPU 집약 메서드 상위 항목** | 5초마다 |
| 메서드 | 메서드 성능 | 추적된 모든 메서드의 **호출 수**, **평균 시간**, **총 시간**, **마지막 실행**. 모든 열로 정렬할 수 있고, 수집된 데이터를 지우는 버튼이 있어요 | 30초마다 |
| 이벤트 | 이벤트 지표 | **전체 이벤트**, **총 오류**, **이벤트 유형**, **평균 오류율**, 그리고 디스코드 이벤트 유형별 처리 수, 오류, 실행 시간, 오류율 | 10초마다 |
| 모듈 | 모듈 지표 | **활성 모듈**, **전체 이벤트**, **총 오류**, **평균 오류율**, 그리고 모듈별 처리된 이벤트, 오류, 실행 시간, 오류율 | 10초마다 |

CPU 사용량은 개요가 새로 고침될 때마다 0.5초 동안 샘플링하며, 전체 시스템이 아니라 봇 프로세스만 측정해요. 메모리는 프로세스 작업 집합(working set)이에요. 전체 메모리는 Windows와 Linux에서 호스트에서 읽고, 다른 환경에서는 0으로 표시돼요.

> [!NOTE]
> 추적된 메서드가 한 번도 실행되지 않으면 메서드 탭은 비어 있어요. 봇을 잠시 사용한 뒤 다시 확인하세요.

## Settings

설정 항목은 없어요. 할 수 있는 작업은 메서드 탭의 지우기 버튼뿐이며, 이 버튼은 메서드 시간을 지워요. 이벤트와 모듈 지표는 직접 지울 수 없고 1시간마다 초기화돼요.

## Setup walkthrough

1. 봇 소유자 계정으로 대시보드에 로그인하세요.
2. 사이드바에서 **성능**를 여세요. 소유자에게만 보여요.
3. **개요**를 1분 정도 열어 두고 CPU와 메모리가 안정되는지 보세요.
4. **모듈**로 이동해 오류 기준으로 정렬하면 문제가 있는 모듈을 찾을 수 있어요. 그다음 **이벤트**에서 가장 많이 발생하는 이벤트 유형을 확인하세요.
5. **메서드**로 느린 메서드를 찾고, 수정 후에는 지워서 다시 측정하세요.

## Commands

성능 페이지는 대시보드에서만 볼 수 있어요. 이에 해당하는 봇 모듈은 없어요. 채팅에서는 관련 소유자 명령어 몇 개를 쓸 수 있어요. 서버의 접두사로 실행하세요(변경하지 않았다면 `.`).

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `stats` | | 없음 | 봇 버전, 5초당 실행된 명령어 수, 메모리, 캐시 개수, 샤드, 가동 시간 |
| `commandstats` | `cstats` | 봇 소유자 | 가장 많이 사용된 명령어, 모듈, 서버, 사용자 |
| `shardstats` | | 봇 소유자 | 모든 샤드의 상태 |

## Tips and gotchas

- 페이지는 봇을 통해 소유자 여부를 확인해요. 한 봇 인스턴스에서는 소유자이지만 다른 인스턴스에서는 소유자가 아닌 계정은, 두 번째 인스턴스에서 대시보드 홈으로 돌아가요.
- 수치는 프로세스별이에요. 여러 프로세스에 걸쳐 샤딩된 봇에서는 대시보드가 연결된 프로세스의 수치만 보여요.
- 이 페이지의 데이터는 저장되지 않아요. 기록이 필요하면 수치를 적어 두거나 스크린샷을 찍으세요.
- 한 이벤트 유형의 오류율이 높다면, 보통 그 이벤트를 듣고 있는 모듈 때문이에요. 다음으로 모듈 탭을 확인하세요.
