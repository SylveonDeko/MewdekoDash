## 기능 설명

분석은 봇을 운영하는 사람을 위한 기록 페이지예요. 봇 소유자에게만 보여요. 사이드바에서 다른 사용자에게는 메뉴가 숨겨지고, 소유자가 아닌 사용자가 URL로 직접 들어가면 대시보드 홈으로 돌아가요. 서버 스태프가 설정할 항목은 없어요.

[성능](/wiki/performance) 페이지는 현재 프로세스 상태를 보여 주고 재시작하면 잊어버리지만, 분석은 봇이 자체 데이터베이스에 기록한 내용을 읽어요. 실행 중인 각 인스턴스는 명령어, 게이트웨이 이벤트, 샤드 지연 시간, REST 호출, 데이터베이스 소요 시간, 프로세스 게이지, 예외, 기능 사용량, AI 및 음악 활동, 대시보드 페이지 조회를 기록해요. 수치는 메모리에서 분 단위로 집계되고 1분마다 저장되며, 5분 및 1시간 단위 버킷으로 묶인 뒤 정해진 일정에 따라 정리돼요. 그래서 지난주를 보거나 지지난주와 비교하고, 인스턴스, 샤드, 서버 기준으로 필터링할 수 있어요.

주간 요약은 Discord 웹후크로 게시할 수 있고, 저장된 모든 지표에 알림 규칙을 걸어 임계값을 넘으면 웹후크로 알릴 수 있어요.

## 이런 상황에 사용해요

- 오류가 늘어난 시점이 배포 전인지 후인지 알고 싶을 때. 지금 무엇이 실패하는지만이 아니라요.
- 서버에서 봇이 느리다고 알려 와서, 특정 기간의 명령어 지연 시간, 활동, 보안 이벤트를 확인하고 싶을 때
- 서버들이 실제로 어떤 기능을 설정하고 사용하는지, 그리고 몇 달에 걸쳐 어떻게 바뀌었는지 보고 싶을 때
- 페이지를 계속 지켜보지 않고도 샤드 지연 시간, 오류율, REST 429가 한도를 넘으면 Discord 알림을 받고 싶을 때
- 채널에서 성장, 명령어, 오류, 인기 기능을 정리한 월요일 요약을 받고 싶을 때

| AI | **요청**, **입력 토큰**, **출력 토큰**, 가격이 등록된 모델의 **예상 비용**(정가 기준). 실패, 토큰, p95, 비용을 보여 주는 모델별 표, 모델별 요청, 토큰, p95. AI 채팅을 많이 사용하는 서버 상위 |
| 음악 | **플레이어**, **시작된 트랙**, **오류**. 노드별 플레이어, 소스별 시작된 트랙, 종류별 오류, 노드 상태, 이유별 종료된 트랙 |
| 웹사이트 | **페이지 조회**, **방문자**, **요청 p95**, **5xx**. 경로별 조회, 요청 소요 시간, 방문자, p95, 5xx를 보여 주는 경로별 표, 경로별 4xx 및 5xx, 로그인 → OAuth 콜백 → 대시보드로 이어지는 퍼널과 이탈 |
| 알림 | 발생 중인 그룹, 사용 설정, 테스트, 1시간 음소거, 삭제가 가능한 규칙 표. 임계값과 비교한 값 및 웹후크 전송 여부를 보여 주는 상태 변경 이벤트 기록(페이지 나눔). **새 규칙**과 **지금 요약 보내기** |
| 파이프라인 | 상태 표시, **마지막 플러시**, **마지막 롤업**, **마지막 유지 보수**, **대기 중인 계열**, **대기 중인 행**. 오류가 있으면 마지막 플러시 오류, 테이블별 행 수와 최신 행, 하트비트 및 마지막 서버 수가 있는 등록된 인스턴스, 플러시 소요 시간과 플러시당 행 수 |

파이프라인 상태는 마지막 플러시가 60초 이내이고, 마지막 롤업이 10분 이내이며, 플러시 오류가 없으면 `healthy`예요. 그렇지 않으면 `flush stale` 또는 `rollup stale`이에요. 플러시가 실패하면 `error`, 봇 설정에서 분석이 꺼져 있으면 `disabled`예요. 마지막 서버 수 갱신이 3분보다 오래된 인스턴스는 노란색으로, 10분보다 오래된 인스턴스는 빨간색으로 표시돼요.

> [!NOTE]
> 모든 시간은 UTC예요. 스냅샷, 집계 데이터, 일별 합계는 매일 밤 한 번 기록되므로, 봇이 UTC 00:05를 한 번 이상 지나 실행되기 전까지 서버 탭과 기능 탭은 비어 있어요.

### 필터 막대

탭 위의 막대는 모든 탭에 적용되며 URL에 저장돼요. 그래서 탭을 바꾸거나, 새로고침하거나, 링크를 공유해도 같은 화면이 유지돼요.

| 컨트롤 | 설명 |
| --- | --- |
| 기간 | `15m`, `1h`, `6h`, `24h`, `7d`, `30d`, 또는 최대 31일 범위의 사용자 지정 UTC 시작 및 종료 |
| 비교 | 지원하는 차트와 타일에 같은 길이의 바로 이전 기간을 겹쳐서 표시해요 |
| 봇 | 파이프라인이 알고 있는 인스턴스 중 하나, 또는 전체 |
| 샤드 | 샤드 ID 하나, 또는 전체 |
| 서버 ID | 원본 테이블과 서버 보기를 한 서버로 제한해요. Enter를 눌러 적용해요 |
| 새로고침 | 탭이 보이는 동안 30초마다 모든 내용을 다시 불러와요. 버튼을 누르면 즉시 다시 불러와요 |
| 링크 복사 | 모든 필터가 포함된 현재 URL을 복사해요 |

타일을 누르면 해당 지표의 세부 내용이 나와요. 차트에서는 작은 계열을 **기타**로 묶거나, 누적 합계를 켜거나, 범위 슬라이더로 확대하거나, 범례 항목을 오른쪽 클릭해서 하나의 계열만 단독으로 볼 수 있어요.

## 설정

페이지 자체에는 설정이 없어요. 설정할 수 있는 것은 알림 규칙과 봇 설정 키 세 개뿐이에요.

### 알림 규칙

각 규칙은 지표 하나를 감시해요. 편집기 항목은 다음과 같아요.

| 항목 | 의미 |
| --- | --- |
| 이름, 설명, 심각도, 활성화 | 라벨과 `info`, `warning`, `critical` 중 하나. 웹후크의 색상과 제목을 정해요 |
| 지표, 필터, 그룹 기준 | 저장된 모든 지표, 선택 사항인 라벨 필터, 그리고 값을 따로 평가할 선택 사항 라벨(예: `shard`별) |
| 집계, 기간 | 1분에서 1일 사이의 `sum`, `avg`, `min`, `max`, `last`, `rate`, `count`, `p50`, `p95`, `p99` |
| 비교 연산자, 임계값, 상한 | `gt`, `gte`, `lt`, `lte`, `outside`(임계값 아래 또는 상한 위), `pct_change`(같은 기간의 바로 이전 기준 대비 백분율), `deviates`(최근 N일 평균 대비 z 점수), `nodata`(기간 내 데이터 없음) |
| 기준, 방향 | `pct_change`와 `deviates`용. 어제 또는 지난주, 그리고 `up`, `down`, `both` |
| 지속 시간 | 규칙이 발동하기 전에 조건이 유지되어야 하는 시간. `immediately`를 선택하면 대기 상태를 건너뛰어요 |
| 재알림 대기 | 발동 알림 사이의 최소 간격 |
| 반복 | 발동 상태가 계속되는 동안 다시 알릴지, 한 번만 알릴지 |
| 최소 샘플 수 | 기간 내 샘플이 이보다 적으면 평가를 건너뛰어요 |
| 웹후크 URL, 멘션 역할 ID, 스레드 ID | Discord 웹후크, 발동 시 멘션할 선택 사항인 역할, 메시지를 올릴 선택 사항인 스레드 |
| 조용한 시간 시작, 종료 | 자정을 넘을 수 있는 UTC 구간이며, 이 구간에는 아무것도 보내지 않아요 |
| 복구 시 알림 | 그룹이 정상으로 돌아오면 그 사실도 게시해요 |

오른쪽의 미리보기 차트는 절대값 비교 연산자에 대해 초안 임계값을 점선 띠로 그려요.

규칙은 1분마다 평가돼요. 각 그룹은 `ok`에서 (지속 시간이 설정된 경우에만) `pending`을 거쳐 `firing`으로 바뀌고, 다시 `ok`로 돌아가요. 이벤트 기록에는 `firing`에서 `ok`로의 전환이 `resolved`로 남아요. 표에서 음소거하면 규칙이 1시간 동안 조용해져요. API로는 최대 30일까지 설정할 수 있어요. 음소거된 규칙과 조용한 시간에도 상태는 바뀌지만 메시지는 게시되지 않아요. **테스트 전송**을 누르면 규칙의 웹후크로 테스트 메시지를 보내요.

### 봇 설정 키

`bot.yml`이나 소유자 `config` 명령어로 설정해요. 모두 기본값은 켜짐, 30, 빈 값이에요.

| 키 | 의미 |
| --- | --- |
| `analyticsEnabled` | `false`이면 수집기가 아무 일도 하지 않아요. 파이프라인 탭에 `disabled`가 표시돼요 |
| `analyticsRetentionDays` | 원본 명령어 행, 페이지 조회, 서버 보안 이벤트 기록을 보관하는 일수 |
| `analyticsDigestWebhook` | 주간 요약을 게시할 Discord 웹후크. 비워 두면 요약을 보내지 않아요 |

### 보관 기간

| 데이터 | 보관 기간 |
| --- | --- |
| 1분 버킷 | 48시간 |
| 5분 버킷 | 14일 |
| 1시간 버킷 | 400일 |
| 명령어 호출, 페이지 조회, 서버 보안 이벤트 | `analyticsRetentionDays` |
| 오류 샘플, 서버별 시간당 기능 및 이벤트 활동 | 90일 |
| 알림 이벤트 | 180일 |
| 일별 스냅샷, 집계 데이터, 일별 합계 | 정리하지 않음 |

원본 행은 15초마다, 1분 버킷은 1분마다 플러시돼요. 1분 버킷은 5분마다 5분 버킷으로, 5분 버킷은 1시간 버킷으로 합쳐지고, 정리 작업은 6시간마다 실행돼요.

### 저장하지 않는 정보

- 메시지 내용. 명령어 행에는 명령어 이름, 모듈, 종류, 결과, 소요 시간과, 실패한 경우 예외 클래스 및 메시지 최대 200자만 남아요.
- 사용자 ID. 분석 데이터는 어떤 사용자가 명령어를 실행했는지로 구분되지 않아요.
- 클라이언트 IP. 페이지 조회는 IP와 사용자 에이전트를 매일 바뀌는 솔트로 해시한 방문자 해시만 남겨서, 날짜가 바뀌면 방문자를 따라갈 수 없어요. `/api/`, `/cdn/`, 정적 파일, 분석 페이지 자체에 대한 요청은 기록하지 않아요.

통계 수집을 거부한 서버와 사용자는 존중돼요. 해당 명령어는 집계에는 계속 포함되지만, 원본 행은 서버 ID와 서버 규모 없이 기록돼요.

## 설정 방법

1. 봇 소유자 계정으로 대시보드에 로그인하고 사이드바에서 **분석**을 열어요. 소유자에게만 보여요.
2. 먼저 **파이프라인**을 열어요. 상태가 `healthy`로 표시되고 모든 인스턴스의 하트비트가 최근이어야 해요. 플러시가 오래되었다면 봇이 데이터를 기록하지 않는 상태예요.
3. 기간을 고르고, 인스턴스를 여러 개 운영한다면 필터 막대에서 봇을 골라요. 이전 기간과 비교하려면 **비교**를 체크해요.
4. **알림**으로 가서 **새 규칙**을 눌러요. `shard.latency` 지표에 5분 동안 `max`, `gt`에 한도 값, `shard`별 그룹화를 선택하고, 웹후크를 붙여 넣은 다음 저장된 행에서 **테스트 전송**을 눌러요.
5. 봇 설정에서 `analyticsDigestWebhook`을 설정한 다음 **지금 요약 보내기**를 눌러 월요일 메시지가 어떻게 보일지 확인해요.
6. 하룻밤이 지난 뒤 **서버**, **기능**, 집계 추이를 확인해요.

## 명령어

분석 페이지는 대시보드 전용이라 이에 대응하는 봇 모듈은 없어요. 소유자 `config` 명령어로 위의 세 가지 키를 바꿀 수 있고, 몇 가지 소유자 명령어로 채팅에서 관련 기능을 다룰 수 있어요. 아래 명령어는 서버의 접두사로 실행하세요(변경하지 않았다면 `.`).

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `config bot analyticsEnabled false` | `conf` | 봇 소유자 | 분석 기록 중지. `true`로 다시 시작 |
| `config bot analyticsRetentionDays 14` | `conf` | 봇 소유자 | 원본 행 보관 기간 변경 |
| `config bot analyticsDigestWebhook <url>` | `conf` | 봇 소유자 | 월요일 요약을 보낼 위치 |
| `stats` | | 누구나 | 봇 버전, 5초당 실행된 명령어, 메모리, 캐시 수, 샤드, 가동 시간 |
| `commandstats` | `cstats` | 봇 소유자 | 가장 많이 쓰인 명령어, 모듈, 서버, 사용자 |
| `shardstats` | | 봇 소유자 | 모든 샤드의 상태 |

## 팁과 주의 사항

- 페이지는 봇을 통해 소유자 여부를 확인하므로, 한 봇 인스턴스에서는 소유자이지만 다른 인스턴스에서는 아닌 계정은 두 번째 인스턴스에서 리디렉션돼요.
- 요약은 월요일 오전 9시 UTC 이후에 발송되며, 지난 7일을 그 전 7일과 비교해요. 서버, 명령어, 오류, 이벤트, 새 서버와 떠난 서버, 페이지 조회, AI 토큰, 음악 트랙을 포함하고, 상위 명령어 5개, 오류 5개, 기능 5개도 함께 보여 줘요.
- 긴 기간의 시리즈는 시간 단위 버킷에서 나오므로 백분위수가 부드러워져요. 분 단위 세부 정보가 필요하면 기간을 좁히세요. 분 단위 데이터는 최근 48시간에만 있어요.
- 플러시 전에 수집기의 메모리 버퍼가 가득 차면, 해당 구간의 추가 원본 명령어 행은 버려지지만 집계는 계속 세요. 파이프라인의 **대기 중인 행** 수치가 계속 늘어나면 이 상황이에요.
- 알림 규칙에는 Discord 웹후크 URL이 필요해요. 다른 값은 저장할 때 거부돼요.
- 예상 AI 비용은 정가가 알려진 모델만 포함하므로, 합계는 최소 금액이에요.
