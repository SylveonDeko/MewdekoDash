## 기능 소개

스태프는 이름과 주소로 마인크래프트 서버를 하나 이상 등록할 수 있어요. 등록한 뒤에는 누구나 `mcstatus`를 실행해서 서버가 켜져 있는지, MOTD, 버전, 지연 시간, 접속 중인 플레이어를 확인할 수 있어요. 서버를 감시하도록 설정할 수도 있어요. 봇은 채널에 상태 임베드를 게시하고 주기적으로 수정하거나, 채널 주제에 플레이어 수를 적어요. 서버가 꺼지거나 다시 켜지면 알려줘요.

서버에 RCON이 켜져 있다면, 스태프는 게임에 접속하지 않고도 Discord나 대시보드 콘솔에서 콘솔 명령어를 보내고 화이트리스트를 관리할 수 있어요.

선택 사항인 동반 플러그인을 설치하면 양방향 브리지가 돼요. 플레이어의 채팅, 입장, 퇴장, 사망, 발전 과제가 원하는 Discord 채널에 게시되고, 브리지 채널에 입력한 메시지는 게임 안의 플레이어에게 전달돼요.

## 사용하면 좋은 이유

- "지금 누가 접속해 있는지" 실시간 임베드를 보여줘서, 멤버가 언제 접속하면 좋을지 알 수 있어요.
- 서버가 다운되거나 점검 후 다시 켜지는 순간 커뮤니티에 바로 알릴 수 있어요.
- 서버 콘솔을 열지 않고 Discord에서 새 멤버를 화이트리스트에 추가할 수 있어요.
- Discord만 쓰는 멤버도 게임 내 채팅, 사망, 발전 과제 소식을 놓치지 않아요.
- 지원서나 신고를 처리하면서 플레이어의 UUID나 스킨 이미지를 바로 확인할 수 있어요.

## 서버 유형

| 유형 | 기본 포트 | 조회 방식 |
| --- | --- | --- |
| 자바 에디션 | 25565 | 서버 목록 핑; **Query Port**가 설정되고 `enable-query=true`인 경우 쿼리 프로토콜도 사용 |
| 베드락 에디션 | 19132 | 베드락 핑 |
| Geyser (자바 + 베드락) | 25565 | Geyser로 표시된 자바 핑 |

각 서버의 이름은 소문자로 저장되며, 처음 추가한 서버가 인수 없이 실행한 `mcstatus`의 기본 서버가 돼요. 봇 호스트에서 허용하지 않은 경우 사설, 예약, 루프백 주소는 거부돼요.

## 서버 감시

**감시 채널**을 설정하면 봇이 **Watch Interval**(분) 간격으로 서버를 조회해요. 기본값은 5분이고 최소 1분이에요. 결과를 어떻게 표시할지는 **감시 모드**에 따라 달라요.

| 모드 | 동작 |
| --- | --- |
| 임베드 (제자리에서 수정) | 상태 임베드를 하나 게시하고 매 주기마다 수정해요. 메시지가 삭제되면 다시 게시해요. |
| 채널 주제 | 짧은 상태 문구를 채널 주제에 적어요. 최대 5분에 한 번만 갱신해요. |
| 둘 다 | 위의 두 가지를 모두 해요. |

매 주기마다 온라인 상태, 플레이어 수, 지연 시간, 버전의 스냅샷도 기록해요. 대시보드의 **기록** 탭에서 시간에 따른 변화를 그래프로 볼 수 있어요.

온라인 상태가 바뀌면 봇은 감시 채널에 알림을 게시해요. 기본값은 초록색 "came online" 또는 빨간색 "went offline" 임베드이고, **서버 온라인 알림**와 **서버 오프라인 알림** 템플릿으로 직접 만든 알림을 쓸 수도 있어요.

### 상태 자리표시자

**사용자 지정 감시 임베드**와 두 알림 템플릿은 임베드 파서를 거치며, 아래 자리표시자를 지원해요.

| 자리표시자 | 값 |
| --- | --- |
| `%mc.server.name%` | 등록된 이름 |
| `%mc.server.address%` | 호스트 이름 또는 IP |
| `%mc.server.port%` | 포트 |
| `%mc.online%` | `Online` 또는 `Offline` |
| `%mc.players.online%` | 현재 플레이어 수 |
| `%mc.players.max%` | 플레이어 최대 인원 |
| `%mc.player.list%` | 접속 중인 플레이어 이름 |
| `%mc.motd%` | 서식 코드를 제거한 MOTD |
| `%mc.version%` | 서버가 보고한 버전 |
| `%mc.latency%` | 핑, 예: `42ms` |
| `%mc.favicon%` | 서버 아이콘 URL |
| `%mc.map%` | 월드 이름, 쿼리 프로토콜에서만 제공 |
| `%mc.gamemode%` | 게임 모드, 쿼리 프로토콜에서만 제공 |
| `%mc.software%` | 서버 소프트웨어, 쿼리 프로토콜에서만 제공 |
| `%mc.plugins%` | 플러그인 목록, 쿼리 프로토콜에서만 제공 |
| `%mc.query%` | 확장 쿼리에 응답했다면 `Yes` |
| `%mc.geyser%` | Geyser가 감지되었다면 `Yes` |

## RCON과 화이트리스트

서버의 **RCON 설정**를 켜고 `server.properties`에 있는 **RCON 포트**와 **RCON 비밀번호**를 입력하세요. 그러면 `mcrcon`으로 콘솔 명령어를 보내고 결과를 받을 수 있어요. `mcwhitelist`는 화이트리스트 명령어를 `add`, `remove`, `list`, `on`, `off`, `reload` 동작으로 감싸요. 대시보드에서는 화이트리스트를 추가, 제거 버튼이 있는 목록으로 보여주고, RCON이 켜진 서버에서는 **콘솔** 탭에서 명령어 입력창을 쓸 수 있어요.

> [!WARNING]
> RCON은 콘솔에 대한 전체 접근 권한을 줘요. `mcrcon`은 관리자에게만 허용하고, 비밀번호는 다른 서버 자격 증명처럼 소중히 다루세요.

## 동반 플러그인 브리지

브리지를 쓰려면 게임 서버에 MewdekoMC 플러그인이 필요해요. Paper 1.21 이상용 Paper 플러그인 또는 21.1.x용 NeoForge 모드 중 하나이며, 둘 다 Java 21에서 실행돼요. 대시보드에서 서버의 **동반 플러그인** 섹션을 열고 키를 생성하세요. **API URL**과 **API 키**를 플러그인의 `config.yml`(Paper) 또는 `config/mewdeko-server.toml`(NeoForge)에 복사한 뒤, 서버를 재시작하거나 `/mewdeko reconnect`를 실행하세요. 키는 한 번만 표시되며, 교체하려면 새 키를 생성하세요.

연결되면 플러그인이 WebSocket으로 이벤트를 전송하고, 봇은 이벤트를 적절한 채널로 전달해요.

| 이벤트 | 전송 위치 | 기본 모양 |
| --- | --- | --- |
| 플레이어 입장 | **입장/퇴장** 채널 | 플레이어 이름과 아바타가 있는 초록색 임베드 |
| 플레이어 퇴장 | **입장/퇴장** 채널 | 플레이어 이름과 아바타가 있는 빨간색 임베드 |
| 채팅 | **채팅 브리지** 채널 | `**player**: message` |
| 사망 | **사망** 채널 | 사망 메시지가 있는 회색 임베드 |
| 발전 과제 | **발전 과제** 채널 | 발전 과제 이름이 있는 초록색 임베드 |
| 서버 상태 | 전송하지 않음. TPS와 메모리가 포함된 기록 스냅샷으로만 저장 | |

비어 있는 이벤트 채널은 **감시 채널**로 대체돼요. Chat Bridge 채널(설정하지 않았다면 감시 채널)에 봇이 아닌 사용자가 보낸 메시지는 기본적으로 `[Discord] user: message` 형식으로 게임에 전달돼요. 플러그인의 설정에서 이벤트 종류별로 끌 수 있고, 콘솔 스트리밍은 기본적으로 꺼져 있으며 봇에는 표시되지 않아요.

### 브리지 이벤트 템플릿

Discord로 보내는 각 이벤트는 **브리지 이벤트 템플릿**에서 템플릿을 따로 설정할 수 있어요. 템플릿은 임베드 빌더의 결과를 사용할 수 있고, 멘션은 무력화되며, 아래 자리표시자가 치환돼요.

| 템플릿 | 자리표시자 |
| --- | --- |
| 플레이어 입장 (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| 플레이어 퇴장 (Discord) | `%mc.player%`, `%mc.uuid%`, `%mc.avatar%` |
| 채팅 메시지 (Discord) | `%mc.player%`, `%mc.message%`, `%mc.avatar%` |
| 사망 메시지 (Discord) | `%mc.player%`, `%mc.death.message%`, `%mc.avatar%` |
| 발전 과제 (Discord) | `%mc.player%`, `%mc.advancement%`, `%mc.avatar%` |
| Discord의 채팅 (게임 내 형식) | `%user%`, `%message%`, `%channel%`; 마인크래프트 § 색상 코드 사용 가능 |

## 설정

마인크래프트 페이지에는 **서버** 탭, **서버 추가** 탭, **기록** 탭, **콘솔** 탭이 있고, 선택한 서버의 이름을 딴 탭에서 해당 서버를 편집해요.

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| Name | | `survival`처럼 명령어에 쓰는 짧은 식별자 |
| Address | | 호스트 이름 또는 IP |
| Port | 25565 | 게임 포트. 베드락은 19132 |
| Type | Java Edition | Java, Bedrock 또는 Geyser |
| Query Port (0 = game port) | 0 | 확장 쿼리 프로토콜용 포트 |
| Watch Channel | 없음 | 상태 임베드와 알림을 받을 채널 |
| Watch Interval (minutes) | 5 | 서버를 조회하는 주기 |
| Watch Mode | 임베드 | 임베드, 채널 주제 또는 둘 다 |
| Custom Watch Embed | 기본 임베드 | 위의 자리표시자를 쓰는 사용자 지정 상태 임베드 |
| Server Online Alert | 기본 임베드 | 서버가 다시 켜졌을 때 게시 |
| Server Offline Alert | 기본 임베드 | 서버가 꺼졌을 때 게시 |
| Event Channels | 감시 채널 | Chat Bridge, Join/Leave, Deaths, Advancements |
| Bridge Event Templates | 기본값 | 위에 나열된 이벤트별 템플릿 |
| RCON Settings | 꺼짐 | 사용 여부, RCON Port, RCON Password |
| Companion Plugin | 키 없음 | 플러그인 API 키 생성 또는 취소, API URL 복사 |

## 설정 순서

1. 대시보드에서 **Minecraft**를 열고 **서버 추가**로 이동하세요.
2. **이름**, **주소**, **포트**를 입력하고, **유형**을 고르고, **감시 채널**과 **감시 모드**를 선택한 뒤 저장하세요.
3. **서버** 탭에서 상태 카드가 몇 초 안에 서버를 온라인으로 표시하는지 확인하세요.
4. 콘솔과 화이트리스트 기능이 필요하다면 서버 편집에서 **RCON 설정**를 켜고, **콘솔** 탭에서 확인하세요.
5. 채팅 브리지를 쓰려면 **Event Channels**를 설정하고, **동반 플러그인**에서 키를 생성한 뒤, 게임 서버에 플러그인을 설치하고 URL과 키를 설정 파일에 붙여 넣으세요.
6. 게임에 접속해서 메시지를 보내 보세요. Chat Bridge 채널에 나타나야 하고, 그 채널에서 보낸 답장은 게임에 나타나야 해요.

## 명령어

명령어는 서버의 접두사(바꾸지 않았다면 `.`)와 함께 실행해요. 슬래시 명령어는 `/minecraft` 아래에 있어요.

| 명령어 | 별칭 | 권한 | 용도 |
| --- | --- | --- | --- |
| `mcstatus [name or address]` | `mcs` | 누구나 | 기본 서버, 등록된 서버, 또는 입력한 `host:port`의 상태 |
| `mcadd <name> <address[:port]>` | | 서버 관리 | 서버 등록. 베드락은 주소 앞에 `bedrock:`를 붙이세요 |
| `mcremove <name>` | `mcrm` | 서버 관리 | 등록된 서버 삭제 |
| `mclist` | `mcl` | 누구나 | 등록된 서버를 유형, 기본 서버 표시, 감시 채널과 함께 나열 |
| `mcdefault <name>` | `mcdef` | 서버 관리 | `mcstatus`가 기본으로 사용할 서버 선택 |
| `mcwatch <name> [#channel]` | `mcw` | 서버 관리 | 채널에 상태 게시를 시작하거나, 채널 없이 실행해 중지 |
| `mcwatchmode <name> <embed, channeltopic or both>` | `mcwm` | 서버 관리 | 감시 시 상태를 표시할 방식 선택 |
| `mcembed <name> [template]` | `mce` | 서버 관리 | 사용자 지정 상태 임베드 설정, `-`로 초기화 |
| `mcplayer <username>` | `mcp` | 누구나 | 플레이어의 UUID, 아바타, 스킨 표시 |
| `mcskin <username>` | | 누구나 | 플레이어의 스킨 이미지 표시 |
| `mcrcon <name> <command>` | | 관리자 | RCON으로 콘솔 명령어 실행 |
| `mcwhitelist <name> <action> [player]` | `mcwl` | 서버 관리 | `add`, `remove`, `list`, `on`, `off`, `reload` |

## 팁과 주의 사항

- `mcstatus`는 Discord 서버마다 분당 10회로 제한되며, 이 제한은 모든 멤버가 함께 사용해요.
- 등록하지 않아도 `mcstatus play.example.com:25565`처럼 주소를 직접 조회할 수 있어요. 다만 사설 주소와 로컬 주소는 차단돼요.
- 채널 주제 모드를 쓰려면 감시 채널에서 **채널 관리** 권한이 필요해요. Discord가 주제 수정 횟수를 제한하므로, 주제 모드는 5분보다 자주 갱신되지 않아요.
- 맵, 게임 모드, 플러그인 같은 자세한 정보는 `server.properties`에 `enable-query=true`가 설정되어 있고 **Query Port**가 맞을 때만 표시돼요.
- 감시 임베드가 삭제되면 다음 주기에 실패하지 않고 새 임베드를 게시해요.
- 브리지 메시지는 `@everyone`, `@here`, 사용자 멘션을 무력화하므로, 게임 안의 플레이어가 Discord를 멘션할 수 없어요.
