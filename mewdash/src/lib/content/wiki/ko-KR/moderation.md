## 기능 소개

모더레이션은 스태프가 개별 멤버에게 사용하는 도구 모음이에요. 핵심은 경고예요. 모더레이터가 `warn @user reason`을 실행하면 멤버에게 사유와 경고한 사람이 적힌 DM이 가고, 경고가 저장돼요. 서버에 경고 로그 채널이 있으면 경고 횟수와 발동한 처벌이 담긴 임베드가 그곳에 올라와요.

경고는 쌓여요. 처벌 단계를 설정해 활성 경고가 정해진 개수에 도달하면 음소거, 타임아웃, 추방, 차단, 역할 지급 중 하나가 자동으로 실행되도록 할 수 있어요. 스태프가 규칙을 일일이 기억할 필요 없이, 봇이 횟수에 도달하는 순간 바로 적용해요. 경고는 나중에 용서하거나 일정 일수가 지나면 자동으로 만료되도록 설정할 수 있어요.

그 밖에 직접 실행하는 작업도 있어요. 음소거(관리 음소거 역할 사용), 타임아웃, 추방, 소프트밴, 차단, 임시 차단, 일괄 추방, 메시지 삭제, 특수 문자로 목록 맨 위에 올라온 멤버의 닉네임 정리 등이에요. 차단 작업마다 메시지 삭제 기간을 따로 설정할 수 있어요. 차단할 때 Discord가 해당 멤버의 메시지를 며칠 치까지 함께 지울지 정하는 값이에요.

대시보드 페이지에서는 경고, 처벌 단계, 경고 로그 채널, 밴 메시지 삭제 설정을 관리할 수 있어요. 음소거, 추방, 차단 같은 직접 작업은 명령어로만 할 수 있어요.

## 이런 상황에 써 보세요

- 어떤 모더레이터가 근무하든 똑같이 적용되는 "세 번이면 제재" 정책을 만들고 싶을 때
- 채널 권한을 일일이 바꾸지 않고 멤버를 빠르게 음소거해야 할 때
- 스팸 계정을 차단하면서 마지막 하루 치 메시지만 지우고 싶을 때. 단골 멤버를 임시 차단할 때는 기록을 지우지 않도록 하고 싶을 때
- 누가, 언제, 왜 경고받았는지 기록을 남겨서 모더레이터가 바뀌어도 확인할 수 있어야 할 때
- "!!! xXx" 같은 이름이 계속 멤버 목록 맨 위로 올라와서 한 번에 정리하고 싶을 때

## 경고

`warn <user> [reason]`은 **멤버 차단** 권한이 필요해요. 봇은 먼저 서버 이름, 모더레이터, 사유가 담긴 임베드를 멤버에게 DM으로 보내려고 해요. DM을 보내지 못하면 채널의 확인 메시지 하단에 그 사실이 표시돼요. 그다음 모더레이터 이름과 사유를 함께 경고를 저장해요. 사유를 입력하지 않으면 `-`로 저장돼요.

대상 멤버는 경고를 하는 모더레이터보다, 그리고 봇보다 역할 순위가 낮아야 해요. 그렇지 않으면 명령어가 거부돼요.

`warnlog <user>`는 멤버의 경고를 한 페이지에 9개씩 나눠서 날짜, 모더레이터, 사유와 함께 보여줘요. 용서된 경고는 취소선으로 표시되고 누가 용서했는지도 나와요. `warnlogall`은 경고가 있는 모든 멤버를 `active (total - forgiven)` 형식으로 보여줘요.

`warnclear <user> [index]`는 경고를 용서 처리해요. 번호를 생략하거나 `0`을 입력하면 모든 경고를 용서해요. 번호를 입력하면 `warnlog`에 표시된 번호의 경고 하나만 용서해요. 용서된 경고는 로그에 남지만 처벌 횟수에는 더 이상 포함되지 않아요. 대시보드에서는 경고를 완전히 삭제할 수도 있어요. 삭제한 경고는 영구적으로 사라져요.

### 경고 만료

`warnexpire <days> <clear|delete>`는 경고가 유효한 기간을 설정해요. 일수는 0부터 366까지 가능하며, 0으로 설정하면 만료 기능이 꺼져요. 경고가 만료되었을 때 동작을 정할 수 있어요.

| 동작 | 설명 |
| --- | --- |
| Clear | 경고를 용서 처리하고 로그에는 남겨 둬요 |
| Delete | 데이터베이스에서 경고를 삭제해요 |

만료는 12시간마다 확인하며, 설정하는 순간에도 한 번 확인해요.

### 경고 로그 채널

`setwarnchannel #channel` 명령어로 설정하거나, 대시보드의 **처벌** 탭에서 **경고 로그 채널** 선택 메뉴로 설정할 수 있어요. 경고가 발생할 때마다 그 채널에 멤버의 이름과 ID, 현재 경고 번호, 발동한 처벌("None"이면 없음), 사유, 경고를 발급한 메시지로 이동하는 링크가 담긴 임베드가 올라와요.

## 경고 처벌

처벌 단계는 "활성 경고가 N개이면 X 실행"이라는 규칙의 목록이에요. 경고가 발급되면 봇은 새 경고를 포함한 멤버의 활성 경고 수를 세고, 그 숫자와 정확히 일치하는 규칙을 찾아요. 정확히 일치할 때만 발동하므로, 3개 규칙만 있고 4개 규칙이 없는 멤버가 어떤 경로로 4개에 도달하더라도 추가 처벌은 없어요.

규칙은 `warnpunish <number> <punishment> [time]`으로 설정해요. 역할 지급은 `warnpunish <number> addrole <role> [time]`을 사용해요. `warnpunish <number>`만 입력하면 규칙이 제거돼요. `warnpunishlist`는 처벌 단계 목록을 보여줘요.

| 처벌 | 기간 설정 | 동작 |
| --- | --- | --- |
| Mute | 선택 | 음소거 역할을 지급하고, 기간을 입력하면 기간제 음소거를 적용해요 |
| ChatMute | 선택 | 음소거 역할만 지급하고 음성 음소거는 하지 않아요 |
| VoiceMute | 선택 | 서버 음성 음소거만 적용해요 |
| Timeout | 필수, 최대 28일 | Discord 타임아웃을 적용해요 |
| Kick | 없음 | 멤버를 추방해요 |
| Softban | 없음 | 차단한 뒤 바로 차단을 해제해서 메시지를 지워요 |
| Ban | 선택 | 영구 차단하거나, 기간을 입력하면 기간제 차단을 적용해요 |
| AddRole | 선택 | 선택한 역할을 추가하고, 기간이 있으면 그 뒤에 역할을 제거해요 |
| RemoveRoles | 없음 | 멤버의 역할을 모두 제거해요 |

기간은 분 단위로 저장되며 최대 49일까지 설정할 수 있어요. Softban, Kick, RemoveRoles는 기간을 입력할 수 없어요. Timeout은 기간 없이는 저장되지 않아요. 처벌은 "Warned too many times." 사유로 실행돼요.

대시보드에서도 같은 단계를 **처벌** 탭에서 설정할 수 있어요. **경고 번호 #**, **처벌**, 선택 항목인 **기간 (분)**, 역할 지급 처벌일 때는 **추가할 역할**을 고른 뒤 **단계에 추가**를 누르면 돼요. 같은 횟수에 이미 규칙이 있으면 새 규칙으로 바뀌어요.

> [!EXAMPLE]
> `warnpunish 2 mute 1h`, `warnpunish 3 timeout 1d`, `warnpunish 5 ban`. 경고 2개면 1시간 음소거, 3개면 하루 타임아웃, 5개면 차단이에요.

## 미니 경고

경미한 위반을 주니어 스태프가 처리할 수 있도록 별도의 경고 체계인 미니 경고도 있어요. `mwarn`은 **멤버 차단** 대신 **멤버 음소거** 권한만 있으면 사용할 수 있어요. 미니 경고에는 고유한 로그(`mwarnlog`, `mwarnlogall`), 고유한 초기화 명령어, 고유한 만료 설정, 고유한 처벌 단계(`mwarnpunish`), 고유한 로그 채널(`setmwarnchannel`)이 있어요. 미니 경고는 기본 처벌 단계에 포함되지 않고, 그 반대도 마찬가지예요. 대시보드에서는 미니 경고를 보여주지 않아요.

## 음소거와 음소거 역할

봇은 음소거 역할을 관리해요. 기본 이름은 `Mewdeko-mute`예요. `muterole @role`로 바꿀 수 있고, `muterole`만 입력하면 현재 역할을 확인할 수 있어요. 음소거가 처음 필요할 때 역할이 없으면 봇이 역할을 만들고, 모든 텍스트 채널을 순회하면서 메시지 보내기, 반응 추가, 파일 첨부, 스레드에서 메시지 보내기, 공개 스레드 만들기를 거부하는 권한 덮어쓰기를 추가해요. 스레드는 건너뛰어요. 채널이 많은 서버에서는 시간이 조금 걸릴 수 있어요.

| 명령어 | 효과 |
| --- | --- |
| `mute` | 전체 음소거. 음소거 역할을 지급해요 |
| `chatmute` | 음소거 역할만 지급해요 |
| `voicemute` | 음성 채널에서만 서버 음소거를 해요 |
| `stfu` | 현재 채널에서만 해당 멤버의 메시지 보내기를 권한 덮어쓰기로 거부해요 |

모든 명령어에는 기간을 입력하는 형식도 있어요. 전체 음소거는 1분부터 90일까지, 채팅 및 음성 음소거는 1분부터 49일까지 설정할 수 있어요. 기간을 입력한 `stfu`는 시간이 지나면 덮어쓰기를 자동으로 해제해요. 음소거와 음소거 해제 시 멤버에게 DM이 가요.

`removeonmute y`를 설정하면 전체 음소거 시 멤버의 다른 역할도 제거하고 저장해 두며, `unmute`를 실행하면 역할을 되돌려줘요. `removeonmute n`으로 끌 수 있어요. `unmuteall`은 확인 메시지를 거친 뒤 음소거 역할을 가진 모든 멤버에게서 역할을 제거해요. 사유를 함께 입력할 수 있어요.

## 타임아웃

`timeout <time> <user> [reason]`은 Discord 기본 타임아웃을 최대 28일까지 적용해요. 실행하는 사람과 봇 모두 **멤버 타임아웃 주기** 권한이 필요해요. `untimeout <user>`로 해제할 수 있어요. 입력한 사유는 감사 로그에 `moderator | reason` 형식으로 기록돼요.

## 차단, 추방, 소프트밴

`ban <user> [reason]`은 차단하기 전에 먼저 멤버에게 DM을 보내요. `ban <time> <user> [reason]`은 기간이 지나면 자동으로 풀리는 임시 차단이며, 최대 49일까지 설정할 수 있어요. `ban <pruneTime> <time> <user>`는 메시지 삭제 기간과 차단 기간을 함께 지정해요. 서버에 없는 사람도 ID로 차단할 수 있어요. `unban <user or id>`로 차단을 해제해요.

`softban <user> [reason]`은 차단한 뒤 바로 차단을 해제해요. 최근 메시지를 함께 지우는 추방과 같아요. `kick <user> [reason]`은 추방하고, `masskick @a @b @c`는 여러 명을 한 번에 추방한 뒤 성공한 수를 알려줘요. `masskill`은 봇 소유자만 사용할 수 있으며, 붙여넣은 ID 목록을 일괄 차단해요.

### 차단 DM

차단된 멤버에게 가는 메시지는 `banmessage <text or embed code>`로 바꿀 수 있어요. 입력한 텍스트는 임베드 파서를 거치므로 임베드 빌더의 기능을 모두 쓸 수 있어요. `-`로 설정하면 DM을 보내지 않으며, `banmsgreset`으로 기본 메시지로 되돌릴 수 있어요. `banmsgtest [duration] [reason]`은 현재 템플릿을 나에게 DM으로 보내 미리 볼 수 있게 해요.

| 플레이스홀더 | 값 |
| --- | --- |
| `%ban.mod%` | 모더레이터의 전체 이름 |
| `%ban.mod.name%` | 모더레이터의 사용자 이름 |
| `%ban.user%` | 차단된 멤버의 전체 이름 |
| `%ban.user.name%` | 차단된 멤버의 사용자 이름 |
| `%ban.reason%` 또는 `%reason%` | 사유. 없으면 `-` |
| `%ban.duration%` | `d.hh:mm` 형식의 기간, 또는 `perma` |

`%server.name%` 같은 서버 플레이스홀더도 사용할 수 있어요.

## 밴 메시지 삭제

차단할 때마다 메시지 삭제 값이 함께 적용돼요. Discord가 차단과 함께 멤버 메시지를 며칠 치까지 지울지를 정하는 값이며, 0부터 7까지 설정할 수 있어요. 모든 차단에 같은 값을 쓰는 대신, 차단 종류마다 기본값이 따로 있어요. 서버 전체, 카테고리, 채널 단위로 원하는 값을 덮어쓸 수 있어요.

| 작업 | 키 | 기본 제공 기본값 |
| --- | --- | --- |
| 차단 | `ban` | 7일 |
| ID로 차단 | `hackban` | 7일 |
| 임시 차단 | `tempban` | 없음 |
| 소프트밴 | `softban` | 7일 |
| 일괄 차단 | `massban` | 7일 |
| 아바타 해시로 차단 | `banbyhash` | 없음 |
| 역할로 차단 | `baninrole` | 없음 |
| 나이 미만 차단 | `banunder` | 없음 |
| 경고 처벌 | `warnpunish` | 없음 |
| 자동 차단 역할 | `autobanrole` | 없음 |
| 역할 모니터 | `rolemonitor` | 없음 |
| 필터 | `filter` | 없음 |
| 봉쇄 | `lockdown` | 없음 |
| 대시보드 | `dashboard` | 없음 |

차단이 발생하면 봇은 가장 구체적인 설정을 찾아요. 명령어를 실행한 채널, 그 채널의 카테고리, 서버 기본값 순서예요. 같은 단계 안에서는 특정 작업에 대한 설정이 "모든 작업" 설정보다 우선해요. 일치하는 설정이 없으면 기본 제공 값이 적용돼요.

`banprune`은 현재 채널에서 차단하면 삭제될 메시지 수와 설정된 모든 값을 보여줘요. `banpruneset <action|all> <days> [#channel or category]`로 설정하고, `banpruneclear <action|all> [#channel or category]`로 제거해요. `banprunereset`은 모든 설정을 지워요.

대시보드의 **밴 메시지 삭제** 탭에는 **서버 기본값** 아래 모든 작업이 일수 입력칸과 함께 나열되고, 모든 작업에 적용되는 **모든 작업** 행이 있어요. **재정의** 섹션에서는 **범위**(채널 또는 카테고리), 대상, **작업**, **메시지 삭제 (일)**을 골라 설정할 수 있어요.

## 메시지 삭제

`purge [count] [flags]`는 현재 채널에서 메시지를 최대 1000개까지 삭제해요. 개수를 입력하지 않으면 봇이 보낸 마지막 메시지 100개를 삭제해요. `purge @user [count]`는 최근 2주 동안 해당 멤버의 메시지만 삭제해요. 플래그는 함께 쓸 수 있어요. `-s`는 고정된 메시지를 건너뛰고, `-nb`는 봇 메시지를 건너뛰고, `-ob`는 봇 메시지만 삭제하고, `-he`는 임베드가 있는 메시지만, `-ne`는 임베드가 없는 메시지만 삭제해요. `-c text`는 텍스트가 포함된 메시지만, `-b date`는 날짜 이전 메시지만, `-a date`는 날짜 이후 메시지만 대상으로 해요.

`purgeuser <user> <count>`는 모든 텍스트 채널에서 최근 `count`개(1부터 1000까지) 메시지를 검색하고, 각 채널에서 해당 사용자의 메시지를 삭제해요.

## 닉네임

`dehoist <user>`와 `sanitize <user>`는 멤버 한 명의 닉네임에서 앞쪽 특수 문자나 특이한 문자를 제거해요. `dehoistall [nicksOnly]`와 `sanitizeall`은 확인 후 모든 멤버에 대해 백그라운드 작업으로 실행해요. `massnickprogress`로 진행 상황을 보고, `massnickstop`으로 취소할 수 있어요. 개별 명령어는 봇에 **닉네임 관리** 권한이 필요하고, "all" 명령어는 **관리자** 권한이 필요해요. 두 경우 모두 봇의 역할이 대상 멤버보다 높아야 해요.

## 설정

대시보드 페이지에는 **개요**(경고 수), **경고**, **처벌**, **최근 활동**, **밴 메시지 삭제** 탭이 있어요.

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| 경고 로그 채널 | 없음 | 모든 경고에 대한 임베드를 받는 채널 |
| 처벌 단계 | 비어 있음 | 경고 횟수마다 실행할 처벌 |
| 경고 만료 | 꺼짐 | 경고를 지우거나 삭제하기까지 걸리는 일수. 명령어로만 설정해요 |
| 음소거 역할 | `Mewdeko-mute` | 음소거 명령어가 사용하는 역할. 명령어로만 설정해요 |
| 음소거 시 역할 제거 | 꺼짐 | 전체 음소거 전후로 역할을 제거하고 되돌려요. 명령어로만 설정해요 |
| 차단 DM 템플릿 | 기본 임베드 | 차단된 멤버가 받는 DM. 명령어로만 설정해요 |
| 밴 메시지 삭제 기본값 | 작업별 | 차단 종류마다 함께 삭제할 메시지 일수 |
| 밴 메시지 삭제 재정의 | 없음 | 채널 또는 카테고리별 메시지 삭제 설정 |

**경고** 탭에서는 사용자 ID로 멤버를 경고할 수 있어요. 사유는 필수예요. ID, 사유, 모더레이터로 검색할 수 있고, 용서된 경고를 숨기거나, 경고 하나를 용서하거나, 멤버의 모든 경고를 용서하거나, 경고 하나를 영구 삭제할 수 있어요.

> [!WARNING]
> 대시보드에서 경고를 삭제하면 영구적으로 사라지고 처벌 횟수에도 포함되지 않아요. 용서하면 기록이 남고 역시 처벌 횟수에서 빠져요. 기록을 지워야 할 특별한 이유가 없다면 용서하는 것이 좋아요.

## 설정 방법

1. 대시보드에서 **모더레이션**을 열고 **처벌** 탭으로 이동해요.
2. 스태프만 볼 수 있는 **경고 로그 채널**을 선택해요.
3. 처벌 단계에 규칙을 추가해요. 처음에는 2회에 60분 음소거, 3회에 1440분 타임아웃, 5회에 차단처럼 부드럽게 시작하는 것을 추천해요.
4. 이미 음소거 역할이 있다면 `muterole @Muted`를 실행하고, 없다면 처음 사용할 때 봇이 `Mewdeko-mute`를 만들도록 두세요.
5. `warnexpire 90 clear`로 만료 기간을 정해서, 오래된 경고가 3개월 후에는 처벌 횟수에 포함되지 않도록 해요.
6. **밴 메시지 삭제** 탭에서 **임시 차단**을 0으로 설정하면 임시 차단 시 기록이 지워지지 않아요. 봇 스팸 채널처럼 더 많이 지워야 하는 채널에는 채널 재정의를 추가하세요.
7. 테스트 계정으로 `warn @alt test`를 실행하고, 로그 채널을 확인한 다음 `warnclear @alt`로 정리하세요.

## 팁과 주의 사항

- 봇의 역할은 봇이 음소거, 추방, 차단하는 모든 멤버보다, 그리고 음소거 역할보다 높아야 해요. "처벌을 적용할 수 없어요" 같은 오류는 대부분 역할 순위 문제예요.
- 봇은 각 명령어에 맞는 권한인 멤버 차단, 멤버 추방, 멤버 타임아웃 주기, 역할 관리, 메시지 관리가 필요해요. 각 명령어는 실행 전에 봇의 권한을 먼저 확인해요.
- 처벌 단계는 정확히 일치하는 횟수에서만 실행돼요. "3회 이상"이라고 가정하지 말고, 필요한 단계를 모두 채워 넣으세요.
- 봇을 통해 발급된 경고만 횟수에 포함돼요. Discord 자체 타임아웃이나 차단은 경고로 집계되지 않아요.
- 음소거 역할은 채널별로 권한을 거부해요. 역할을 만든 뒤에 생성된 채널은 누군가 음소거될 때 다음 번에 덮어쓰기가 추가되며, 즉시 추가되지는 않아요.
- Discord의 일괄 삭제는 최근 14일 이내 메시지만 지울 수 있어요. 더 오래된 메시지는 메시지 삭제 명령어가 건너뛰어요.
- 차단 시 메시지 삭제는 설정과 상관없이 Discord 제한에 따라 최대 7일까지만 가능해요.
- 대시보드에서 경고를 줄 때는 유효한 사유가 필요하고, 모더레이터 이름은 대시보드 계정 이름으로 기록돼요.
