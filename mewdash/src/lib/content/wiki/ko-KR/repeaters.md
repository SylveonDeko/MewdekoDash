## 기능 소개

반복 메시지는 봇이 한 채널에 같은 메시지를 계속 다시 올리는 기능이에요. 가장 흔한 용도는 "규칙을 읽어 주세요"를 6시간마다 올리는 정기 알림이에요. 봇은 매번 메시지를 올리기 전에 이전에 올린 사본을 먼저 삭제해요. 그래서 채널에 같은 메시지가 쌓이지 않고, 메시지는 항상 아래쪽에 있어요.

반복 메시지에는 다섯 가지 실행 모드가 있어요. 일정한 간격 외에도, 다른 사람이 메시지를 올리는 순간 실행하는 진짜 고정 메시지로 쓸 수 있고, 지정한 메시지 수가 쌓인 뒤 실행하거나, 채널이 바쁠 때나 조용할 때 실행할 수 있어요. 선택 사항인 시간 범위를 쓰면 서버 시간대 기준의 업무 시간, 저녁, 주말에만 실행되도록 제한할 수 있어요. 포럼 반복 메시지는 새로 만들어진 모든 스레드에 자동으로 올릴 수도 있어요.

메시지는 임베드 빌더, 일반 텍스트, 구성 요소, 일반 플레이스홀더를 모두 지원하므로, 짧은 텍스트뿐 아니라 풍부한 공지로도 만들 수 있어요. 멘션은 만든 사람이 **@everyone, @here 및 모든 역할 멘션** 권한이 있을 때만 유지되고, 그렇지 않으면 무력화돼요.

## 이런 때 사용해요

- 활발한 채널의 맨 아래에 규칙이나 "도움 요청 방법" 안내를 계속 고정해 두고 싶을 때
- 서버 시간 18:00에 매일 이벤트 알림을 올리고 싶을 때
- 태그로 걸러서 새로 만들어진 포럼 스레드마다 게시 가이드라인을 올리고 싶을 때
- 한 시간 동안 조용했던 채널에 대화 시작 메시지를 올려 활기를 불어넣고 싶을 때
- 업무 시간 동안, 그리고 7일 동안만 프로모션을 진행하고 싶을 때

## 실행 모드

| 모드 | 실행 시점 |
| --- | --- |
| 시간 간격 | 설정한 간격마다 실행해요. 시작 시간을 정하면 하루 중 그 시각에 맞춰 실행해요. 기본 모드예요. |
| 즉시 | 한 번 실행한 뒤, 자신의 메시지가 채널의 마지막 메시지가 아니게 되면 다시 올려요. |
| 메시지 수 기준 | 마지막 실행 이후 기준 메시지 수만큼 메시지가 올라오면 실행해요. |
| 활동 시 | 채널이 바쁠 때 실행해요. 기준값을 시간 범위 안의 최근 대화량과 비교해요. |
| 활동 없을 시 | 시간 범위 전체 동안 채널에 메시지가 하나도 없으면 실행해요. |

활동 기반 모드는 1분마다 확인하며, 서버에서 메시지 집계가 켜져 있어야 해요. 간격은 5초에서 25000분 사이여야 해요. 기본값은 5분이며, 시각을 지정하고 간격을 지정하지 않으면 하루(1일)예요. **활동 기준값**의 기본값은 5개 메시지이고, **시간 범위**의 기본값은 5분이며 범위는 30초에서 6시간 사이예요.

## 조건과 제한

- **마지막 메시지이면 반복하지 않음**(중복 방지): 자신의 마지막 사본이 여전히 가장 최근 메시지라면 봇은 이번 실행을 건너뛰어요.
- **대화 감지**: 최근 1분 안에 메시지가 3개 이상 올라오면 실행을 미루고 30초 뒤에 다시 확인해요.
- **시간 예약**: `business`는 월요일부터 금요일까지 09:00부터 17:00까지, `evening`은 매일 18:00부터 23:00까지, `weekend`는 토요일과 일요일 하루 종일이에요. 시간은 서버 시간대 기준이에요. 먼저 서버 시간대를 설정하지 않으면 봇은 UTC를 사용하고 이를 알려 줘요.
- **자동 삭제 기간**과 **최대 표시 횟수**: 최대 보존 기간이나 게시 횟수에 도달하면 반복 메시지가 스스로 삭제돼요.
- **알림 숨기기**: 메시지를 조용히 보내서 누구의 기기에도 알림이 울리지 않게 해요.
- **우선순위**는 반복 메시지마다 0에서 100 사이로 저장되며, 기본값은 50이고 목록에 표시돼요.

## 스레드와 포럼

- **새 스레드에 자동 생성**: 반복 메시지 채널 아래에 스레드가 만들어지면 봇이 그 스레드에 메시지를 올리고, 멤버가 답글을 달 때마다 아래쪽에 유지해요.
- **스레드 전용 모드**: 반복 메시지가 상위 채널에는 절대 올라가지 않고 스레드에만 올라가요. 대상이 포럼 채널이면 반드시 필요해요.
- **포럼 태그 필터**: 필수 태그와 제외 태그가 어떤 포럼 게시물에 고정 메시지를 올릴지 결정해요.

## 플레이스홀더

메시지는 일반 플레이스홀더 세트를 거쳐 처리돼요. 사용자 플레이스홀더는 봇 자신을 가리켜요. 반복 메시지는 누가 실행하는 것이 아니기 때문이에요. 자주 쓰는 플레이스홀더는 다음과 같아요.

| 플레이스홀더 | 값 |
| --- | --- |
| `%server%`, `%server.name%` | 서버 이름 |
| `%server.members%` | 캐시된 멤버 수 |
| `%server.id%`, `%server.icon%` | 서버 ID와 아이콘 URL |
| `%channel%`, `%channel.name%` | 반복 메시지 채널의 멘션과 이름 |
| `%bot.name%`, `%bot.avatar%` | 봇의 이름과 아바타 |
| `%server.time%`, `%time.day%` | 서버 시간과 현재 요일 |

`%huggif%` 같은 반응 GIF 플레이스홀더도 치환돼요. `%user%` 같은 트리거 플레이스홀더는 봇으로 치환돼요.

## 설정

반복 메시지 페이지에는 **개요**, **반복 메시지 관리**, **새로 만들기** 세 개의 탭이 있어요.

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| 대상 채널 | 없음 | 메시지를 올릴 텍스트 채널 또는 포럼 채널 |
| 포럼 태그 필터 | 없음 | 필수 태그와 제외 태그. 포럼 채널에서만 사용해요 |
| 메시지 내용 | 없음 | 임베드 빌더를 열어요 |
| 실행 모드 | 시간 간격 | 다섯 가지 모드 중 하나 |
| 반복 간격 | 5분 | 1분부터 매일까지의 프리셋, 또는 사용자 지정 `HH:MM:SS` |
| 마지막 메시지이면 반복하지 않음 | 끔 | 중복 방지 확인 |
| @everyone 및 @here 멘션 허용 | 끔 | 대량 멘션을 무력화하지 않고 메시지에 유지해요 |
| 우선순위 (0-100) | 50 | 목록에 표시되는 우선순위 값 |
| 대기열 위치 | 0 | 저장된 정렬 값 |
| 시작 시간 (HH:MM) | 없음 | 시간 간격 반복 메시지를 맞출 하루 중 시각 |
| 대화 감지 | 끔 | 사람들이 대화하는 동안 실행을 미뤄요 |
| 알림 숨기기 | 끔 | 조용히 보내요 |
| 새 스레드에 자동 생성 | 끔 | 스레드 고정 메시지. 포럼 채널에서만 사용해요 |
| 스레드 전용 모드 | 끔 | 상위 채널을 건너뛰어요. 포럼 채널에서만 사용해요 |
| 자동 삭제 기간 (일) | 없음 | `d.hh:mm:ss` 형식의 최대 보존 기간. 예: `7.00:00:00` |
| 최대 표시 횟수 | 무제한 | 삭제 전까지의 게시 횟수 |
| 시간 예약 | 없음 | 프리셋 버튼 또는 사용자 지정 예약 |
| 활동 기준값 / 필요한 메시지 수 | 5 | 활동 모드에서 필요한 메시지 수 |
| 시간 범위 | 00:05:00 | 활동 모드의 시간 범위 |

**개요**에서는 전체 수, 활성 수, 전체 표시 횟수, 실행 모드별 비율, 가장 활발한 반복 메시지를 볼 수 있어요. **반복 메시지 관리**에서는 각 반복 메시지마다 **편집**, **지금 실행**, **삭제**를 할 수 있고, 간격, 기준값, 최대 기간, 최대 실행 횟수를 빠르게 수정할 수도 있어요.

## 설정 따라 하기

1. 대시보드에서 **반복 메시지**를 열고 **새로 만들기**를 선택해요.
2. **대상 채널**을 고르세요. 포럼이라면 **스레드 전용 모드**를 체크하고 필요한 **포럼 태그 필터**를 설정하세요.
3. **메시지 내용** 칸을 클릭해서 임베드 빌더에서 메시지를 만드세요.
4. **실행 모드**를 고르세요. 고정 메시지라면 즉시를, 알림이라면 **반복 간격** 프리셋이 있는 시간 간격을 고르세요.
5. 중복 방지, 조용히 보내기, 시간 예약, 만료 기간이 필요하면 **고급 옵션**을 여세요.
6. **반복 메시지 만들기**를 누르고, **반복 메시지 관리** 탭에서 **지금 실행**으로 테스트하세요.

> [!NOTE]
> 시간 예약에는 서버 시간대가 필요해요. 업무 시간, 저녁, 주말 범위를 켜기 전에 시간대 명령어로 먼저 설정하세요.

## 명령어

이 명령어는 서버의 접두사(바꾸지 않았다면 `.`)와 함께 실행해요. 모두 메시지 관리 권한이 필요해요. 반복 메시지는 `repeatlist`에서 나오는 번호로 지정해요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `repeat [time] [interval] <message>` | | 메시지 관리 | 현재 채널에 반복 메시지 만들기. 예: `repeat 6h Read the rules` 또는 `repeat 18:00 Event tonight` |
| `repeatlist` | `replst`, `replist`, `repli` | 메시지 관리 | 채널, 모드, 간격, 다음 실행 시각과 함께 목록 표시 |
| `repeatinvoke <index>` | `repinv` | 메시지 관리 | 지금 실행하고 타이머를 다시 시작 |
| `repeatremove <index>` | `reprm` | 메시지 관리 | 반복 메시지 삭제 |
| `repeattoggle <index>` | `reptoggle`, `reptog` | 메시지 관리 | 삭제하지 않고 켜거나 끄기 |
| `repeatmessage <index> <message>` | `repmsg` | 메시지 관리 | 메시지 교체 |
| `repeatchannel <index> [#channel]` | `repchan` | 메시지 관리 | 텍스트 채널 또는 포럼 채널로 옮기기 |
| `repeatredundant <index>` | `repeatredun`, `repred` | 메시지 관리 | 중복 방지 확인 켜기/끄기 |
| `repeattriggermode <index> <mode>` | `reptriggermode`, `repmode` | 메시지 관리 | `timeinterval`, `immediate`, `aftermessages`, `onactivity`, `onnoactivity` 중 하나 |
| `repeatactivity <index> <threshold> <window>` | `repactivity`, `repact` | 메시지 관리 | 활동 기준값과 시간 범위 설정. 예: `10 5m` |
| `repeatpriority <index> <0-100>` | `reppriority`, `repprio` | 메시지 관리 | 우선순위 값 설정 |
| `repeatschedule <index> <preset>` | `repschedule`, `repsched` | 메시지 관리 | `business`, `evening`, `weekend`, 또는 해제하려면 `none` |
| `repeatconversation <index>` | `repconversation`, `repconv` | 메시지 관리 | 대화 감지 켜기/끄기 |
| `repeatsuppressnotifications <index>` | `repsuppressnotif`, `repsilent`, `repsuppress` | 메시지 관리 | 조용히 보내기 켜기/끄기 |
| `repeatthreadautosticky <index>` | `repthreadauto`, `repthreads` | 메시지 관리 | 새 스레드에 게시하기 켜기/끄기 |
| `repeatthreadonly <index>` | `repthreadonly`, `reptonly` | 메시지 관리 | 스레드 전용 모드 켜기/끄기 |
| `repeatforumtags <index> <add/remove/clear/list> [required/excluded] [tags]` | `repforumtags`, `repftags` | 메시지 관리 | 태그 ID로 포럼 태그 필터 관리 |

## 팁과 주의 사항

- 봇에는 메시지 보내기, 링크 첨부, 메시지 관리 권한이 채널에서 필요해요. 다시 올리기 전에 이전 사본을 삭제해야 하기 때문이에요.
- 채널이 삭제되거나 봇이 접근 권한을 잃으면 반복 메시지는 스스로 삭제돼요.
- 반복 메시지는 봇이 시작한 직후에 불러와요. 그 전까지는 명령어가 아무 반응 없이 끝나요.
- 즉시 모드는 다른 사람이 메시지를 올릴 때마다 다시 올라가요. 메시지가 아주 빠르게 올라오는 채널에서는 피하거나 대화 감지와 함께 쓰세요.
- **@everyone, @here 및 모든 역할 멘션** 권한이 있는 멤버만 모두 또는 역할을 멘션하는 반복 메시지를 만들 수 있어요. 그렇지 않으면 멘션이 이스케이프돼요.
- 활동 기반 모드는 메시지 집계에 의존해요. 모드를 바꾸기 전에 집계를 켜 두세요. 그렇지 않으면 명령어가 거부돼요.
- **최대 표시 횟수**의 만료 계산에는 직접 실행한 게시도 포함돼요.
