## 기능 소개

메시지 세기를 켜면, 봇은 사람이 최소 길이 이상의 메시지를 보낼 때마다 멤버별, 채널별로 카운트를 하나씩 기록해요. 메시지 내용은 저장하지 않고, 누가, 어디서, 언제 보냈는지만 저장해요. 카운트는 대기열에 모였다가 일괄로 데이터베이스에 기록되므로, 활발한 서버에서도 봇이 느려지지 않아요.

멤버는 `usermessages`로 본인의 총계를 보고, `channelmessages`로 가장 활발한 채널을 보고, `servermessages`로 서버 전체를 볼 수 있어요. `topusers`는 각 멤버가 전체 메시지에서 차지하는 비율과 함께 상위 열 명의 순위표를 출력해요. `activitygraph`는 가장 바쁜 요일이나 시간대를 막대 그래프 이미지로 보여 줘요.

대시보드에서도 같은 수치를 차트로 볼 수 있고, 운영진은 세기를 켜거나 끄고, 카운트를 초기화하고, 데이터를 CSV나 JSON으로 내보낼 수 있어요.

## 이런 때 사용해요

- 보상, 역할, 운영진 모집에 필요한 가장 활발한 멤버를 찾아보세요.
- 서버를 재구성하기 전에 어떤 채널이 한산하고 어떤 채널이 활발한지 확인하세요.
- 가장 바쁜 시간대 그래프를 본인의 시간대로 보고 이벤트 시간을 정하세요.
- 메시지 수와 메시지 품질을 비교해서 봇이나 스팸 계정을 찾아내세요.

## 무엇이 집계되나요

| 규칙 | 동작 |
| --- | --- |
| 세기 켜짐 | `togglemsgcount`나 대시보드 스위치를 켜기 전까지 아무것도 기록하지 않아요 |
| 봇 | 집계하지 않아요 |
| DM | 집계하지 않아요. 서버 채널만 집계해요 |
| 최소 길이 | **최소 메시지 길이**보다 짧은 메시지는 건너뛰어요. 기본값은 0이라서 모든 메시지가 집계돼요 |
| 타임스탬프 | 시간 및 요일 그래프를 위해 메시지 시각은 90일 동안 보관해요. 총계는 계속 보관해요 |

최소 길이는 최대 4098까지 설정할 수 있어요. `minmsglength`를 숫자 없이 실행하면 현재 값을 보여 줘요.

## 활동 그래프

`activitygraph days`는 일주일 전체의 데이터가 필요하고, 지난 4주를 기준으로 해요. `activitygraph hours`는 지난 7일 동안 24시간 전체의 데이터가 필요해요. 시간별 그래프는 먼저 시간대를 골라야 해요. 봇이 자주 쓰는 시간대 목록을 보여 주고, 모든 IANA 시간대 이름을 받아들이며, 답하지 않으면 취소해요. 차트는 PNG 이미지로 올라와요.

## 설정

메시지 통계 페이지에는 **통계**와 **관리**, 두 개의 상위 탭이 있어요. 통계에는 **개요**, **상위 사용자**, **상위 채널**이 있고, 관리에는 **설정**과 **데이터 내보내기**가 있어요.

| 설정 | 기본값 | 조정하는 내용 |
| --- | --- | --- |
| 메시지 세기 켜기 | 꺼짐 | 새 메시지를 기록할지 여부 |
| 최소 메시지 길이 | 0 | 0~4098 사이의 슬라이더. 집계되는 가장 짧은 메시지 길이 |
| 메시지 수 초기화 | | **서버 전체 메시지 수 초기화**를 확인하면 이 서버의 저장된 카운트를 모두 삭제해요 |
| 내보내기 형식 | CSV | 불러온 통계를 CSV 또는 JSON으로 다운로드해요 |
| 사용자 통계 포함 | 켜짐 | 내보내기에 상위 사용자 행을 추가해요 |
| 채널 통계 포함 | 켜짐 | 내보내기에 상위 채널 행을 추가해요 |
| 시간별 분석 포함 | 꺼짐 | 내보내기에 가장 바쁜 시간과 가장 바쁜 요일 행을 추가해요 |

**개요** 탭에는 **일일 메시지**, **총 메시지**, **마지막 업데이트**, **상태** 타일이 있고, 가장 덜 활발한 사용자와 채널, **24시간 활동** 차트, **주간 추세** 차트가 있어요. **상위 사용자** 탭은 **상위 메시지 작성자**를 보여 주고, **상위 채널** 탭은 **가장 활발한 채널**을 보여 줘요.

> [!NOTE]
> 내보내기 파일은 페이지에 이미 불러온 통계를 바탕으로 브라우저에서 만들어져요. 입력한 시작일과 종료일은 파일 헤더에만 적히고, 행을 걸러내지는 않아요.

## 설정 따라 하기

1. 대시보드에서 **메시지 통계**를 열고 **관리**로 이동한 뒤 **설정**을 선택하세요.
2. **메시지 세기 켜기**를 켜세요.
3. 한 글자짜리 답장을 무시하고 싶다면 **최소 메시지 길이**를 5로 설정하거나, Discord에서 `minmsglength 5`를 실행하세요.
4. 서버에서 하루 동안 대화하게 한 뒤 **통계**에서 처음 수치를 확인하세요.
5. 일주일 뒤 `activitygraph hours`를 실행하고 시간대를 골라서 서버가 가장 바쁜 시간을 확인하세요.

## 명령어

이 명령어는 서버의 접두사(바꾸지 않았다면 `.`)와 함께 실행해요.

| 명령어 | 별칭 | 필요 권한 | 용도 |
| --- | --- | --- | --- |
| `usermessages [@user]` | `usermsg`, `umsg` | 없음 | 본인이나 다른 멤버의 총계, 가장 활발한 채널과 가장 덜 활발한 채널 |
| `channelmessages [#channel]` | `channelmsg`, `cmsg` | 없음 | 채널의 총계, 가장 활발한 멤버와 가장 덜 활발한 멤버 |
| `servermessages` | `servermsg`, `smsg`, `guildmessages`, `guildmsg` | 없음 | 서버 총계와 가장 활발한 멤버 및 채널, 가장 덜 활발한 멤버 및 채널 |
| `topusers` | `topu` | 없음 | 메시지 수 상위 열 명과 비율 |
| `activitygraph [days or hours]` | `actgraph` | 없음 | 가장 바쁜 요일 또는 시간의 막대 그래프. 기본값은 요일 |
| `minmsglength [number]` | `mmlength`, `minmlength` | 서버 관리 | 메시지가 집계되기 위한 최소 길이 보기 또는 설정 |
| `togglemsgcount` | `togglemessagecount` | 관리자 | 세기 켜기 또는 끄기 |
| `resetmessagecounts [@user] [#channel]` | `rmc`, `resetmsgcounts`, `resetmessages`, `resetcounts` | 메시지 관리 | 확인 후 서버 전체, 멤버 한 명, 채널 하나, 또는 특정 채널의 특정 멤버 카운트 초기화 |

## 팁과 주의 사항

- 세기는 켠 시점부터만 시작돼요. 그 전에 보낸 메시지는 나중에 채워지지 않아요.
- 세기를 켜기 전까지 모든 통계 명령어와 대시보드는 예전 데이터가 있어도 "비활성화됨"이라고 표시해요.
- 카운트는 최대 100개의 이벤트를 묶어서 기록하므로, 총계는 실시간 채팅보다 몇 초 늦을 수 있어요.
- 채널을 삭제해도 그 채널의 카운트는 삭제되지 않아요. 채널을 없애기 전에 완전히 지우고 싶다면 `resetmessagecounts #channel`을 실행하세요.
- 시간별 그래프는 선택한 시간대만큼만 정확해요. 운영진끼리 일관되게 보려면 운영 모듈의 시간대 명령어로 서버의 시간대를 저장해 두세요.
- XP 시스템은 자체 활동 추적을 하고, 이 카운트는 사용하지 않아요.
